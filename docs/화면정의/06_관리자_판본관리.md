# 화면 A: 판본 관리 (곡 편집 화면 아래쪽)

## A-0. 영역 순서 (2026-09-21 개정)

```
┌ 판본 (14개)                                          [+ 판본 추가] ┐
│ ⚠ 추천 판본이 없어요 — 사용자에게는 '준비 중'으로 보여요             │ ① 추천 없을 때만
│ ┌ 이 판본을 고른 이유 ──────────────────────────────────────┐    │ ② 추천 있을 때만 (A-1)
│ └─────────────────────────────────────────────────────────┘    │
│ ⚠ 추천 판본의 저작권이 확정되지 않아 다운로드가 열리지 않아요 [판정하기] │ ③ 해당 시
│ ┌ 판본 목록 ────────────────────────────────────────────────┐   │ ④ 항상 (A-2)
│ │ ★ 추천 / ◇ 추천 후보 / 그 밖의 행                           │   │
│ │   └ [이 판본으로 바꾸기] 패널 — 지정을 누른 행 바로 아래 (A-3) │   │
│ └──────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────┘
```

| # | 영역 | 나오는 조건 |
|---|---|---|
| ① | `추천 판본이 없어요 — 사용자에게는 '준비 중'으로 보여요` InlineAlert warning | 판본은 있는데 추천이 없을 때 (기존) |
| ② | **A-1 "이 판본을 고른 이유"** | **추천이 있을 때만.** 없으면 상자 자체가 없다 — 빈 제목도 만들지 않는다 (기획 8-A 6) |
| ③ | `추천 판본의 저작권이 확정되지 않아 다운로드가 열리지 않아요` + `판정하기` | 추천이 UNKNOWN/RESTRICTED (기존) |
| ④ | A-2 판본 목록 | 항상 |

**추천이 없는데 이력은 있는 곡**(추천 판본을 삭제해 추천이 빠진 곡): ① 아래에 **접힘 줄 하나만** 둔다 — `▸ 바뀐 이력 (3)`(A-1 의 이력과 같은 모양·같은 내용). "이 판본을 고른 이유" 제목·상자는 **없다**(고를 판본이 없다). 이력이 0건이면 이 줄도 없다.
> **왜** — 기획 8-B 7 이 "추천을 빼면 이력에 `추천을 뺐어요` 한 줄이 남는다"를 요구하는데, 영역을 통째로 지우면 그 줄을 **볼 자리가 사라진다.** 관리자가 "어제까지 추천이 있었는데 왜 없지?"를 묻는 곳이 바로 이 화면이다. 8-A 6 의 "영역"은 **"이 판본을 고른 이유" 제목이 붙은 상자**를 가리키는 것으로 읽는다. **(2026-09-21 product-planner 확인 완료 — 기획 §11 D1)**: designer 해석이 맞다. 이 문서를 다시 고칠 필요 없음.

## A-1. "이 판본을 고른 이유" — 신규 (2026-09-21)

**추천 판본이 있는 곡에만.** 자리는 **판본 목록 바로 위**(기획 §2-1). 모양은 **3가지뿐**이고, 어느 모양이든 아래 순서를 지킨다.

```
제목 "이 판본을 고른 이유"
① 누가·언제 골랐나 (한 줄)
② 무슨 근거로 골랐나 (자동이면 규칙+그때 값 / 사람이면 사유+메모 / 기록 없으면 안내)
③ 이전 추천이 무엇이었나 (있을 때만)
④ 미검수 줄 (해당 시) — 새로 만드는 표시가 아니라 기존 "추천 판본 미검수"가 놓이는 자리
⑤ ▸ 바뀐 이력 (N)  — 기록이 2건 이상일 때만
```

### (A) 자동으로 골랐을 때

```
┌──────────────────────────────────────────────────────────────────┐
│ 이 판본을 고른 이유                                                │
│ 자동으로 골랐어요 · 2026-09-07 14:20                               │
│ 전체 악보 · 전곡 · 파일 있는 판본 중 IMSLP 다운로드가 가장 많은 것     │
│ IMSLP 다운로드 1,204회 · 후보 3개 중 1위                            │
│                                                                  │
│ ⚠ 아직 아무도 미리보기를 확인하지 않았어요   [미리보기 열기] [확인함]  │
│ ▸ 바뀐 이력 (3)                                                   │
└──────────────────────────────────────────────────────────────────┘
```

**셋째 줄(그때 그 값)은 세 갈래다** — 기획 §1-3. 지금 값을 다시 계산해 쓰지 않는다(지정 시점에 박아 둔 값).

| 상황 | 문구 |
|---|---|
| 후보 2개 이상 + 다운로드 수 있음 | `IMSLP 다운로드 1,204회 · 후보 3개 중 1위` |
| 후보 2개 이상 + 다운로드 수 없음 | `IMSLP 다운로드 수가 적혀 있지 않은 판본이에요 · 후보 3개 중 1위` + 아래 한 줄(`--font-size-xs` `--color-warning`) `다운로드 수가 없는 판본은 뒤로 밀리는 규칙이라, 미리보기를 꼭 확인해 주세요` |
| **후보가 1개뿐** | **`고를 수 있는 판본이 이것 하나뿐이었어요`** — 수가 있으면 뒤에 ` (IMSLP 다운로드 1,204회)`. **"1위"라는 말을 쓰지 않는다** (기획 8-A 3) |

> **왜 "후보 3개 중 1위"를 쓰면서 1개일 때만 말을 바꾸나** — 자동 지정은 언제나 1위를 고른다. "1위"는 그 자체로 정보가 0이고, 관리자가 아는 값은 **"몇 개 중에서"** 다. 후보가 하나였다면 그건 고른 게 아니라 **남은 것**이라 "1위"가 거짓 안심을 준다.

**자동에는 "이전 추천" 줄이 없다.** 자동 지정은 추천이 아직 없는 곡에만 걸리므로 항상 첫 지정이다(기획 §0-1 4).

### (B) 사람이 골랐을 때

```
┌──────────────────────────────────────────────────────────────────┐
│ 이 판본을 고른 이유                                                │
│ 창희 님이 골랐어요 · 2026-09-20 11:02                              │
│ 앞 추천이 이 곡의 악보가 아니었어요                                 │
│ 앞 추천은 관현악 총보였음                                          │ ← 메모(적었을 때만)
│ 이전 추천: 전체 악보 · 전곡 · Peters / Köhler / 1880               │
│ ✓ 미리보기를 확인한 추천이에요                                      │
│ ▸ 바뀐 이력 (2)                                                   │
└──────────────────────────────────────────────────────────────────┘
```

| 줄 | 문구 규칙 |
|---|---|
| 누가·언제 | **`{닉네임} 님이 골랐어요 · {YYYY-MM-DD HH:mm}`**. 닉네임이 비어 있으면 `관리자가 골랐어요` (미결 6-5 결정 — 아래 "관리자 이름 표기") |
| 고른 사유 | A-3 에서 고른 6개 중 하나의 **라벨 문장 그대로**. `--font-weight-medium` `--color-text`. **따옴표를 두르지 않는다** — 이 화면에서 따옴표는 "사람이 친 원문"(별칭 `'녹턴'`)의 표시라 고른 선택지에 쓰면 뜻이 흐려진다 |
| 메모 | 적었을 때만 한 줄. `--font-size-sm` `--color-text-secondary`. 여러 줄이면 2줄까지 보이고 그 뒤 `…` + 클릭 시 전체 펼침 |
| 이전 추천 | `이전 추천: {종류} · {포함 범위} · {출판사} / {편집자} / {연도}` (`--font-size-sm` muted). 없는 값은 `–`. 이전 추천이 없었으면 **`처음 지정한 추천이에요`** |

### (C) 기록이 없을 때 — 기존 42곡 (기획 §5)

```
┌──────────────────────────────────────────────────────────────────┐
│ 이 판본을 고른 이유                                                │
│ 기록이 없어요 — 근거를 남기는 기능이 생기기 전에 정해졌어요           │
│ ⚠ 아직 아무도 미리보기를 확인하지 않았어요   [미리보기 열기] [확인함]  │
│ 미리보기를 열어 확인하고, 그대로 둘 거면 '확인함'을 눌러 주세요.        │
│ 다른 판본이 맞으면 아래 목록에서 다시 골라 주세요.                    │
└──────────────────────────────────────────────────────────────────┘
```

- 첫 줄 `기록이 없어요` `--font-weight-medium` + 이어지는 `— 근거를 남기는 기능이 생기기 전에 정해졌어요` `--color-text-secondary`. **빈 칸·빈 표가 아니다**(8-A 5).
- **마지막 안내 줄은 검수 여부로 갈린다** — 42곡 대부분이 "기록 없음 + 미검수"라 두 줄이 같은 말로 겹쳐 읽히면 안 된다.

  | 검수 | 안내 줄 |
  |---|---|
  | 미검수 | `미리보기를 열어 확인하고, 그대로 둘 거면 '확인함'을 눌러 주세요. 다른 판본이 맞으면 아래 목록에서 다시 골라 주세요.` |
  | 확인함 | `이미 미리보기를 확인한 곡이에요. 다시 지정하면 그때부터 고른 이유가 남아요.` (`--font-size-sm` muted) — 기획 §5-3 의 "자동 지정 + 미리보기만 확인한 곡"은 일감이 아니다 |

- 이 곡에는 **이력도 없다.** `▸ 바뀐 이력` 줄을 두지 않는다 — "기록이 없어요"가 이미 그 말을 했다.
- 관리자가 한 번 다시 지정하면 이 모양은 (B) 로 바뀌고 안내가 사라진다(8-E 3).

### 미검수 줄 — 신규 정의 (senior-dev 2026-09-08 요청분을 여기서 닫는다)

`01` §F6-4 · API 명세서 §5-6-1 의 "추천 판본 미검수"가 **화면정의 어디에도 없었다.** 기획 §2-1 이 "고른 이유 영역은 그 표시가 놓이는 자리"라 했으므로 여기에 둔다. **같은 뜻의 새 표시를 하나 더 만들지 않는다.**

| 상태 | 표시 |
|---|---|
| 미검수 (`recommendationReviewed=false`) | `warning`(`--icon-size-sm` `--color-warning`) + `아직 아무도 미리보기를 확인하지 않았어요` (`--font-size-sm` `--color-warning`) · 오른쪽 `.btn.btn-text` **`미리보기 열기`** · `.btn.btn-text` **`확인함`** |
| 확인함 | `✓ 미리보기를 확인한 추천이에요` (`--font-size-xs` `--color-success`) · 오른쪽 `.btn.btn-text` **`확인 해제`** |

- `미리보기 열기` → **기존 `PreviewLightbox`(00 §3-10) 재사용**, 추천 판본의 첫 페이지. 캡션 `{곡 제목} — {종류} · {포함 범위} (1쪽/{쪽수}쪽)`. 판본 목록의 추천 행 썸네일(40px)을 눌러도 같은 라이트박스가 열린다. **이 버튼이 없으면 "확인함"은 근거 없는 버튼이 된다.**
- 미리보기가 없는 추천(생성 실패)이면 `미리보기 열기` `:disabled` + 옆 한 줄 `미리보기가 아직 없어요 — PDF를 직접 확인해 주세요`(00 §3-9 비활성 패턴).
- `확인함` → `PUT …/recommended-edition/review {reviewed:true}` → 줄이 **그 자리에서** `✓ 미리보기를 확인한 추천이에요` 로 바뀌고 Toast `확인했어요`. 실패면 영역 아래 InlineAlert danger `처리하지 못했어요. 잠시 후 다시 시도해 주세요`.
- `확인 해제` → `PUT …/recommended-edition/review {reviewed:false}` → 줄이 **그 자리에서** 미검수 모양(경고 아이콘 + `아직 아무도 미리보기를 확인하지 않았어요` + `미리보기 열기`·`확인함`)으로 되돌아가고 Toast `확인을 해제했어요`. 실패면 같은 InlineAlert danger.

**"확인 해제" 버튼을 되살린다 — 왜 되살렸나 (2026-09-21 개정, senior-dev 되돌림 S1).** 이 절은 애초에 "확인을 풀 일이 있으면 다시 지정하면 된다"는 근거로 이 버튼을 없앴다. `06_추천판본_선정근거와_변경_기획서.md` 개정이 그 전제를 둘 다 무너뜨렸다.
  - **같은 판본을 다시 지정해도 검수가 풀리지 않는다.** "다시 지정" 이 더는 검수 해제 수단이 아니다.
  - **다른 판본으로 지정하려면 이제 A-3 에서 사유가 필수다.** 검수만 풀고 싶어서 다른 판본을 지정하면, 실제로는 바꿀 이유가 없는데 사유 칸에 뭐라도 적어야 한다 — **거짓 사유**가 이력에 영구히 남는다.
  - 계약에는 `reviewed:false` 경로가 **그대로 있다**(§5-6-1). 화면이 그 경로로 가는 버튼을 감추면, "잘못 확인함을 눌렀다"를 고칠 방법이 "판본을 실제로 바꾸며 거짓말을 적는 것"뿐이 된다 — 목적과 수단이 어긋난다. 그래서 확인함 줄에 `확인 해제` 버튼을 되살린다.

### 관리자 이름 표기 — 미결 6-5 결정

**결정: 닉네임. 로그인 아이디는 화면에 쓰지 않는다.**

| 항목 | 결정 |
|---|---|
| 표기 | **`{닉네임} 님이 골랐어요`** / 이력 1단은 `{닉네임} 님` |
| 왜 "님"인가 | 조사(이/가)가 이름 받침에 따라 갈린다(`창희가` / `한창이`). `님이` 는 어떤 이름에도 같은 꼴로 붙는다. 기획 §0-3 의 `(관리자 이름)이 골랐어요` 를 문구만 다듬은 것이다 |
| 왜 닉네임인가 | 화면에서 사람을 가리키는 이름은 이미 **헤더의 닉네임**(00 §2-1)뿐이다. 로그인 아이디는 관리자 계정 정보라 화면에 흘리지 않는다 |
| 저작권 판정 메모와의 정합 | 판정 메모(화면 B·C)는 **누가 판정했는지를 화면에 보이지 않는다**(계약에도 없다). 즉 "아이디를 쓰는 선례"가 없다 — 이번이 관리 화면에서 사람 이름을 보이는 **첫 자리**이고, 헤더와 같은 닉네임으로 맞춘다 |
| 닉네임이 비었을 때 | `관리자가 골랐어요` / 이력 1단 `관리자`. **아이디로 떨어지지 않는다** |
| 검토 후 뺀 것 | "내가 골랐어요"(본인 강조) — 분기를 하나 늘리는 값에 비해 얻는 게 없다. 지금 관리자는 사실상 한 사람이다 |

| 등록(new) 곡 | 곡을 먼저 저장하기 전엔 판본 섹션 대신 `곡을 저장하면 판본을 추가할 수 있어요`(muted). **A-1 없음** |

## A-3. "이 판본으로 바꾸기" 패널 — 신규 (2026-09-21)

`추천으로 지정` / `이 후보를 추천으로 지정` 을 누르면 **그 행 바로 아래**에 펼쳐진다. 기획 §3-1 의 "사유를 고르는 자리"다.

### 왜 모달이 아니라 행 아래 인라인인가

| 근거 | 내용 |
|---|---|
| 대상이 보여야 한다 | 이 패널의 주어는 **바로 위 행의 판본**이다. 모달은 그 행을 가린다 — "무엇으로 바꾸는지"를 가린 채 "왜 바꾸는지"를 물을 수 없다 |
| 비교가 목적이다 | 관리자는 다른 행의 IMSLP 다운로드 수·쪽수·판정을 곁눈질하며 고른다. **다른 행들을 흐리게 만들지 않는다**(`opacity` 를 낮추지 않는다) |
| 모달이 이미 하나 있다 | 같은 화면의 화면 B(판본 추가/수정)가 모달이다. 같은 화면에서 모달 두 종류가 다른 일을 하면 "닫으면 뭘 잃는지"를 매번 다시 배운다 |
| ConfirmDialog 의 문법과 다르다 | 이 서비스에서 모달 확인창은 **되돌릴 수 없는 일**(삭제)의 문법이다. 추천 변경은 되돌릴 수 있고(다시 지정하면 된다), 읽고 고르는 **폼**에 가깝다 |
| 경고 4~5줄 | 모달이면 모달 본문 스크롤 + 페이지 스크롤이 겹친다 |

### ② 경고 묶음 상자 — **이 화면 개정에서 가장 어려운 자리**

**문제**: 경고가 3종 → 6종이 되면서 **한 번에 여러 개**가 뜬다. 지금 방식(경고마다 InlineAlert 한 상자)으로는 노란 상자가 4~5개 쌓이고, 그러면 **아무도 안 읽는다.** 읽히지 않는 경고는 없는 것보다 나쁘다 — "경고를 보고도 지정했다"는 기록만 남기 때문이다.

**먼저 확인한 사실 두 가지** (문구를 다듬기 전에 셈이 먼저다)

| 사실 | 근거 | 화면에 미치는 것 |
|---|---|---|
| **한 화면에 최대 5줄이다. 6줄은 불가능하다** | 판본 종류는 하나뿐이라 ②편곡과 ⑥파트보는 **동시에 성립할 수 없다**. 최대 = ① + (② 또는 ⑥) + ③ + ④ + ⑤ | 상자 높이의 최악을 5줄로 잡고 설계한다 |
| **④가 뜨면 ①은 반드시 뜬다** | ④의 조건(`지금 곡이 바로 받기 가능` + `새 판본이 확인 중/이용 제한`)은 ①의 조건(`새 판본이 확인 중/이용 제한`)을 포함한다 — ④ ⊂ ① | 이 둘이 **겹쳐 보이는 것은 우연이 아니라 구조**다. 그래서 "다른 말로 읽히게" 하는 일이 문구가 아니라 **배치**의 문제가 된다 |

**푼 방법 — 상자는 하나, 안을 두 묶음으로 나눈다.**

```
⛔ 바꾸기 전에 확인할 것 4가지
   바뀌면 생기는 일
   · 지금 받을 수 있는 곡이에요 — 바꾸면 이 곡의 다운로드가 닫혀요      ← ④ (굵게)
   · 이미 이 곡을 받아 간 사람이 있어요 — 그 사람들의 '받은 악보'에     ← ⑤
     '지금 추천과 달라요' 표시가 생겨요
   이 판본은 이런 판본이에요
   · 이 판본은 저작권이 '확인 중'이라 사용자에게 다운로드가 열리지 않아요 ← ①
   · 이 판본은 2악장만 들어 있어요 — 곡 전체가 아니에요                ← ③
```

| 규칙 | 값 | 왜 |
|---|---|---|
| **상자는 하나** | 경고가 몇 개든 InlineAlert 하나. 항목은 `·` 불릿 | 노란 상자 5개가 만드는 "벽지"를 없앤다. 줄 수를 줄이는 게 아니라 **덩어리 수**를 줄인다 |
| **개수를 제목에 적는다** | `바꾸기 전에 확인할 것 {N}가지` | 끝이 어딘지 알면 읽기 시작한다. 4개인지 모르고 읽으면 두 줄에서 그만둔다 |
| **두 묶음** | `바뀌면 생기는 일`(④→⑤) / `이 판본은 이런 판본이에요`(①→⑥→②→③) | 기획 §3-2 의 구분(`1~3·6 = 판본의 성질`, `4~5 = 변경의 결과`)을 **눈에 보이게** 옮긴 것. **①과 ④를 서로 다른 묶음에 놓는 것 자체가 "다른 말"을 만든다** — 위는 "나에게 일어나는 일", 아래는 "이 판본이 어떤 물건인가" |
| **순서 고정** | ④ → ⑤ → ① → ⑥ → ② → ③ | 매번 같은 자리에서 같은 종류를 읽게 한다. 심각도 순이기도 하다(곡이 닫힘 > 받아 간 사람 > 안 열리는 판본 > 다른 악기 > 편곡 > 부분) |
| **④만 굵게** | `--font-weight-medium` | 5줄 중 하나만 굵으면 눈이 거기서 멈춘다. 둘 이상 굵게 하면 굵은 게 배경이 된다 |
| **아이콘은 상자에 하나** | 항목마다 아이콘을 붙이지 않는다 | 아이콘 5개 = 소음 |
| **접지 않는다** | "3개 더 보기" 같은 요약을 만들지 않는다 | 접으면 안 읽는다. 더 나쁜 건 **무엇을 감췄는지 모른다**는 것 — 감춰진 게 ④(곡이 닫힘)일 수 있다 |
| 묶음 제목 | `--font-size-xs` `--font-weight-medium`, 상자 톤의 글자색, 위 `--space-2` | |
| 묶음 제목이 안 나오는 때 | **항목이 1개면** 제목 줄·묶음 제목 없이 **기존 InlineAlert 한 줄**과 똑같이 보인다. **한 묶음만 해당되면** 그 묶음 제목은 생략하고 제목 줄 + 불릿만 | 하나짜리에 소제목을 붙이면 관료적으로 읽힌다 |

**상자 톤 = 들어 있는 항목 중 가장 무거운 것** (한 줄 규칙)

| 들어 있는 것 | 톤 | 아이콘 |
|---|---|---|
| ④ 가 있다 | **danger** (`--color-danger-bg` / `-border` / `--color-danger`) | `error` |
| ④ 는 없고 ①②③⑥ 중 하나라도 | **warning** | `warning` |
| ⑤ 뿐 | **info** | `info` |
| 아무것도 없음 | **상자 자체가 없다** | — |

> ⑤만 있을 때 노랑이 되지 않게 하는 이유: ⑤는 막아야 할 위험이 아니라 **알아 두면 되는 사실**이다. 노랑을 남발하면 진짜 노랑이 안 보인다.

**합치지 않은 이유** — ①과 ④를 `이 판본은 확인 중이라 안 열려요 — 지금 받을 수 있는 이 곡이 닫혀요` 한 줄로 묶으면 최대 4줄이 된다. 하지만 기획 인수 조건 **8-C 2 가 "판본 경고와 별개로 함께 보인다"** 를 요구한다(`06` §3-2 "둘 다 뜬다"). 두 줄로 남긴다.

### ②-1. 경고 6종 문구 (확정)

| # | 조건 | 묶음 | 화면 문구 | 보조 줄(`--font-size-xs`) |
|---|---|---|---|---|
| **④** | 지금 곡이 `바로 받기 가능`인데 새 판본이 확인 중/이용 제한 | 바뀌면 생기는 일 | **`지금 받을 수 있는 곡이에요 — 바꾸면 이 곡의 다운로드가 닫혀요`** | `곡 상세의 'PDF 받기'가 사라지고 상태가 '{저작권 확인 중\|한국에서 이용 제한}'이 돼요` |
| **⑤** | 이 곡에 다운로드 기록이 있다 | 바뀌면 생기는 일 | `이미 이 곡을 받아 간 사람이 있어요 — 그 사람들의 '받은 악보'에 '지금 추천과 달라요' 표시가 생겨요` | — (사람 수·건수를 적지 않는다 — 기획 §3-2) |
| **①** | 새 판본이 확인 중 / 이용 제한 | 이 판본은 이런 판본이에요 | `이 판본은 저작권이 '{확인 중\|이용 제한}'이라 사용자에게 다운로드가 열리지 않아요` | `판정을 '자유 이용 가능'으로 바꾸면 열려요` |
| **⑥** | 종류가 **파트보** | 이 판본은 이런 판본이에요 | `이 판본은 한 악기 파트만 담고 있어요 — 피아노 독주곡에는 맞지 않을 수 있어요` | — |
| **②** | 종류가 **편곡** | 이 판본은 이런 판본이에요 | `이 판본은 편곡이에요 — 사용자가 원곡 악보를 기대하고 받을 수 있어요` | — |
| **③** | 포함 범위가 **특정 악장** | 이 판본은 이런 판본이에요 | `이 판본은 {2}악장만 들어 있어요 — 곡 전체가 아니에요` | — |

**④를 ①과 다른 말로 읽히게 한 수단 4가지** (기획 §10 designer ③)

| 수단 | ① | ④ |
|---|---|---|
| **자리** | 아래 묶음 `이 판본은 이런 판본이에요` | **위 묶음** `바뀌면 생기는 일` |
| **주어** | **이 판본은** | **이 곡** (`지금 받을 수 있는 곡이에요`) |
| **시제·동사** | `열리지 않아요` — 지금 그런 상태 | `닫혀요` — **내가 눌러서 일어나는 변화** |
| **굵기** | 보통 | **굵게**(상자 안에서 유일) |

- ①의 보조 줄이 `판정을 바꾸면 열려요`(해결 방법)인 반면 ④에는 해결 방법이 없다 — ④의 보조 줄은 **무엇이 사라지는지**를 말한다. 이 비대칭이 "성질 vs 결과"를 한 번 더 굳힌다.
- 기존 ① 문구의 꼬리 `— 저작권 판정을 '자유 이용 가능'으로 바꿔야 해요` 는 **보조 줄로 내렸다.** 본문 줄이 짧아야 5줄이 읽힌다.

### ③ 고른 사유 (필수, 하나) — 미결 6-2 중 **문구 확정**

> 기획 §9 6-2: **내용은 사람**(42곡을 실제로 훑어 본 뒤), **문구는 designer**. 아래는 문구 확정분이며 **6개의 뜻은 기획 §1-4 그대로**다. 바뀐 것은 ⑴ 괄호 설명을 라벨 밖 보조 줄로 내린 것 ⑵ 1·4 의 "자동으로 고른 판본" → **"앞 추천"** (앞 추천이 사람이 고른 것일 수도 있다 — A→B→C 일 때 원문은 거짓이 된다) 두 가지다.

| # | 라디오 라벨 (확정) | 보조 줄 (`--font-size-xs` muted) | 첫 지정에서 |
|---|---|---|---|
| 1 | `앞 추천이 이 곡의 악보가 아니었어요` | `다른 편성(총보 등)이거나 아예 다른 곡이었어요` | **감춤** |
| 2 | `이 판본이 더 읽기 좋아요` | `스캔이 깨끗하거나 조판이 또렷해요` | 보임 |
| 3 | `이 판본의 편집·운지가 배우는 사람에게 맞아요` | `운지·페달 표기가 레슨에 쓸 만해요` | 보임 |
| 4 | `앞 추천은 지금 받을 수 없어요` | `파일이 없거나 이용 제한이 됐어요` | **감춤** |
| 5 | `이 판본이 곡 전체를 담고 있어요` | `또는 이 곡에 맞는 범위예요` | 보임 |
| 6 | `기타 — 직접 적기` | `메모에 이유를 적어 주세요 (필수)` | 보임 |

- **첫 지정(이전 추천이 없는 곡)에서는 1·4 를 감춘다** → 4개만 보인다. 앞 추천이 없는데 "앞 추천이 …"를 고르게 두면 근거가 거짓이 된다. **선택지 값 6개는 그대로**이고 화면만 줄인다(senior-dev 계약 변경 아님).
- 그룹 라벨 `왜 이 판본을 고르셨어요?` + `*`(`.form-label.required`). 기본 선택 **없음**.
- 세로 나열(가로 배치 금지 — 라벨이 길다). 각 항목 높이 ≥ `--touch-target`, 라벨 전체가 클릭 영역.
- 보조 줄은 라벨 아래 `--space-1`, 왼쪽 들여쓰기는 라디오 동그라미 폭만큼.

### ④ 메모

| 항목 | 값 |
|---|---|
| 형태 | `.form-input` **한 줄**. `.form-textarea` 를 쓰지 않는다 — 이 메모는 문장이 아니라 **꼬리표**다(저작권 판정 메모는 법적 근거라 문장이 필요해서 2줄 textarea 다). 한 줄 칸이 "짧게 적어도 된다"고 말한다 |
| 라벨 | 기본 `메모 (선택)` / **"기타" 선택 시 `메모 *`** 로 바뀌고 `.required` |
| 자리 문구 | `예: 앞 추천은 관현악 총보였음` |
| 비어도 저장 | "기타"가 아니면 **비워도 저장된다**(8-B 3) |
| 길이 제한 | **300자.** `{n}/300` 카운터를 오른쪽 아래(`--font-size-xs` muted)에 붙인다 |

### ⑤ "확인했어요" 체크 (기본 꺼짐)

| 항목 | 값 |
|---|---|
| 라벨 | `미리보기를 열어 이 곡의 피아노 악보가 맞는지 확인했어요` (기획 §3-3 문구 그대로) |
| 기본값 | **꺼짐.** 켜 두면 아무 생각 없이 지나가고, 그러면 미검수 표시가 "뜻 없는 항상 0"이 된다 |
| 옆 버튼 | `.btn.btn-text` **`미리보기 열기`** → **바꿀 판본**의 첫 페이지 `PreviewLightbox`(00 §3-10). 미리보기가 없으면 `:disabled` + `미리보기가 아직 없어요 — PDF를 직접 확인해 주세요` |
| 보조 줄 | 꺼짐: `체크하지 않으면 이 곡은 '추천 판본 확인 필요'에 남아요` / 켜짐: `이 곡은 '추천 판본 확인 필요'에서 바로 빠져요` (`--font-size-xs` muted) |
| 필수 아님 | 체크하지 않아도 바꿀 수 있다 |

> 체크 옆에 `미리보기 열기`를 붙이는 이유: **보지 않고 체크하는 것을 막을 수는 없어도, 보려면 화면을 떠나야 하는 상태는 만들지 않는다.**

### ⑥ 버튼과 검증

| 항목 | 값 |
|---|---|
| `취소` | `.btn.btn-secondary` → 패널이 닫히고 **추천도 고른 이유도 하나도 바뀌지 않는다**(8-B 6). **확인창을 띄우지 않는다** — "취소하면 아무 일도 없다"가 이 버튼의 전부여야 한다 |
| `이 판본으로 바꾸기` | `.btn.btn-primary`. **`:disabled` 로 두지 않는다** — 비활성 버튼은 "왜 못 누르는지"를 말하지 않는다. 누르면 검증하고 안내한다(기획 §3-1 6 과 같은 흐름) |
| 사유 미선택 | 저장 안 됨. 사유 그룹 위에 `--color-danger` 한 줄 **`왜 이 판본을 골랐는지 골라 주세요`** + 그룹으로 스크롤·포커스. 추천은 바뀌지 않는다(8-B 2) |
| "기타"인데 메모 빔 | 저장 안 됨. 메모 경계 `--color-danger` + 아래 **`왜 이 판본을 골랐는지 적어 주세요`**(8-B 4) |
| 저장 중 | 버튼 안 스피너 16px + `바꾸는 중…` `:disabled`(00 §3-7). 취소 버튼도 `:disabled` |
| 성공 | 패널 닫힘 → 목록 재정렬(새 추천이 맨 위) → **A-1 이 새로고침 없이** 방금 고른 사유·내 이름·지금 시각으로 바뀜(8-B 5) → 이력 +1 → Toast `추천 판본을 {이전 종류·출판사}에서 {새 종류·출판사}로 바꿨어요` (이전 없으면 `추천 판본으로 지정했어요`) — **기존 문구 유지** |
| 성공 + 체크함 | A-1 의 미검수 줄이 `✓ 미리보기를 확인한 추천이에요` 로 나온다 |
| 실패 | **패널은 열린 채**, 버튼 위에 InlineAlert danger `바꾸지 못했어요. 잠시 후 다시 시도해 주세요`. 고른 사유·메모·체크는 **그대로 남는다** |
| 파일 없음 400 | `파일이 없어 추천으로 지정할 수 없어요` (서버 문구 그대로). 정상 흐름에서는 버튼이 이미 막혀 있어 볼 일이 없다 |
| 세션 만료 | 00 §4 공통 규칙 (패널 닫고 로그인으로, 작성 중 내용 안내 포함) |

### 모바일 (<768px)

- 패널은 **행 아래 같은 자리**(전체 화면 시트로 띄우지 않는다 — 위 행이 가려지면 안 된다).
- 경고 상자: 항목 줄이 2~3줄로 접힌다. **그래도 접지 않는다.**
- 사유 라디오: 세로 그대로, 각 항목 높이 `--touch-target`.
- 버튼 2개: 패널 하단 가로 2등분(`취소` 40% / `이 판본으로 바꾸기` 60%), 패널이 길어 버튼이 화면 밖이면 **패널 하단 sticky**(배경 `--color-surface`, 위 경계 `--color-border`, `--shadow-lg` — 화면 B·05 폼과 같은 패턴).

## 플랫폼 차이 (06 전체)

- 앱 미도입.
- 모바일: 판본 추가/수정은 전체 화면 시트(닫기 ✕ 좌상단, 저장은 하단 sticky). 대기함 표는 카드. 일괄 바는 하단 sticky 로 이동.
- **A-1 "이 판본을 고른 이유"**: 모바일도 **동일**(세로 한 열이라 그대로 쌓인다). 이력 한 줄만 3단 → 2단으로(`{시각} · {누가}` / `{이전} → {새}` / 사유 — 사유는 셋째 줄 유지).
- **A-3 패널**: 모바일도 **행 아래 인라인**(전체 화면 시트로 띄우지 않는다). 버튼만 패널 하단 sticky. 상세는 A-3 "모바일".
- 데스크톱: 모달 640px, 표.
