## 구성 요소

|---|---|---|
| **구분 바** | `피아노`(선택) · `바이올린 준비 중` · `오케스트라 준비 중`. 준비 중 탭을 누르면 **화면 이동**(push) — 현재 쿼리(`q`·`in`·`level`·`pages`·`downloadable`·`page`)를 그대로 실어 `/violin?q=…` 로 간다. 검색어·기준·필터는 버리지 않고, 뒤로 오거나 돌아가기 링크로 오면 그대로 복원된다(기획 04 §1-2, 08 §2-3) | 00 §3-15 **공통**. 상세 08 §1 |
| **검색 기준 세그먼트** | `전체` · `곡명` · `작곡가`. 주소의 **`in`** 이 선택돼 보인다(`in=TITLE` → 곡명, `in=COMPOSER` → 작곡가, 없거나 이상한 값이면 **"전체"**). 바꾸면 **검색어 유지 + 즉시 재검색**, 필터 **유지**, 페이지 **1페이지로**. 주소 갱신은 **push**(뒤로 가기로 되돌아감) — "전체"를 고르면 `in` 을 주소에서 뗀다 | 00 §3-16 **공통**. 상세 08 §4 |
| 검색창 | SearchBar large. URL `q` 값이 채워진 상태. **자리 문구는 선택된 기준에 따라 바뀐다**(08 §4-3). 고쳐서 Enter → `q` 갱신, `page`·필터는 **초기화**(새 검색), **기준은 유지**. `✕` 로 비우기 | 공통 |
| 구분 안내 줄 | `{구분}은 준비 중이라 피아노 악보에서 찾았어요.` — 주소에 화면 전용 쿼리 **`from=violin` / `from=orchestra`** 가 있을 때만(준비 중 화면의 헤더 검색이 붙여 보낸다). 검색창 아래, 작곡가 카드 위. 이 검색 한 번에만 보인다 — 이 화면의 **모든 주소 갱신**(재검색·기준·필터·페이지)에서 `from` 을 이어 붙이지 않는다. 알 수 없는 값이면 줄 없음(오류 아님). API 로 넘기지 않는다 | InlineAlert **info** (00 §3-11). 상세 08 §2-4 |
| 작곡가 일치 카드 | `작곡가: 쇼팽 (Frédéric Chopin)` 굵게 / 아래 **`등록된 곡 24개 모두 보기`** / 오른쪽 `chevron_right`. **`곡 24개` 로 쓰지 않는다** — 그 문구는 "이 결과에 24개"로 읽혀서 아래 결과가 8곡·0곡일 때 사용자가 모순으로 느낀다. 숫자(필터·페이지와 무관한 "작곡가 페이지에 가면 있는 곡 수")는 그대로 두고 **문구로 다른 질문의 답임을 말하기로** 한 확정 사항이다(기획 01 §11-4, 인수 조건 01 §6 "§11-4 필터 0건과 작곡가 카드" 1번). 기획 문구의 끝 `→` 는 **카드 오른쪽 `chevron_right` 가 대신한다** — 한 줄에 화살표를 두 개 두지 않는다(08 §1-2: 화살표는 "행 → 상세"의 표시). 카드 전체 → 작곡가 상세. **필터 0건일 때 카드에 딸리는 출구 한 줄은 아래 [A] 참조**. 검색어가 작곡가 한글·원어·별칭에 걸릴 때만. 여러 작곡가에 걸리면 세로로 최대 3개(넘으면 `작곡가 N명 더 — 작곡가 목록에서 찾기` 링크). **기준이 "곡명"이면 이 카드를 표시하지 않는다** — 곡명 기준은 작곡가를 찾지 않기로 한 약속이라(기획 04 §4-2, 인수 조건 8-D 5) 카드가 뜨면 그 약속이 깨져 보인다. 기준 "전체"·"작곡가"에서는 표시. **현재 구분에 공개 곡이 있는 작곡가만**(기획 04 §5) | 흰 카드 `--radius-md`, **좌측 4px 띠 `--color-primary`**, 아이콘 `person` `--color-primary`, padding `--space-4`. 아래 `--space-4` |
| 결과 건수 | `'녹턴' 검색 결과 21곡`. 필터가 걸려 있으면 `'녹턴' 검색 결과 21곡 중 8곡`. **기준이 전체가 아니면 뒤에 muted 로 `· 곡명에서 찾음` / `· 작곡가 이름에서 찾음`** — 결과가 적을 때 "왜 적은가"를 그 자리에서 답한다. 이 표시는 **사실 고지**이지 권유가 아니므로 인수 조건 8-E 5 위반이 아니다(아래 "사실 고지와 권유는 다르다") | `--font-size-base` `--font-weight-medium`, 검색어 부분 `--color-primary`, 기준 표시 `--font-size-sm` `--color-text-muted` |

| **구분 안내 줄이 뜬 상태에서 0건** | 안내 줄은 그대로 두고 그 아래에 A/B/C 중 하나. 이 줄은 0건 안내와 겹치는 말을 하지 않으므로 예외적으로 공존한다 |

## 0건 화면 3분기 (기획 04 §4-4 우선순위를 화면에서 겹치지 않게)

**원칙: 한 화면에 빈 상태 블록은 하나뿐이다.** 여러 안내가 동시에 뜨면 사용자는 무엇도 읽지 않는다.

```
결과 0건
  │
  ├─ 필터가 하나라도 선택돼 있나? ── 예 ──▶ [A] 필터 안내만
  │     (필터를 다 풀면 결과가 있는지 화면이 알 필요 없다.        + 작곡가 카드가 1명 떠 있으면
  │      풀었는데도 0건이면 그때 B 또는 C 로 넘어간다 = 가까운 원인부터)  카드에 딸린 출구 한 줄 (아래)
  └─ 아니오
       │
       ├─ 기준이 곡명/작곡가이고 전체 기준에 결과가 있다고 **확인됨** ─ 예 ─▶ [B] "전체로 찾기" 하나
       └─ 그 외 ────────────────────────────────────────────────▶ [C] 기존 0건 안내
```

### [A] 안에서 유일하게 허용되는 한 줄 — 작곡가 카드에 딸린 출구

```
┌────────────────────────────────────┐
│ 👤 작곡가: 쇼팽 (Frédéric Chopin)   │  ← 카드는 그대로 떠 있다 ("등록된 곡 10개 모두 보기 ›")
│    등록된 곡 10개 모두 보기       › │
└────────────────────────────────────┘
'쇼팽' 검색 결과 10곡 중 0곡
┌ 난이도 [입문]…  ☑ 바로 받기 가능한 곡만 ─▶   ← 필터 바 유지(원인이 보여야 한다)

        [filter_alt_off 48px]
      이 조건에 맞는 곡이 없어요
        ┌──────────────┐
        │   필터 해제    │              ← .btn.btn-secondary (주된 출구)
        └──────────────┘
   쇼팽의 곡은 10개 등록돼 있어요 —
   조건 없이 모두 보기 →                ← .btn.btn-text (한 단계 조용한 두 번째 출구)
```

| 항목 | 값 |
|---|---|
| 문구 | `{작곡가}의 곡은 {N}개 등록돼 있어요 — 조건 없이 모두 보기` + `arrow_forward` 16px. `{N}` 은 **카드에 적힌 것과 같은 숫자**(필터·페이지와 무관). 조사 계산을 피해 `의` 는 고정 문자열 |
| 형태 | `.btn.btn-text` `--font-size-md` `--color-primary`. **버튼이 아니다** — `필터 해제`(secondary 버튼)보다 한 단계 조용해야 한다. primary 버튼을 두 개 만들지 않는다 |
| 자리 | `.empty-state` 블록 **안**, `필터 해제` 버튼 아래 `--space-4`. 카드 안이 아니라 여기다 — 사용자가 "0곡"을 읽는 바로 그 자리에서 모순을 이어야 하고, 카드 안에 넣으면 카드가 같은 말을 두 줄로 반복한다 |
| 동작 | 그 작곡가 상세로 이동(push). **필터를 푸는 게 아니라 화면을 옮긴다** — `필터 해제` 와 목적지가 다르다 |
| 뜨는 조건 | ① 상태가 **[A]** 이고 ② 작곡가 일치 카드가 **정확히 1명** 떠 있을 때만 |
| 카드가 2명 이상일 때 | **이 줄을 하나도 붙이지 않는다.** 어느 작곡가를 가리키는지 모호해지고 줄이 늘어 더미가 된다. 그때는 카드마다 이미 `등록된 곡 N개 모두 보기 ›` 라는 자기 출구를 갖고 있다 *(designer 판단 → 기획 확정: `04` 개정 7, `01` §6 §11-4 항목에 인수 조건 추가. qa 재현: 시드 기준 `슈` → 슈베르트·슈만 카드 2개, 필터로 0곡을 만들어도 줄이 없어야 한다 — 줄이 보이면 결함)* |
| 카드가 없을 때 | 줄도 없다. 기준이 "곡명"이면 카드 자체가 뜨지 않으므로(8-D 5) 이 줄도 뜨지 않는다 |

**"[A]에서는 다른 안내를 전부 숨긴다"는 원칙과 어떻게 공존하는가**

숨기기로 한 것들(기준 관련 안내·"다른 이름으로 불리기도 해요" 3줄·인기곡·작곡가 목록 버튼·IMSLP 링크)과 이 한 줄은 **성격이 다르다.** 셋으로 가른다.

1. **조언이 아니라 확실한 클릭이다.** 숨긴 것들은 전부 "이렇게 해 보세요"(결과를 모른다). 이 줄은 화면이 이미 **서버에게 받은 숫자 10개**를 근거로 하고, 누르면 반드시 10곡이 있는 화면이 나온다. [B]에서 조언을 숨긴 이유가 "확실한 클릭 하나가 조언 더미에 묻히면 안 된다"였는데, 이 줄은 **묻히는 쪽이 아니라 묻힐 뻔한 쪽**이다.
2. **새 블록이 아니라 이미 화면에 있는 것의 각주다.** [A] 에서 사용자가 마주치는 진짜 혼란은 **"카드는 10개라는데 결과는 0곡"** 이다. 그 모순을 만든 것이 화면 자신이므로, 그 설명은 새로 들여온 안내가 아니라 **화면이 자기 말에 지는 책임**이다. 카드를 지우면 사용자가 0건 화면에 갇힌다는 것이 기획 §11-4 의 판단이고, 카드를 남기기로 한 이상 이 줄은 그 카드의 일부다.
3. **위계로 충돌을 막는다.** "가까운 원인부터 말한다"는 순서는 그대로다 — `필터 해제`(가까운 원인, secondary 버튼)가 먼저 보이고, 이 줄은 **글자만 있는 링크**로 한 단계 아래에 놓인다. 두 출구는 목적지가 달라 서로를 대신하지 않는다(하나는 이 화면에 남고, 하나는 작곡가 상세로 나간다).

> 따라서 **"빈 상태 블록은 한 화면에 하나뿐"** 이라는 규칙은 깨지지 않는다. 블록은 여전히 하나([A])이고, 이 줄은 그 블록 **안의 두 번째 줄**이다. 인수 조건 8-E 10 도 그대로 통과한다 — 8-E 10 이 "겹쳐 보이면 안 된다"고 지목한 것은 **세 가지 안내 블록**(필터 해제 안내 · 전체로 찾기 출구 · 기존 0건 안내 3줄+IMSLP+인기곡+작곡가 목록)이고, 이 줄은 그 셋 중 어느 것도 아니다.

**[B]·[C]에는 이 줄을 붙이지 않는다.** 두 경우는 필터가 걸려 있지 않아 "조건 없이"라는 말이 가리킬 조건이 없고, [B]에서는 `전체로 찾기` 라는 더 정확한 출구가 이미 있다.

---

**사실 고지와 권유는 다르다 (인수 조건 8-E 5 를 읽는 법 — qa 용)**

기획 04 §8-E 머리말이 못 박은 구분을 이 정의서에도 적어 둔다.

| | 뜻 | 이 화면의 예 | 8-E 5 |
|---|---|---|---|
| **권유** | 다른 기준으로 찾아보라고 **시키는 말** | `곡명으로 좁혀 보세요` 류 — **어느 화면에도 만들지 않는다** | 보이면 **위반** |
| **사실 고지** | 지금 무슨 일이 일어났는지만 말한다. 누를 수 없고, 아무것도 권하지 않고, 결과가 있다고 약속하지 않는다 | [C]의 `지금은 '곡명'에서만 찾고 있어요`(8-E 11) · 결과 건수 옆 `· 곡명에서 찾음` · 구분 안내 줄 `바이올린은 준비 중이라 피아노 악보에서 찾았어요` | **위반 아님** |

- **8-E 5 는 "전체로 0건일 때 권유를 하지 않는다"이지 사실 고지 금지가 아니다.** 게다가 8-E 5 의 상황(기준=전체)에서는 `지금은 '곡명'에서만…` 줄도 `· 곡명에서 찾음` 표시도 **애초에 나오지 않는다**(둘 다 기준≠전체일 때만).

---

**[B] 판정 정보 — 응답 `totalInAll` (확정 2026-09-10, API 명세서 §3-1; 기획이 "타협 불가"라고 한 조건의 화면 규칙)**

`totalInAll` = 같은 구분 · 같은 검색어 · 기준 전체 · **필터 없음**의 곡 수. `in=ALL` 이면 `null`, 아니면 정수(0 포함).

| 응답 `totalInAll` | 화면 |
|---|---|
| **정수 N > 0** (기준 곡명/작곡가) | [B] — `전체에서 찾으면 N곡이 있어요` + `전체로 찾기 →` |
| **`0`** (기준 곡명/작곡가, 전체로도 0건) | [C]. `지금은 '곡명'에서만 찾고 있어요` 줄은 표시 |
| **`null`** (기준 전체 — 질문이 성립하지 않는다) | [C]. [B] 검사를 하지 않는다. 사실 고지 줄도 없다 |

- **"모름"(`null`)과 "0건"(`0`)을 같게 취급하지 않는다.** 계약이 셋을 갈라 주므로 화면이 추측으로 [B] 를 띄우는 경우가 없다. frontend-dev: `!totalInAll` 로 판정하면 둘이 뭉개진다 — `!= null && > 0` 로 읽는다.
- 이전 시안의 "있다/없다만" 변형(숫자 없는 `전체에서 찾으면 결과가 있어요`)은 **쓰지 않는다** — 계약이 항상 정수를 준다.

- 그 한 줄(`지금은 '곡명'에서만 찾고 있어요`)은 **사실 고지이지 출구가 아니다.** 버튼이 아니고, "전체로 찾으면 있다"고 약속하지 않는다. 사용자의 눈을 위쪽 세그먼트로 보내는 것이 전부다.
- **"곡명이나 작곡가로 좁혀 보세요" 류 안내는 어느 경우에도 만들지 않는다** (안내는 넓히는 방향으로만 — 기획 04 §4-4).
- 자세한 배치·문구·근거: `08_악기구분_탭_준비중안내.md` §4-7.
