(최근 본 곡이 없으면 왼쪽 열은 인기곡 하나뿐 — 2026-09-10 시안과 같다)

- 상단 소개 영역: 배경은 페이지 바탕 그대로(기존 보라 그라데이션 hero **사용 안 함** — 검색창이 주인공이어야 하므로 배경을 비운다). 상하 padding `--space-10`(모바일 `--space-6`). 구분 바가 위에 붙었으므로 **위쪽 padding 을 `--space-8`(모바일 `--space-5`)로 줄인다** — 헤더·탭·h1 이 연달아 오면 첫 화면이 무거워진다.
- 기준 세그먼트 ↔ 검색창 간격 `--space-2`, 세그먼트 위 `--space-4`. **세그먼트 왼쪽 끝 = 검색창 왼쪽 끝** (00 §3-16).
- 인기곡 : 작곡가 = 데스크톱 `7fr : 5fr`, gap `--space-8`. 태블릿(600~1023)은 세로 쌓기, 작곡가 4열.
- **최근 본 곡이 있을 때(2026-09-20)**: 데스크톱 왼쪽 7fr 열에 `최근 본 곡` → `인기곡` 세로 두 블록(사이 `--space-8`), 오른쪽 5fr 의 작곡가는 **두 블록 옆에 걸쳐 선다**(grid-row span). 작곡가 영역이 아래로 밀리지 않는다. 모바일·태블릿은 세로 쌓기: 검색 → 최근 본 곡 → 인기곡 → 작곡가. 없으면 그리드에 빈 칸·빈 제목이 남지 않는다(영역 자체를 렌더하지 않는다).

## 상태별 UI

| 상태 | 표시 |
|---|---|
| **로딩** (인기곡·작곡가 동시 요청) | 검색창은 즉시 렌더·포커스. 인기곡 자리 스켈레톤 5줄(순위 원 + 제목 줄), 작곡가 자리 스켈레톤 카드 4개. 두 영역 독립 |
| **인기곡 불러오기 실패** | 인기곡 영역 안에만 `연결을 확인해 주세요` + `다시 시도`(00 §3-9, 아이콘 없이 작게: 제목 `--font-size-md`). 검색창·작곡가 영역은 영향 없음 |
| **작곡가 불러오기 실패** | 위와 같이 작곡가 영역 안에만 |
| **인기곡 0개** (곡이 아직 하나도 없음) | 인기곡 영역: 아이콘 `library_music` 48px + `아직 등록된 곡이 없어요` (`--font-size-md` muted). 영역 제목은 유지 |
| **작곡가 0명** | 작곡가 영역: `아직 등록된 작곡가가 없어요`. "모든 작곡가 보기" 링크는 그대로(목록 화면의 빈 상태로 이어짐) |
| **빈 검색어 Enter** | 이동 없음. 검색창 흔들림 + 경계 강조(00 §3-1). 오류 문구 없음 |
| **기준만 바꿨을 때** (검색어 없음) | **화면 이동 없음.** 세그먼트 선택 표시 · 검색창 자리 문구 · 예시 칩 3개만 바뀐다. 포커스는 검색창에 그대로. 오류 문구·흔들림 없음 (인수 조건 8-E 2) |
| **기준을 바꾸고 이미 친 글자가 있을 때** | 입력칸 내용을 **지우지 않는다.** 자리 문구는 어차피 안 보이므로 눈에 띄는 변화는 예시 칩뿐 |
| **구분 바** | 서버 응답과 무관하게 **즉시 렌더**(고정 3개). 인기곡·작곡가가 실패해도 구분 바는 살아 있다 (08 §1-6) |
| **다시 들어왔을 때** | 항상 **"전체"**로 시작한다. 지난 선택을 기억하지 않는다 (인수 조건 8-F 5) |
| **인기곡 중 준비 중/이용 제한 곡** | compact 카드에 상태 뱃지 표시(제목 오른쪽, 모바일은 아래 줄) |
| **로그인 상태** | 홈 내용은 동일. 헤더만 다름(로그인 시 "내 악보" 메뉴 — 00 §2-1). **최근 본 곡은 로그인과 무관** — 로그인해도 다른 기기에 나타나지 않고, 로그아웃해도 남는다(8-E 5) |
| **최근 본 곡 — 저장된 곡 없음** (첫 방문·시크릿 창·지운 직후·저장이 막힌 브라우저) (2026-09-20) | **영역 자체가 없다.** 제목도 빈 카드도 없다. 요청도 보내지 않는다. 이 홈은 2026-09-10 시안과 픽셀 단위로 같다(8-E 2·10, 8-G 4) |
| **최근 본 곡 — 로딩** | 저장된 곡이 있으면 **그 개수만큼**(최대 10) compact 스켈레톤을 제목과 함께 **즉시** 그린다 → 응답 오면 교체. 이유: 이 영역은 거의 확실히 나타날 것이라, 응답 후에 끼워 넣으면 인기곡이 한 화면 아래로 튄다. 인기곡·작곡가 스켈레톤과 독립 |
| **최근 본 곡 — 정보를 못 가져옴** (네트워크·서버) | 영역이 **조용히 사라진다**(스켈레톤째 제거). 오류 상자·다시 시도 없음(8-E 11). 인기곡·작곡가의 실패 표시는 기존대로 각자 영역에 |
| **최근 본 곡 — 일부가 숨김·삭제됨** | 그 곡만 빠진다(눌러서 404 를 만나지 않는다 — 8-E 8). **전부** 그러면 영역이 없다. 숨김이 풀리면 다시 나온다 |
| **최근 본 곡 — 지우기 누름** | 즉시 영역 제거(전환 애니메이션 없음 — 빈 자리가 잠깐이라도 남지 않게). 다음에 곡 상세를 하나 열면 그 1곡으로 다시 생긴다(8-E 6) |
| **최근 본 곡 — 11곡째** | 가장 오래된 곡이 빠져 10곡(8-E 4). 홈은 저장된 것을 그대로 그릴 뿐 자르지 않는다 |

## 플랫폼 차이

- 앱(Flutter) 미도입 — 웹 반응형만.
- 모바일: 검색 버튼은 입력칸 안 아이콘(`search`). 데스크톱: 입력칸 오른쪽 "검색" 버튼.
- 모바일: 구분 바 3등분 2줄, 기준 세그먼트 폭 100% 3등분. 데스크톱: 구분 바 한 줄, 세그먼트 auto 폭.
- **왜 예시 칩이 기준을 따라 바뀌는가**: 작곡가 이름이 든 검색어(`쇼팽 녹턴`)가 곡명에서 걸리는 건 **별칭에 기댄 우연**이라 곡명 칩에 두지 않는다 — 시드에서는 별칭 덕에 곡명으로도 2곡이 나오지만(0건 아님, 결함 아님), 별칭에 작곡가 이름이 없는 곡은 확실히 0건이다(예: `베토벤 엘리제`. 기획 04 §4-2-1·§4-6 1). 우리가 만든 칩이 사용자를 0건으로 보내지 않도록 곡명 칩은 곡 이름·작품번호로만 짠다. 근거: 08 §4-5.
- 모바일에서 `autoFocus` 는 iOS Safari 가 키보드를 자동으로 띄우지 않을 수 있다 — 포커스는 걸되 키보드 강제 표시는 시도하지 않는다(qa: "커서가 검색창에 있다" 기준은 포커스 여부).
- **최근 본 곡은 브라우저 저장**이다(05 §4-2). 앱을 만들면 기기 저장으로 옮기되 계정 동기화로 바꾸지 않는다 — 기획이 "계정의 것이 아니다"로 못 박은 기능이다(05 §0-4).
- **왜 최근 본 곡을 이렇게 두었나 (2026-09-20)**
  - **인기곡과 같은 카드, 순위만 뺐다**: 기획 8-E 7 이 "인기곡과 같은 모양"을 요구한다. 가로 스크롤 띠·작은 칩 같은 다른 모양은 발자국을 줄일 수 있지만 그 조건을 어긴다. 대신 **더 크지 않게** — 썸네일·큰 글자·배경색을 더하지 않고, 최대 개수(10)도 인기곡과 같다(05 §4 "인기곡보다 크지 않게").
  - **데스크톱에서 인기곡의 열 안에 넣은 이유**: 전폭으로 두면 10줄짜리 블록이 인기곡·작곡가를 통째로 한 화면 아래로 밀어 "검색창 하나가 주인공"인 홈이 "최근 본 곡이 주인공"인 홈이 된다. 같은 열의 위에 두면 작곡가 열은 제자리에 남고, "검색창 아래·인기곡 위"라는 순서도 지켜진다.
  - **"내 최근 본 곡"이라 부르지 않는 이유**: "내"는 계정을 암시한다. 시크릿 창·다른 폰에서 없는 목록에 "내"를 붙이면 "왜 내 건데 여기 없지"가 된다. 제목은 그냥 사실(`최근 본 곡`)만 말하고, 무엇도 약속하지 않는다.
  - **지우기에 확인·되돌리기가 없는 이유**: 이 버튼의 진짜 용도는 공용 컴퓨터에서 "내가 뭘 봤는지"를 한 번에 없애는 것이다(05 §4-2). 되돌리기 토스트를 두면 그 목적이 5초 동안 열려 있다.
  - **스켈레톤을 저장된 개수만큼 그리는 이유**: 영역이 "있을 때만" 나타나므로, 있을 것이 확실한 순간(저장된 곡이 있음)에는 자리를 먼저 잡아야 아래 영역이 튀지 않는다. 결과가 0(전부 숨김·실패)이면 영역째 걷는다 — 그 잠깐의 스켈레톤은 오류 상자가 아니므로 8-E 11 에 어긋나지 않는다.
