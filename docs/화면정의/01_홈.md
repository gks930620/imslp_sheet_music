- 상단 소개 영역: 배경은 페이지 바탕 그대로(기존 보라 그라데이션 hero **사용 안 함** — 검색창이 주인공이어야 하므로 배경을 비운다). 상하 padding `--space-10`(모바일 `--space-6`). 구분 바가 위에 붙었으므로 **위쪽 padding 을 `--space-8`(모바일 `--space-5`)로 줄인다** — 헤더·탭·h1 이 연달아 오면 첫 화면이 무거워진다.
- 기준 세그먼트 ↔ 검색창 간격 `--space-2`, 세그먼트 위 `--space-4`. **세그먼트 왼쪽 끝 = 검색창 왼쪽 끝** (00 §3-16).
- 인기곡 : 작곡가 = 데스크톱 `7fr : 5fr`, gap `--space-8`. 태블릿(600~1023)은 세로 쌓기, 작곡가 4열.

## 플랫폼 차이

- 앱(Flutter) 미도입 — 웹 반응형만.
- 모바일: 검색 버튼은 입력칸 안 아이콘(`search`). 데스크톱: 입력칸 오른쪽 "검색" 버튼.
- 모바일: 구분 바 3등분 2줄, 기준 세그먼트 폭 100% 3등분. 데스크톱: 구분 바 한 줄, 세그먼트 auto 폭.
- **왜 예시 칩이 기준을 따라 바뀌는가**: 작곡가 이름이 든 검색어(`쇼팽 녹턴`)가 곡명에서 걸리는 건 **별칭에 기댄 우연**이라 곡명 칩에 두지 않는다 — 시드에서는 별칭 덕에 곡명으로도 2곡이 나오지만(0건 아님, 결함 아님), 별칭에 작곡가 이름이 없는 곡은 확실히 0건이다(예: `베토벤 엘리제`. 기획 04 §4-2-1·§4-6 1). 우리가 만든 칩이 사용자를 0건으로 보내지 않도록 곡명 칩은 곡 이름·작품번호로만 짠다. 근거: 08 §4-5.
- 모바일에서 `autoFocus` 는 iOS Safari 가 키보드를 자동으로 띄우지 않을 수 있다 — 포커스는 걸되 키보드 강제 표시는 시도하지 않는다(qa: "커서가 검색창에 있다" 기준은 포커스 여부).
