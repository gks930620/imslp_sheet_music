> **2026-09-10 개정 — 이 화면의 변화는 딱 하나다**: 헤더 아래에 **악기 구분 바**가 붙고(00 §3-15 / 08 §1), 그 곡이 속한 구분의 탭이 선택돼 보인다. 곡 정보·추천 판본·판본 목록·다운로드·미리보기·문구는 **하나도 바뀌지 않는다**(기획 04 §7 "충돌하지 않는 것"). 브라우저 탭 제목만 `월광 소나타 — 쉬운악보 피아노` 형식으로(00 §4-1).
>
> **2026-09-20 개정 — 즐겨찾기(기획 `05`)**: 곡 정보 영역에 **즐겨찾기 버튼**(§3-6 — 2상태·자리·토스트·비로그인 복귀)이 하나 생긴다. 그 별과 충돌하는 아이콘 둘을 바꾼다 — "악장 안내" 줄 `bookmark` → **`menu_book`**(05 §8 충돌 6, 인수 조건 8-A 8), 추천 판본 라벨 `star` → **`thumb_up`**(§3-6-4). 추천 판본 카드·판본 목록·다운로드·미리보기·문구는 그대로다(8-G 3 — `01` §6 곡 상세 인수 조건이 그대로 통과해야 한다). 이 화면이 정상으로 열리면 브라우저의 **최근 본 곡**에 기록된다(화면 변화 없음 — 상태표 마지막 행, `01_홈`). 내 악보 화면은 `09_내악보_즐겨찾기_받은악보.md`.
>
> **2026-09-20 재개정 — 로그인 복귀 주소 확정(API 명세서 §10-4)**: §3-6-2·§3-6-3 의 "로그인 화면으로, 이유 = 즐겨찾기"를 `/login?redirect={이 곡 상세 주소}&reason=favorite` 로 닫았다.

이 화면의 주인공은 **추천 판본 카드 하나와 다운로드 버튼 하나**다. 곡 정보는 그 위에 간결하게, 나머지는 아래로 접는다.

### 3-4. 같은 작곡가의 다른 곡

- h2 `같은 작곡가의 다른 곡` (`--font-size-xl`), WorkCard **compact** 최대 5개(순위 숫자 없음, 작곡가 줄 생략). 누르면 그 곡 상세 `/piano/works/:id`(스크롤 맨 위). 서버가 이 곡의 구분 안에서 고른 목록이라 링크의 구분과 어긋나지 않는다(API 명세서 §0-7).
- 0개면 **영역 생략**.

### 3-5. 미리보기 크게 보기 `PreviewLightbox` (00 §3-10)

```
 star_border 20px             star 20px
```

#### 3-6-2. 로그인 상태에 따라

| 상태 | 버튼 | 누르면 |
|---|---|---|
| 로그인 | 계정의 상태대로 켜짐/꺼짐 | §3-6-1 |
| 비로그인 | **보인다**(꺼짐 모양, 자물쇠·"로그인 필요" 문구 없음 — 8-B 1, 8-G 2) | **로그인 화면**으로 이동 — `/login?redirect={이 곡 상세 주소}&reason=favorite`(**확정** — API 명세서 §10-4, `09` §3). 버튼 상태는 바뀌지 않은 채 떠난다 |
| 인증 확인 중(헤더 "…") | 꺼짐 모양으로 그린다. 상태를 알게 되면 그 상태로 바뀐다(애니메이션 없음). 즐겨찾기 상태가 곡 상세 응답과 함께 오면 깜빡임이 없다 — `09` §6 S5 | **로그인 화면으로 보내지 않는다.** 확인이 끝난 뒤 그 결과대로 — 로그인돼 있었으면 켜지고, 아니면 로그인 화면(8-B 7) |
| 세션이 조용히 풀림(저장 거부) | — | 비로그인과 같다: 로그인 화면 → 복귀 완성. **헤더도 비로그인 상태로 바뀐다**(05 §1-2 마지막) |

#### 3-6-3. 비로그인 → 로그인 → 돌아와서 완성 (05 §1-2, 8-B)

```
곡 상세(예: /piano/works/21) [☆ 즐겨찾기] 누름
   → /login?redirect=%2Fpiano%2Fworks%2F21&reason=favorite                 `09` §3, API 명세서 §10-4
      (부제 자리: ☆ 즐겨찾기는 로그인하면 쓸 수 있어요)
   → 로그인 성공
   → 같은 곡 상세로 복귀 — 도착 시점에 이미 [★ 즐겨찾기됨]
   → Toast 성공 (check_circle) "즐겨찾기에 넣었어요"  — 한 번, 3초
```

| 항목 | 값 |
|---|---|
| 돌아온 화면 | **같은 곡 상세**(홈·내 악보 아님 — 05 §1-2 "막다른 화면 금지"). 헤더는 로그인 상태(닉네임·내 악보 메뉴) |
| 버튼 | 화면이 그려질 때 **이미 켜져 있다.** 꺼짐 → 켜짐으로 바뀌는 애니메이션·지연을 두지 않는다("다시 누를 필요가 없다"가 눈에도 보여야 한다) |
| 토스트 | `즐겨찾기에 넣었어요` — 성공 아이콘. **한 번만.** 새로고침하면 뜨지 않는다(완성이 두 번 일어나지 않는 것과 같은 수단 — senior-dev, `09` §6 S2). **다른 기기에서 이미 넣어 둔 곡이어도 같은 문구**다(05 §1-2 5 허용 범위 — "새로 넣었는지"를 계약이 구분할 필요가 없게 한다, `09` §6 P2) |
| 완성이 실패(네트워크) | 버튼 꺼짐 + §3-6-1 실패 토스트. 사용자가 다시 누르면 된다 |
| 로그인 화면에서 돌아가기·뒤로 가기 | 곡 상세, 버튼 꺼짐, 토스트 없음(8-B 6) |

#### 3-6-4. 왜 별인가 — 그리고 추천 판본 라벨의 별을 바꾼 이유

이 화면에는 이미 `star` 가 있었다(추천 판본 라벨, §3-2). 즐겨찾기를 별로 하면 **제목 아래의 ★ 과 카드 위의 ★ 이 서로 다른 뜻**으로 몇 줄 사이에 선다. 둘 중 하나가 물러나야 했다.

| 안 | 검토 |
|---|---|
| 즐겨찾기를 하트(`favorite`)로, 추천 별은 유지 | **탈락.** ① 기획이 즐겨찾기를 **별**로 못 박았다 — 05 §0-2("별 모양"), §2-4 빈 상태 문구 `☆ 즐겨찾기`, 인수 조건 **8-A 1 "채워진 별 + 글자"**. 하트로 바꾸면 인수 조건 문구부터 고쳐야 한다. ② 한국어 "즐겨찾기"의 그림은 브라우저 즐겨찾기(크롬 주소창의 별)로 학습돼 있다. 하트는 "좋아요·찜"이지 "즐겨찾기"가 아니다 |
| **즐겨찾기는 별, 추천 판본 라벨을 `thumb_up` 으로** | **채택.** 추천 라벨의 별은 `03` §3-2 에서 designer 가 고른 장식이라 바꿔도 계약·인수 조건·문구가 흔들리지 않는다. "추천"의 그림으로는 별보다 엄지(`thumb_up`)가 더 곧다 — 별은 "내가 표시한 것", 엄지는 "남(운영자)이 권하는 것". 라벨은 좌측 4px 띠·primary 글자로 이미 눈에 띄므로 아이콘 교체로 인지도가 떨어지지 않는다 |
| 추천 라벨의 아이콘을 아예 뺀다 | 가능하지만 라벨이 소제목처럼 보인다. 엄지 하나가 "이건 판정이다"를 말해 준다 — 채택하지 않음 |

- 켜진 별의 색은 **primary** 다. 흔한 노란 별을 쓰지 않는 이유: 이 서비스의 노랑은 "저작권 확인 중" 뱃지의 색(`--badge-unknown-*`)이라 노란 별이 같은 화면에 서면 그 뱃지와 묶여 읽힌다(`09` §5).
- **관리 화면의 추천 별**(곡 목록 `추천 판본 있음`, 판본 목록 추천 뱃지)은 **이번에 바꾸지 않는다** — 05 §6 "관리 화면 변화 없음". 관리 화면에는 즐겨찾기 요소가 없어 같은 화면 충돌은 없다. 다음 관리 화면 라운드에서 `thumb_up` 으로 맞추는 것을 planner 에게 올려 두었다(`09` §6 P1).
- 곡 카드(검색 결과·작곡가 상세·인기곡·같은 작곡가의 다른 곡)에는 별을 **두지 않는다**(05 §1-3, 8-G 5). 이 화면의 "같은 작곡가의 다른 곡" compact 카드도 마찬가지.

| **즐겨찾기 누름 (비로그인 · 세션 풀림)** | 로그인 화면(이유 한 줄 "즐겨찾기…", `09` §3) → 로그인 후 이 곡 상세로 복귀, 버튼 이미 켜짐 + 토스트 `즐겨찾기에 넣었어요` 한 번(§3-6-3). 돌아가기·뒤로 가기면 꺼진 채 복귀, 안내 없음 |

| **정상으로 열림 → 최근 본 곡 기록** | 곡 정보가 그려지면 브라우저의 "최근 본 곡"(구분별, 10곡)에 맨 앞으로 들어간다 — **화면 변화·안내 없음**(05 §4-1). 404·불러오기 실패·숨김 곡은 기록하지 않는다(8-E 9). 저장이 막힌 환경이면 조용히 건너뛴다. 저장 수단은 senior-dev(05 §11 ⑥) |
