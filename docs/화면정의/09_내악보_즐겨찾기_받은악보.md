## 1-1. 즐겨찾기 탭

### 1-1-1. 항목 = 곡 카드 + 해제 열

| 요소 | 규칙 | 토큰 |
|---|---|---|
| 해제 열 | 카드 오른쪽, 폭 `--touch-target`(44px), 항목 전체 높이. 왼쪽 `1px solid --color-border` 로 카드와 **눈에 보이게 갈라 둔다**. 카드 링크의 hover 배경(`--color-surface-muted`)은 이 열까지 번지지 않는다 — 어디까지가 링크인지 보인다 | `--color-border` |
| 해제 버튼 | **채운 별 `star`** 24px(`--icon-size-lg`) `--color-primary`, 44×44 아이콘 버튼. **`aria-label="즐겨찾기 해제"`**, 데스크톱 `title="즐겨찾기 해제"`. 화면에 글자는 없다 — qa 는 접근성 이름 "즐겨찾기 해제"로 찾는다(8-C 4) | `--color-primary` |
| hover / 포커스 | 배경 `--color-surface-muted` 원(`--radius-full`). 포커스 링 00 §5 | — |

### 1-1-2. 해제 토스트 — "되돌리기"

```
┌─────────────────────────────────────────┐
```

| 항목 | 값 |
|---|---|
| 문구 | `즐겨찾기에서 뺐어요` — 곡 제목을 넣지 않는다(제목이 길면 두 줄이 되고, 방금 누른 사람은 어느 곡인지 안다). 아이콘 없음(성공도 실패도 아닌 중립 알림) |
| 되돌리기 버튼 | 오른쪽 텍스트 버튼 `되돌리기`. 글자 `--color-primary-light`(어두운 바탕 위라 `--color-primary` 는 대비가 모자란다) `--font-weight-medium`, 높이 `--touch-target`, 좌우 padding `--space-3` |
| 지속 | **5초**(기본 3초보다 길다 — 누를 결정을 하는 시간). 수동 닫기 `close` 도 있다 |
| 되돌리기를 누르면 | 토스트 즉시 사라짐 → 항목이 **원래 자리**로 돌아오고 탭 숫자 +1. 별도 토스트 없음(항목이 돌아오는 것이 피드백) |
| 되돌릴 수 있는 것 | **마지막 해제 하나뿐.** 토스트가 떠 있는 동안 다른 항목을 해제하면 토스트가 새 것으로 바뀌고(00 §3-11 "마지막 것으로 바꾼다") 앞의 해제는 그대로 확정된다. 여러 개를 쌓아 두지 않는다 |
| 해제 자체가 실패 (네트워크·서버) | 항목이 **제자리로 돌아오고** 탭 숫자 복구, 토스트 **실패** `즐겨찾기를 저장하지 못했어요. 다시 시도해 주세요`(`error` 아이콘). 되돌리기 토스트는 그 전에 내려간다 |
| 되돌리기가 실패 | 항목은 돌아오지 않는다(다시 넣기가 안 된 것). 같은 실패 토스트. 사용자는 곡 상세에서 다시 넣을 수 있다 |
| 화면을 떠나면 | 토스트는 남아 있어도 된다(body 에 붙는 기존 구현). 되돌리기를 눌렀는데 이미 다른 화면이면 — 서버에는 다시 넣고, 화면 갱신은 없다(내 악보로 돌아오면 있다) |

## 1-2. 받은 악보 탭

### 1-2-1. 항목 = 곡 카드 + 받기 영역

| 요소 | 규칙 | 토큰 |
|---|---|---|
| 받기 영역 | 카드 링크 **밖**. 모바일: 카드 아래, 위쪽 `1px dashed --color-border` 로 가름, padding `--space-3 --space-4`. 데스크톱: 카드 오른쪽 열 폭 280px, 왼쪽 `1px solid --color-border`, 세로 가운데 정렬 아님(위에서부터) | — |
| 받은 날짜 | `{날짜} 받음` — **오늘 → `오늘 받음`**, 어제 → `어제 받음`, 같은 해 → `9월 12일 받음`, 다른 해 → `2025년 9월 12일 받음`. 사용자 지역 시각. 시·분은 쓰지 않는다(선반이지 영수증이 아니다, 05 §3-2). **한 곡 한 줄이므로 날짜는 가장 최근 것** | `--font-size-sm` `--color-text-muted` |

| 성공 후 | **그 자리에서** 날짜가 `오늘 받음` 으로 바뀐다. 순서는 다시 불러올 때(새로고침·탭 이동) 최근 받은 순으로 반영 — 보고 있는 목록을 즉석에서 재정렬하지 않는다 | — |

### 1-2-2. "다시 받기" 3상태 (05 §3-3 표를 화면으로)

| 그때 받은 판본의 지금 상태 | 받기 영역에 보이는 것 | 버튼/링크가 하는 일 |
|---|---|---|
| **① 그대로 받을 수 있음** (판본 있음 · 파일 있음 · 자유 이용 가능 · 지금 추천 판본과 같음) | 날짜 / `받은 판본: …` / **`⬇ 다시 받기`** | 그 판본 PDF 클릭 1번. 날짜 → `오늘 받음` |
| **② 받을 수 있지만 지금 추천은 다름** | 날짜 / `받은 판본: …` / **`⬇ 다시 받기`** / 그 아래 한 줄 **`지금 추천 판본은 이것과 달라요 — 곡 보기`** (`info` 16px `--color-info`, 본문 `--font-size-sm` `--color-text-secondary`, `곡 보기` 는 `.btn.btn-text` `--font-size-sm`) | 다시 받기 = **그때 판본**(바꿔치기하지 않는다). `곡 보기` → 곡 상세(거기서 지금 추천을 본다). InlineAlert 상자로 만들지 않는다 — 항목마다 상자가 붙으면 목록이 경고판이 된다. 한 줄 텍스트 + 작은 아이콘 |
| **③ 받을 수 없음** (판본 삭제 · 파일 없어짐 · 판정이 "이용 제한"/"확인 중"으로 바뀜) | 날짜 / `받은 판본: …`(알 수 있는 만큼, 없으면 줄 생략) / **`그때 받은 악보는 지금 받을 수 없어요`** (`block` 16px `--color-text-muted`, 글자 `--font-size-sm` `--color-text-secondary`) / 그 아래 **③-a** 지금 추천 판본이 바로 받기 가능하면 `지금 추천 판본: {종류} · {범위} · {쪽수}쪽 · {크기}` 한 줄 + **`⬇ 지금 추천 판본 받기`**(`.btn.btn-primary`) / **③-b** 아니면 **`곡 보기`**(`.btn.btn-outline`, 모바일 폭 100%) | ③-a: 추천 판본 PDF 클릭 1번. 성공하면 이 항목은 **그 자리에서 ① 형태로** 바뀐다(받은 판본 = 방금 받은 추천 판본, `오늘 받음`). ③-b: 곡 상세(뱃지·IMSLP 링크는 거기 있다). **이유를 갈라 말하지 않는다**("삭제됐어요"/"제한이에요" 없음 — 05 §3-3). "이용 제한" 판본의 PDF 는 어느 경로로도 내려오지 않는다(8-D 8) |

- 한 항목에 **버튼은 최대 하나**(다시 받기 / 지금 추천 판본 받기 / 곡 보기 중 하나). 상태 ②의 `곡 보기` 는 버튼이 아니라 한 줄 끝의 텍스트 링크라 위계가 겹치지 않는다.
- 상태 ③에서 `받은 판본:` 줄을 남기는 이유: "무엇을 못 받는가"가 보여야 "지금 추천 판본 받기"가 대체라는 것을 안다. 판본이 **삭제**돼 정보가 남지 않았으면 줄을 생략한다(senior-dev — 남길 수 있으면 남긴다, §6 S4).
- **대조 확인(2026-09-20)** — API 명세서 §10-3·§2-4 와 이 3상태 표가 어긋나지 않는지 확인함: 서버 `redownloadState` 세 값(`AVAILABLE`/`RECOMMENDATION_CHANGED`/`UNAVAILABLE`)이 위 ①/②/③ 과 1:1 로 대응하고, ③ 안의 `redownloadUrl`·`alternativeEdition` 유무가 ③-a/③-b 분기와 그대로 맞는다. 판본이 삭제되면 상태 판정용 `received` 는 `null`(→ ③으로 떨어짐)이지만, 표시용 `EditionBriefDTO.id` 만 `null` 이고 `kind`·`scope`·`movementNumber`·`pageCount`·`fileSize` 는 스냅샷으로 남을 수 있다 — 그래서 ③에서도 "알 수 있는 만큼" `받은 판본:` 줄이 남는다는 이 표의 문구가 정확히 맞는다. **어긋난 곳 없음.**

## 1-4. 왜 이런 형태인가

### (a) 탭 — 밑줄형 링크, 세그먼트 아님 (D4)

이 서비스에서 "고르는 것"의 문법은 `08` §1-3 에 세 가지로 정리돼 있다: **밑줄형 = 주소가 바뀌는 화면 이동**(구분 바), **pill 세그먼트 = 제자리 재조회**(검색 기준), **낱개 pill = 필터**. 내 악보의 두 탭은 각각 **자기 주소가 있고 뒤로 가기로 되돌아가는 이동**(05 §2-1 3, 8-F 3)이므로 밑줄형이 맞다. 세그먼트로 만들면 "같은 목록을 다른 기준으로 다시 조회한다"로 읽힌다.

구분 바와 겹쳐 보이지 않게 하는 것: ① 구분 바는 **헤더에 붙은 전폭 띠**, 본문 탭은 **h1 아래 본문 안**(좌우 여백 안쪽) ② 본문 탭에는 **숫자 `(N)`** 이 붙는다 ③ 둘 사이에 h1 `내 악보` 가 선다. 마크업은 구분 바와 같은 규칙(`<nav aria-label="내 악보">` + `<a href>` + `aria-current`, `role="tab"` 금지 — 08 §1-2).

### (b) 해제 버튼 — 링크 밖 44px 열의 채운 별 (D5)

- **오터치를 막는 것은 문구가 아니라 경계다.** 카드 전체가 링크라(00 §3-2) 그 위에 버튼을 얹으면 모바일에서 "상세로 가려다 해제"가 난다(05 §1-3 이 걱정한 바로 그것). 해제 버튼을 `<a>` **밖의 별도 열**에 두고 세로선으로 가르면, 링크 영역과 버튼 영역이 물리적으로 겹치지 않는다. 카드 hover 배경이 이 열에 번지지 않게 해 "여기는 링크가 아니다"를 눈으로도 보인다.
- **채운 별 = 곡 상세의 "즐겨찾기됨"과 같은 그림.** 곡 상세에서 채운 별을 눌러 끄는 동작과 여기서 채운 별을 눌러 빼는 동작이 **같은 손짓**이다. 즐겨찾기 목록의 항목마다 채운 별이 있는 것은 "이 목록은 별을 켠 곡들"이라는 뜻과도 맞는다.
- **글자를 반복하지 않는 이유**: 20줄마다 `즐겨찾기 해제` 6자가 서면 목록이 시끄럽다(05 §1-3 이 카드에 별을 안 두는 이유와 같은 논리). 실수는 되돌리기 토스트가 받는다. 접근성 이름은 `aria-label`/`title` 로 준다(00 §5).
- 검토하고 버린 안: 카드 아래 줄에 텍스트 링크 `즐겨찾기 해제`(항목 높이가 한 줄씩 늘고 링크와 세로로 붙어 오터치가 남는다) / 길게 누르기·스와이프(발견되지 않고 데스크톱에 없다).

### (c) "다시 받기"의 위계 (D7·D8)

- 곡 상세의 `PDF 받기` 는 화면에 하나뿐인 주인공이라 `btn-lg`(52px)다. 받은 악보에서는 항목마다 버튼이 있으므로 **판본 행(00 §3-6)의 "PDF 받기"와 같은 급** — `.btn.btn-primary` 보통 크기. 20개가 있어도 primary 여야 하는 이유: 이 탭에 온 사람의 목적이 그 버튼이고, outline 으로 낮추면 "곡 보기"(상태 ③-b outline)와 급이 같아져 "받을 수 있는 항목"과 "못 받는 항목"이 한눈에 갈리지 않는다.
- 3상태가 **버튼 하나·문장 하나**로 구별된다: ① 버튼만 / ② 버튼 + 한 줄 / ③ 문장 + (대체 버튼 | 링크). 상태 ②를 InlineAlert 상자로 만들지 않은 이유는 표에 적었다.
- `받은 판본:` 줄은 세 상태 모두에 있다. "누르기 전에 무엇을 받는지 안다"는 요구는 이 줄이 답한다.

# 3. 로그인 화면 — "이유 한 줄" 2종 (05 §1-2 1 · §2-1 5)

> 로그인 화면(`/login?redirect=`)은 보일러플레이트 잔재이고 이번에 **정비하지 않는다**(05 §0-3 제외 · 사용자 별도 작업 ④). 바꾸는 것은 **부제 한 줄**뿐이다.

```
┌──────────────────────────────┐
│         [로고 아이콘]          │
│           로그인              │   h1 (기존)
│  ☆ 즐겨찾기는 로그인하면 쓸 수 있어요 │   ← 이유 한 줄 — 부제 자리(기존 "서비스에 로그인하세요")를 대체
│  ┌──────────────────────────┐│
│  │ 아이디                    ││   (이하 기존 그대로: 아이디·비밀번호·로그인·카카오·구글·회원가입)
│  …                           │
│  이전 페이지로 돌아가기          │   (기존) → 곡 상세로. 즐겨찾기는 안 된다(8-B 6)
└──────────────────────────────┘
```

| 어디서 왔나 | 이유 한 줄 | 앞 아이콘 (16px, `--color-primary`) | 로그인 후 |
|---|---|---|---|
| 곡 상세 즐겨찾기 버튼(비로그인·세션 풀림) | `즐겨찾기는 로그인하면 쓸 수 있어요` | `star_border` — 방금 누른 버튼과 같은 그림 | **그 곡 상세**로 복귀 + 즐겨찾기 **완성** + 토스트(`03` §3-6-3) |
| 내 악보 주소 직접 진입(비로그인·세션 풀림) | `내 악보는 로그인하면 볼 수 있어요` | `library_music` — 헤더 메뉴와 같은 그림 | **들어오려던 탭**으로 복귀 |
| 그 밖(헤더 "로그인", 관리 딥링크 등) | (없음) — 기존 부제 `서비스에 로그인하세요` 그대로 | — | 기존 복귀 동작 |

- 자리: 기존 `.logo-subtitle` 자리. 글자 `--font-size-md` `--color-text-secondary`(부제보다 한 단계 진하게 — 읽어야 하는 줄이다), 가운데, 아이콘과 글자 사이 `--space-1`.
- **배너·InlineAlert 로 만들지 않는다.** 05 §8 충돌 3 이 좁힌 "로그인 권유는 로그인 화면 안의 한 줄뿐"(8-G 2)에서 "한 줄"을 문자 그대로 지킨다.
- 이유는 화면 전용 쿼리 **`reason`**, 값 **`favorite`**(즐겨찾기) / **`library`**(내 악보)로 들고 온다(**확정** — API 명세서 §10-4, §6 S2 닫힘). 화면은 "이유 값이 즐겨찾기 / 내 악보 / 없음" 세 갈래만 안다. 알 수 없는 값·값 없음은 "없음"과 같다(오류 아님).
- `이전 페이지로 돌아가기` 와 브라우저 뒤로 가기: 곡 상세로 돌아가되 **즐겨찾기는 되지 않고 안내도 없다**(8-B 6). 화면 쪽 변화 없음.
- 회원가입을 거치면 돌아갈 주소가 끊기는 문제(05 §10 8-4)는 ④ 작업 몫 — 이 문서는 건드리지 않는다.
- 잔재 메모(이번 범위 밖, 기록만): 로고 아이콘 `toys`, 부제 `서비스에 로그인하세요`, 탭 제목은 그대로 `로그인 — 쉬운악보`.
