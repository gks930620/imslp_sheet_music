### 2-0. 악기 구분 바 (2026-09-10 추가)

헤더 바로 아래 전폭 띠. `피아노 / 바이올린(준비 중) / 오케스트라(준비 중)` **밑줄형 탭**이며 **필터가 아니라 화면 이동**이다(주소가 바뀌고 히스토리에 남는다).

- 전체 정의·근거·모바일 배치·상태: **`08_악기구분_탭_준비중안내.md` §1**

- 보이는 화면: 홈 · 검색 결과 · 곡 상세 · 작곡가 목록/상세 · 준비 중 안내 · 찾을 수 없는 페이지(선택 표시 없음)
- 안 보이는 화면: 관리 전체(`/admin**`) · 로그인 · 범위 밖 유지 화면(마이페이지·커뮤니티·채팅)

### 2-4. 찾을 수 없는 페이지 (기존 `NotFoundPage` 수정)

```
┌──────────────────────────────────────┐
│  피아노 │ 바이올린 준비중 │ 오케스트라 준비중 │  ← 구분 바: 보이되 **어느 탭도 선택 표시 없음**
├──────────────────────────────────────┤
│         [search_off 64px]            │
│   찾을 수 없는 페이지예요               │
│   주소가 틀렸거나, 내려간 곡이거나,      │
│   아직 열지 않은 악기 구분이에요         │
│   [🔍 곡 이름, 작곡가, 작품번호로 찾기 ] [검색] │
│          [홈으로]                     │
└──────────────────────────────────────┘
```
- 제목 "찾을 수 없는 페이지예요" (기존 "페이지를 찾을 수 없습니다"에서 교체). **보조 문구는 어디서 온 404인가에 따라 두 갈래다**(아래 표). 기본(공통) 갈래는 **"주소가 틀렸거나, 내려간 곡이거나, 아직 열지 않은 악기 구분이에요"** (2026-09-10 교체 — 없는 구분 이름 주소도 이 화면으로 오기 때문).
- **보조 문구 두 갈래 (2026-09-11 명문화 — senior-dev 코드리뷰 정합)**: 코드가 곡 상세만 짧은 문구로 override 하고 테스트가 잠갔다. 그 근거를 여기 한곳에 못 박는다.

  | 404가 난 곳 | 보조 문구 | 왜 |
  |---|---|---|
  | **곡 상세**(`WorkDetailPage` — 없는/숨김 곡 id: `/piano/works/:id`·`/works/:id`) | **`주소가 틀렸거나 내려간 곡이에요`** (악기 구분 절 없음) | 곡 상세는 **이미 열린 구분(피아노) 안**에서 곡 id 로만 도달한다. "아직 열지 않은 악기 구분"은 이 자리에서 해당이 없어 오히려 어색하다. `WorkDetailPage` 가 이 짧은 문구로 override 하고 `WorkDetailPage.test.jsx` 가 잠근다 |
  | **그 밖 전부**(공통 `NotFoundPage` — 없는 구분 이름 `/cello`, 준비 중 구분 하위 경로 `/violin/search`, 없는 작곡가 `04` §상태표, catch-all `*`) | 위 **기본 문구** (구분 절 포함) | 없는 구분 이름 주소가 이 화면으로 오므로 "아직 열지 않은 악기 구분" 절이 필요하다 |

- 검색창 컴포넌트 **large** 변형 추가. 이 검색은 피아노 구분의 결과 `/piano/search?q=` 로 간다(`from` 을 붙이지 않는다 — 08 §3). "홈으로"는 기존 `.btn.btn-primary`, `/piano` 으로.
- 없는 곡·작곡가·숨김 곡 주소(404)**와 없는 구분 이름 주소**가 모두 이 화면(같은 레이아웃·아이콘·검색창·"홈으로"). **다른 것은 보조 문구 한 줄뿐**(위 두 갈래) — 그 밖의 화면 구조로 둘을 구별해 그리지 않는다.
- **주소에 들어 있던 구분 문자열을 화면에 되뱉지 않는다** (`'첼로'는 없는 구분이에요` 같은 문구를 만들지 않는다). 상세: `08_악기구분_탭_준비중안내.md` §3.
- 브라우저 탭 제목 `찾을 수 없는 페이지 — 쉬운악보` (구분 이름 없음, §4-1).

## 3. 공통 컴포넌트

> 클래스 이름은 제안이다. frontend-dev 가 바꿔도 되지만 **한 컴포넌트 = 한 파일**로 만들어 화면마다 재사용한다. 색·크기는 전부 토큰.

### 3-1. 검색창 `SearchBar`

```
large  (홈, 검색 결과 상단, 찾을 수 없음)
┌──────────────────────────────────────────────────────┬────────┐
│ 🔍  곡 이름, 작곡가, 작품번호로 찾기 — 예: 월광, 쇼팽 녹턴, K.545 │  검색  │
└──────────────────────────────────────────────────────┴────────┘
compact (헤더)
┌──────────────────────────────┐
│ 🔍  곡 이름, 작곡가, 작품번호   │      (버튼 없음, Enter 만)
└──────────────────────────────┘
```

| 항목 | 값 |
|---|---|
| 자리 문구 large | **검색 기준에 따라 바뀐다** (§3-16, 08 §4-3). 전체: `곡 이름, 작곡가, 작품번호로 찾기 — 예: 월광, 쇼팽 녹턴, K.545` / 곡명: `곡 이름으로 찾기 — 예: 월광, 엘리제를 위하여, Op.27 No.2` / 작곡가: `작곡가 이름으로 찾기 — 예: 쇼팽, 베토벤, Chopin`. 모바일 360px 에서 잘리면 짧은 버전(08 §4-3 표) |
| 자리 문구 compact | `곡 이름, 작곡가, 작품번호` — **바뀌지 않는다** (헤더 검색은 항상 "전체") |

| 글자 | large `--font-size-base` / compact `--font-size-md` |
| 경계 | `1px solid --color-border`, 포커스 시 `--color-primary` 2px, 반경 `--radius-md` |
| 아이콘 | `search` (`--color-text-muted`), 입력 중엔 오른쪽에 `close` 지우기 버튼 |
| 버튼 | large 만 "검색" (`.btn.btn-primary`, 높이 검색창과 동일). 모바일에선 버튼을 입력칸 안 오른쪽에 아이콘 버튼(`search`)으로 접어 한 줄 유지 |

### 3-2. 곡 카드 `WorkCard` (목록 항목)

검색 결과·작곡가 상세·홈 인기곡·같은 작곡가의 다른 곡에 공통. 전체가 링크(곡 상세).

```
┌──────────────────────────────────────────────────────────────┐
│ ┌────┐  월광 소나타                          [준비 중]         │  ← 한국어 제목 굵게 / 상태 뱃지(해당 시)
│ │ A4 │  Piano Sonata No.14                                     │  ← 원어 제목
│ │thumb│ 베토벤 (Beethoven, Ludwig van) · Op.27 No.2            │  ← 작곡가(원어) · 작품번호
│ └────┘  [중급]  12쪽                                          │  ← 난이도 칩 · 추천 판본 쪽수
│         '월광'으로 찾음                                       │  ← 별칭 일치 줄 (검색 결과에서만)
└──────────────────────────────────────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 축소 이미지 | 추천 판본 첫 페이지. 폭 `--thumb-width-list`(56px, 데스크톱 72px), 비율 `--thumb-aspect`. **없으면 자리 자체를 두되** `--color-surface-placeholder` 배경에 `music_note` 아이콘(`--color-text-disabled`) — 목록에서는 "미리보기 준비 중" 글자를 넣지 않는다(좁음) |
| 제목 | `--font-size-base` `--font-weight-medium` `--color-text`. 한국어 제목이 없으면(관리자 미입력) 원어 제목을 이 자리에 쓰고 원어 줄은 생략 |
| 원어 제목 | `--font-size-sm` `--color-text-muted` |
| 작곡가 | `--font-size-sm` `--color-text-secondary`. 작곡가 상세 화면에서는 이 줄에서 작곡가를 빼고 작품번호만 |
| 작품번호 | `--font-family-mono` 는 쓰지 않는다(카드에선 본문체). 여러 개면 " · " 로 이어 붙임 |
| 난이도 | 난이도 칩(§3-3). 미정이면 "난이도 미정" 칩 |
| 쪽수 | "12쪽". 추천 판본 없으면 표시 안 함 |
| 상태 뱃지 | 준비 중 / 한국에서 이용 제한 / 저작권 확인 중 중 하나. 바로 받기 가능이면 **없음**. 제목 줄 오른쪽 (모바일에선 제목 아래 줄로 내려감) |
| 별칭 일치 줄 | `'월광'으로 찾음` — 검색어가 **별칭**에 걸렸을 때만. `--font-size-xs` `--color-primary`. 대표 제목·작곡가·작품번호로 걸린 건 표시 안 함 |
| 컨테이너 | 기존 `.post-list` / `.post-item` 패턴(흰 카드 안에 행, 경계선 `--color-border`, hover `--color-surface-muted`) 재사용. 한 항목 padding `--space-4`(모바일) / `--space-5` |
| 터치 | 항목 전체 높이 ≥ `--touch-target` |

**compact 변형** (홈 인기곡·같은 작곡가의 다른 곡): 축소 이미지 없이 `순위 숫자 · 한국어 제목 · 작곡가 · 난이도 칩` 한 줄. 상태 뱃지는 표시.

### 4-1. 브라우저 탭 제목 (2026-09-10 추가 — 기획 04 §3-7, §9 8-4)

형식 **`{화면 고유 부분} — 쉬운악보 {구분}`**. 구분이 걸리는 화면에만 뒤에 구분 이름이 붙는다.

| 화면 | `<title>` |
|---|---|
| 홈 | `쉬운악보 — 피아노` |
| 검색 결과 | `'녹턴' 검색 결과 — 쉬운악보 피아노` |
| 곡 상세 | `월광 소나타 — 쉬운악보 피아노` |
| 작곡가 목록 / 상세 | `작곡가 — 쉬운악보 피아노` / `쇼팽 — 쉬운악보 피아노` |

| 찾을 수 없음 | `찾을 수 없는 페이지 — 쉬운악보` |
| 관리 화면 / 로그인 | `관리 — 쉬운악보` / `로그인 — 쉬운악보` |

- `index.html` 기본 `<title>` 은 `쉬운악보` 그대로. 화면마다 갱신한다. **갱신 수단 확정(2026-09-10 senior-dev — `03_기술결정.md` §21-7)**: 라이브러리(`react-helmet` 류) 없이 **`useDocumentTitle(title)` 훅** 하나 — `document.title` 대입, 언마운트 시 기본값 복귀 없음(다음 화면이 곧바로 자기 제목을 쓴다). 화면 컴포넌트가 위 표의 문자열로 호출한다. 곡 상세는 응답 `section` 으로 자기 교정한 뒤 그 구분 이름으로 쓴다(03 상태표). 계약 검증 `App.documentTitle.test.jsx`.
- **푸터에는 구분을 넣지 않는다** — 푸터 3줄(§2-2)은 출처·저작권 고지 자리다. 근거: `08` §5.

## 5. 접근성 최소 기준

- 모든 아이콘 전용 버튼에 `aria-label` (검색, 닫기, 메뉴, 지우기, 페이지 이동).
- 뱃지·칩은 색만으로 구분하지 않는다 — 문구·아이콘이 항상 같이 있다.
- 포커스 링: 키보드 포커스 시 `outline: 2px solid --color-primary; outline-offset: 2px`. 마우스 클릭 시엔 숨김(`:focus-visible`).
- 본문 대비: `--color-text-muted`(#757575) 이하로 더 흐린 글자를 본문에 쓰지 않는다.
- 라이트박스·모달은 열릴 때 포커스를 안으로, 닫히면 원래 요소로.

**화면 안의 링크 규칙 (프론트 계약 — API 명세서 §0-5, 03_기술결정 §21-6)**
- 구분 안의 화면(홈·검색·곡 상세·작곡가)으로 가는 링크는 **전부 `/{현재 구분}/…`** 로 만든다. 현재 구분의 유일한 근원은 **주소 첫 세그먼트**(`useSection()` 훅) — 하위 컴포넌트에 prop 으로 내려보내지 않고, 쿠키·세션·`localStorage` 에 저장하지 않는다(같은 주소는 누구에게나 같은 화면). 검색 기준 `in` 도 같은 이유로 저장하지 않는다.
- 현재 구분이 없거나(404·관리·로그인·범위 밖) 준비 중이면 **기본 구분 `piano`**. 1차에는 열린 구분이 피아노뿐이므로 모든 링크가 `/piano/…` 다.
- **예외 하나**: 관리 화면 → 사용자 곡 화면 링크는 `/works/:id`(구분 없음). 관리자는 곡의 구분을 모르고 알 필요도 없다(관리 응답에 `section` 이 없다, §0-7). 이 링크를 `/piano/works/:id` 로 "고치지" 않는다.
- 주소 갱신 방식: 구분 탭·기준 세그먼트·필터·페이지·재검색은 **push**(뒤로 가기로 되돌아간다). 옛 주소 리다이렉트와 곡 상세 자기 교정만 **replace**.

쿼리 값(확정, API 쿼리 이름과 동일 — `02_API_명세서.md` §3-1·§3-8·§4-6):
- `in` — **검색 기준**(2026-09-10 확정). 값 `TITLE` | `COMPOSER`(주소에는 **대문자**로 쓴다 — 계약 §3-1 의 enum 과 같은 표기로 통일, 서버·프론트 모두 대소문자 무시). **전체는 생략** — `/piano/search?q=월광` 이 기준 없던 시절 주소와 같은 모양이라 옛 링크가 그대로 열린다(인수 조건 8-F 3). 알 수 없는 값(`in=xyz`, `in=`)은 서버가 `ALL` 로 열어 **200** 을 주고 응답 `in` 이 확정값이다 — 세그먼트는 응답의 `in` 으로 그린다(08 §4-4)
- `from` — **화면 전용**(검색 결과만). `violin` | `orchestra`. 준비 중 화면의 헤더 검색이 붙여 보낸다. 결과 화면의 어떤 주소 갱신에도 이어 붙이지 않는다(한 번만 보이는 안내 줄 — 08 §2-4). 알 수 없는 값이면 안내 줄 없음, 오류 아님. API 로 넘기지 않는다
- `section` — **화면 주소에는 쓰지 않는다**(경로 첫 세그먼트가 그 역할). API 호출에만 `section=PIANO` 처럼 붙인다(생략 시 서버 기본 `PIANO`). 정의되지 않은 값은 API 가 **400** 이지만, 없는 구분 이름은 라우터가 먼저 404 화면으로 보내므로 화면에서 그 요청은 나가지 않는다 — `in` 의 관용(200)과 일부러 다르다: `in` 은 "잘못 붙은 쿼리 한 조각"이고 `section` 은 "어느 세계를 보고 있는가"라 조용히 다른 세계를 보여주면 안 된다(§0-7)
- `level` — 사용자 화면은 쉼표 구분 복수(`level=ELEMENTARY,INTERMEDIATE`), 관리 곡 목록은 단일(`BEGINNER|ELEMENTARY|INTERMEDIATE|ADVANCED|NONE`, NONE=미정)
- `pages` — `LE10 | 11_20 | GE21` 단일
- `downloadable` — `true` 일 때만 의미 있음
- `sort`(작곡가 상세) — `downloads`(기본) | `opus`
- `page` — 0-base
- `/admin/works?q=&status=&composerId=&level=&page=` — `status=READY|PREPARING|RESTRICTED|UNKNOWN|NEEDS_WORK|HIDDEN`
- `/admin/copyright?q=&composerId=&page=`
