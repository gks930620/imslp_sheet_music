# 제품 비전 — IMSLP 문제 정의와 핵심 컨셉

> 작성일: 2026-09-05
> 작성: 메인 세션(사용자와의 대화에서 합의한 내용 정리). 이후 기획서(`01_*`)는 product-planner 가 이 문서를 기준으로 쓴다.
> 서비스 가칭: **쉬운악보** (사용자가 이름을 정하면 교체)

## 1. 한 줄 정의

**"한국어로 검색 → 곡 하나 → 추천 악보 1개 → 바로 PDF."**
IMSLP(퍼블릭 도메인 악보 아카이브) 위에 얹는 **한국어 검색 + 큐레이션 레이어**다. IMSLP 를 번역하는 게 아니라, IMSLP 가 아카이브라서 못 해주는 "찾아서 바로 받기"를 해준다.

## 2. 누구를 위한 것인가

- **1차(지금)**: 피아노를 배우는 한국인 (취미·입시·레슨생). 유명곡 악보를 빨리 받아 연습하고 싶다.
- **이후**: 성악·합창·실내악·오케스트라 파트보가 필요한 사람 (범위 확장 시 별도 기획).

## 3. IMSLP 가 불편한 이유 (문제 정의)

| # | 문제 | 사용자가 겪는 상황 |
|---|---|---|
| 1 | **제목이 원어 정식 명칭 기준** | "월광 소나타"로는 못 찾는다. `Piano Sonata No.14, Op.27 No.2` 로 쳐야 한다. 작곡가도 `Tchaikovsky, Pyotr` 처럼 성-이름 순 로마자. 한글 검색은 아예 안 된다. |
| 2 | **한 곡에 판본이 너무 많다** | 곡 페이지 하나에 파일이 10~50개. 1880년대 스캔, 편집자별 판본, 전체보/파트보/편곡본이 섞여 있고 "이걸 받으세요"가 없다. |
| 3 | **용어를 모르면 못 고른다** | Complete Score / Parts / Vocal Score / Arrangements and Transcriptions 의 뜻을 초보자는 모른다. |
| 4 | **미리보기가 없다** | 받기 전엔 스캔 화질, 페이지 수, 손글씨 판본 여부를 모른다. 여러 개 받아보고 버린다. |
| 5 | **다운로드 절차가 길다** | 클릭 → 저작권 면책 페이지 → 대기 → 광고 → PDF. 모바일에선 더 심하다. |
| 6 | **저작권 표기가 한국 기준이 아니다** | 서버가 캐나다라 "캐나다 PD / EU·US 비PD" 식으로 뜬다. 한국(사후 70년)에서 써도 되는지 알려주지 않는다. |
| 7 | **원하는 단위로 못 찾는다** | "피아노, 중급, 5쪽 이내" 필터가 없다. 소나타 2악장만 원해도 전곡 PDF 뿐이다. |
| 8 | **위키 구조** | 작곡가 → 알파벳 카테고리 → 곡 → 판본으로 타고 내려가야 한다. 반응형이 아니다. |

## 4. 핵심 컨셉 (해결 방향)

| 문제 | 해결 |
|---|---|
| 1 이름 | **한국어 별칭 사전** — 곡마다 한국 통용 제목·별명·작곡가 한글 표기·작품번호(Op., BWV, K., D., Hob.)를 붙여 어떤 말로 쳐도 같은 곡으로 떨어지게 한다. 초기엔 유명 피아노곡을 직접 정리, 이후 사용자 제안으로 확장. **이 사전이 서비스의 진짜 자산이다.** |
| 2·3 판본 | **곡당 추천 판본 1개** — 화질 좋고 널리 쓰이는 판본을 기본으로 보여주고 나머지는 "다른 판본 보기"로 접는다. 판본 종류는 한국어로 풀어 쓴다(전체 악보 / 파트보 / 편곡). |
| 4 미리보기 | **첫 페이지 이미지 + 쪽수 + 파일 크기**를 받기 전에 보여준다. |
| 5 절차 | **우리 서버에서 바로 PDF** — 한 번의 클릭으로 다운로드. 대기·면책 페이지 없음. |
| 6 저작권 | **한국 기준 저작권 뱃지** — "한국에서 자유 이용 가능" 여부를 한 줄로. |
| 7 필터 | **난이도·쪽수·편성 필터** — 1차는 피아노 독주만이므로 난이도·쪽수 위주. |
| 8 구조 | **검색창 하나** — 홈은 검색창과 인기곡·작곡가 바로가기뿐. |

## 5. 결정 사항 (2026-09-05 사용자 확정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 1차 범위 | **피아노 독주곡만** | 곡 수 대비 수요가 가장 크고 판본 문제가 제일 심하다. 다른 편성은 이후 확장. |
| 파일 제공 방식 | **우리 서버에서 직접 내려준다** (IMSLP 링크로 넘기지 않음) | "바로 받기"가 핵심 가치. 링크 방식은 IMSLP 대기 페이지를 그대로 겪는다. |
| 파일 확보 방식 | **IMSLP 에서 크롤링해 우리 저장소에 보관** | 로컬 개발 단계는 디스크(`uploads/`), 배포 시 Railway 버킷으로 옮긴다(컨벤션 §5-3). |
| 크롤링 범위 | **큐레이션된 피아노 인기곡 목록 기준**(전체 IMSLP 아님) | 트래픽·저장 용량·저작권 검토를 감당 가능한 규모로. |
| 스택 | 기존 보일러플레이트(Spring Boot + React CSR) 유지 | 로그인·파일·커뮤니티 모듈 재활용. Flutter 앱은 미도입. |

## 6. 리스크와 대응

| 리스크 | 내용 | 대응 |
|---|---|---|
| **IMSLP robots.txt** | `Crawl-delay: 2`, 그리고 `/images/`, `/wiki/File:`, `/wiki/Special:` 은 일반 크롤러에 **Disallow**. 즉 PDF 실파일 경로는 자동 수집을 원치 않는다는 신호다. 작품 페이지(`/wiki/작품명`)와 공개 API(`API.ISCR.php`)는 허용. | ① 메타데이터는 API·작품 페이지로 수집(허용 범위). ② PDF 는 **큐레이션 목록만, 요청 간격 2초 이상, 식별 가능한 User-Agent(연락처 포함)**, 동시 1커넥션, 한 번 받은 파일은 재요청하지 않는다. ③ 규모가 커지면 IMSLP 에 연락해 허가(또는 미러 자격)를 받는다. **이 판단은 사용자 확인 필요** — 문제되면 "메타데이터만 수집 + 사용자가 누르면 그때 1회 대리 다운로드" 방식으로 후퇴한다. |
| **저작권** | IMSLP 파일은 대부분 퍼블릭 도메인이지만 일부는 CC 라이선스(표기 의무)·특정 국가에서만 PD. 한국 기준(저작자 사후 70년, 편집자·편곡자 권리 별도)으로 재판단해야 한다. | 파일마다 IMSLP 저작권 표기를 저장하고, 한국 기준 판정 필드를 둔다. 판정 불가·비PD 는 다운로드 막고 IMSLP 링크만 제공. CC 파일은 출처·라이선스 표기. |
| **출처 표기** | IMSLP 는 자원봉사 아카이브다. 출처 없이 가져다 쓰면 신뢰 문제. | 모든 악보 상세에 "출처: IMSLP (원본 페이지 링크)"와 스캔 제공자·판본 정보를 표기. |
| **저장 용량·비용** | 악보 PDF 는 1~30MB. 1,000곡 × 판본 2개면 수십 GB. | 1차는 200~300곡 × 추천 판본 1개(+대체 1개)로 제한. 버킷 요금은 GB 단위($0.015/GB-월)라 감당 가능. |
| **별칭 사전 품질** | 한국 통용 제목은 정답이 하나가 아니다("엘리제를 위하여" / "엘리제" / "Für Elise"). | 곡 하나에 별칭 N개 구조. 검색은 부분 일치 + 초성/공백 무시. 사용자 제안 기능은 2차. |
| **난이도 표기** | 공식 기준이 없다. | 1차는 관리자가 직접 입력(입문/초급/중급/고급). 근거 없는 자동 산정은 하지 않는다. |

## 7. 범위 밖 (1차에서 하지 않는 것)

- 피아노 이외 편성(성악·합창·실내악·오케스트라 파트보)

- 앱(Flutter)
- 자동 난이도 판정, OMR(악보 인식)

## 8. 확인된 IMSLP 사실 (2026-09-05 조사)

- **공개 API**: `https://imslp.org/imslpscripts/API.ISCR.php?account=worklist/disclaimer=accepted/sort=id/type=2/start=0/retformat=json` — 작품 목록(페이지당 약 334건). 항목: `id`(제목+작곡가), `parent`, `intvals{composer, worktitle, icatno, pageid}`, `permlink`(작품 페이지 URL). `type=1` 은 인물. **파일 URL 은 포함되지 않는다** — 파일은 작품 페이지에서 얻어야 한다.
- **작품 페이지 구조**: "Sheet Music" 아래 전곡/악장별 섹션, 파일마다 `#파일ID`, PDF 링크, 크기(MB)·쪽수, 편집자, 출판사·연도·플레이트 번호, 저작권 상태, 스캔 제공자, 평점, 다운로드 수. 일반 정보에 작곡 연도·악장·조성·작품번호·장르·별칭(예: Moonlight Sonata).
- **파일 링크 패턴**: `/wiki/Special:ImagefromIndex/{파일ID}` → 면책 페이지 → `/images/{a}/{ab}/{파일명}.pdf`.
- **robots.txt**: `Crawl-delay: 2`. Disallow: `/index.php`, `/wiki/Special:`, `/images/`, `/imglnks/`, `/wiki/File:`, `/wiki/Image:`, `/instruments`, `/works`, `/work/`, `/instrument/`, `/library/`. 사이트맵 제공.
- 이용약관 페이지(`IMSLP:Terms_of_Use`)는 404 — 재배포 규정은 각 파일의 라이선스(PD/CC)와 robots.txt 를 기준으로 판단한다.

## 9. 보충 (2026-09-06)

- §5 "파일 확보 방식"과 §6 "IMSLP robots.txt" 리스크에 대한 실측 조사 결과는 `docs/설계/00_IMSLP_수집_조사.md`, 그에 따른 수집 방식 절충안은 `docs/기획/01_MVP_피아노_기획서.md` §9-1 에 있다.

## 10. 보충 (2026-09-07) — 실데이터가 §3·§4 에 준 충격

1차 수집이 돌면서 다음이 확인됐고, 그대로 두면 **§3 의 문제 2·7 을 우리가 그대로 재현**한다. 개정 내용은 `01_MVP_피아노_기획서.md` §10 에 있다.

| §3 문제 | 실데이터 | 지금 기획의 결과 |
|---|---|---|
| 2 판본이 너무 많다 | 곡 하나에 IMSLP 판본 **70~90개**, 우리 서버에 파일이 있는 건 곡당 **2개**(20곡 수집에 판본 1,792건) | "다른 판본 보기"를 펼치면 68줄이 "파일 없음 · IMSLP에서 보기". → §10-1 로 개정 |
| 7 원하는 단위로 못 찾는다 | 큐레이션 50곡 중 **38곡이 묶음 악보**(곡집·모음곡·다악장). "강아지 왈츠"를 찾은 사람에게 왈츠 3곡짜리 전곡 PDF 를 준다 | 곡 상세 어디에도 "그게 몇 번인지"가 없다(시드에 값이 없다). → §10-3 로 개정, **2차의 첫 과제는 "곡집 → 개별 곡 분리"** |
| 6 저작권 | 수집 판본이 전부 "확인 중"이라 자동 판정을 돌리기 전엔 **바로 받기 가능 곡이 0개** | §4 의 "우리 서버에서 바로 PDF"가 성립하지 않고 링크 모음이 된다. → §10-8(공개 기준)로 개정 |

## 11. 보충 (2026-09-08) — 3차 QA 가 §1·§2 에 되물은 것

동작하는 제품을 시나리오로 시험해 보니, **계약대로 만들었는데도 §1 한 줄 정의와 §2 대상 사용자에 어긋나는 화면**이 4곳 나왔다. 기획 결론은 `01_MVP_피아노_기획서.md` §11 에 있다. 이 문서에 미치는 영향만 적는다.

| §1·§2 와 어긋난 지점 | 결론 |
|---|---|
| **홈 첫 화면**에 한국어 제목 없는 곡·못 받는 곡이 1위로 올라온다 → §1 "한국어로 검색 → 바로 PDF"를 첫 화면에서 부정한다 | 홈 인기곡은 **순위표가 아니라 견본 진열대**로 규정. "바로 받기 가능 + 한국어 제목 있음"만 이 자리에 선다 (`01` §11-3) |
| 추천 판본이 **편곡·2악장만**이어도 사용자는 모른 채 받는다 → §3 문제 7("원하는 단위로 못 찾는다")을 우리가 재현하고, 게다가 **알려주지도 않는다** | 막지 않고 **받기 전·받는 순간·받은 뒤(파일 이름) 세 곳에서 알린다** (`01` §11-2). 근본 해법은 §10-10 의 "곡집 → 개별 곡 분리"(2차 첫 과제)로 그대로 유지 |
| 관리자가 **곡 단위 목표**(공개 기준 35곡)를 갖는데 작업 목록이 판본 단위 사정을 반영하지 않는다 | '보완 필요'는 **곡 단위 작업 목록**으로 확정 (`01` §11-1) |
