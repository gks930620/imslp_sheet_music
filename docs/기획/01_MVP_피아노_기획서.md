## 0. 이 문서의 범위와 용어

### 0-1. 한 줄 정의

**"한국어로 검색 → 곡 하나 → 추천 악보 1개 → 바로 PDF."**

### 0-2. 1차 범위

| 포함 | 제외 (2차 이후) |
|---|---|
| 피아노 독주곡만. **단 2026-09-10 부터 이 문서가 다루는 것은 "피아노 **구분**"이다** — 상단에 바이올린·오케스트라 구분이 "준비 중"으로 함께 보인다(§13, `04_악기구분과_검색기준_기획서.md`) | 다른 편성(성악·합창·실내악·오케스트라)의 **곡·수집·판본**. 구분 탭은 보이되 안내 화면만 열린다 |
| 비로그인 사용자: 검색·곡 상세·작곡가·다운로드 | 즐겨찾기, 별칭 제안, 판본 후기 등 로그인이 필요한 사용자 기능 |
| 관리자(ADMIN): 곡·별칭·난이도·판본·저작권 관리, 수집 운영 | 사용자 회원가입 유도, 마이페이지 확장 |
| 전곡 PDF 1개 단위 제공 | 악장별 분할 PDF (악장 페이지 안내 문구는 제공) |
| 웹(반응형) | Flutter 앱 |

### 0-3. 사용자에게 보이는 용어 (화면 전체에서 통일)

| 용어 | 뜻 | IMSLP 원어 |
|---|---|---|
| **곡** | 작품 하나. 예: 월광 소나타 | Work |
| **판본** | 한 곡에 딸린 PDF 파일 하나. 출판사·편집자·스캔이 다르면 다른 판본 | File / Edition |
| **추천 판본** | 관리자가 곡마다 1개 고른 "이걸 받으세요" 판본 | (없음 — 우리 개념) |
| **전체 악보** | 곡 전체(또는 특정 악장)를 담은 악보 | Complete Score |
| **파트보** | 한 악기 파트만 담은 악보. 피아노 독주에는 거의 없음 (용어만 예비) | Parts |
| **편곡** | 다른 편성에서 피아노로, 또는 피아노에서 다른 편성으로 옮긴 악보 | Arrangements and Transcriptions |
| **포함 범위** | 판본이 전곡을 담는지, 특정 악장만 담는지. 예: "전곡", "2악장만" | (IMSLP 섹션 구분) |
| **묶음 악보** | 여러 곡·여러 악장이 한 PDF 에 들어 있는 곡. 예: 부르크뮐러 25 연습곡, 쇼팽 왈츠 Op.64, 월광 소나타(3악장). 1차 큐레이션 50곡 중 30곡 이상이 여기 해당한다 | (IMSLP 는 곡집도 작품 1개로 둔다) |
| **수록곡 안내** | 묶음 악보 안에 무엇이 몇 번으로 들어 있는지 알려주는 한 줄. 예: "이 악보에는 25곡이 들어 있어요 — 2번 아라베스크 · 15번 발라드 · 25번 귀부인의 승마". **쪽수가 아니라 곡 번호 기준**(쪽수는 판본마다 다르다) | (없음 — 우리 개념) |
| **별칭** | 한 곡을 부르는 모든 이름. 한국 통용명·별명·원어·영어 별칭 | (Alternative Title) |
| **작품번호** | Op. / BWV / K. / D. / Hob. 등 작품 식별 번호 | Opus / Catalogue No. |
| **난이도** | 입문 / 초급 / 중급 / 고급 / 미정 (관리자 직접 입력, 자동 산정 없음) | (없음) |
| **한국 기준 저작권** | 아래 3가지 중 하나. 뱃지로 표시 | (IMSLP 표기는 별도 원문 보관) |

**한국 기준 저작권 뱃지 3종** (판본마다 하나)

| 뱃지 | 뜻 | 사용자가 할 수 있는 것 |
|---|---|---|
| **한국에서 자유 이용 가능** | 관리자가 한국 기준(저작자 사후 70년, 편집자·편곡자 권리 포함)으로 이용 가능하다고 판정 | 우리 서버에서 바로 다운로드 |
| **한국에서 이용 제한** | 한국 기준으로 아직 보호 중이거나 재배포 불가로 판정 | 다운로드 불가. IMSLP 원본 페이지 링크만 |
| **저작권 확인 중** | 관리자 판정 전 (수집 직후 기본값) | 다운로드 불가. IMSLP 원본 페이지 링크만 |

**곡의 준비 상태** (검색 결과·상세에서 사용자에게 보이는 뱃지)

| 상태 | 조건 | 표시 |
|---|---|---|
| **바로 받기 가능** | 추천 판본이 지정되어 있고, 그 판본의 PDF가 우리 서버에 있고, 뱃지가 "자유 이용 가능" | 뱃지 없음(기본), 다운로드 버튼 활성 |
| **준비 중** | 추천 판본이 없거나, 추천 판본의 PDF가 아직 없음(수집 전 / 수집 실패 / 정보만 등록) | "준비 중" 뱃지, IMSLP 링크 제공 |
| **이용 제한** | 추천 판본은 있으나 뱃지가 "이용 제한" 또는 "확인 중" | "한국에서 이용 제한" 또는 "저작권 확인 중" 뱃지, IMSLP 링크 제공 |

## 2. 사용자 흐름 — 일반 사용자 (비로그인)

### F1. 홈

1. 사용자가 서비스 주소로 들어온다 → **홈** 화면. 로그인 요구 없음.
2. 홈에는 다음이 위에서 아래 순서로 보인다.
   - 서비스 이름과 한 줄 설명("한국어로 검색하고 바로 받는 피아노 악보")
   - **검색창 1개** (자리 문구: "곡 이름, 작곡가, 작품번호로 찾기 — 예: 월광, 쇼팽 녹턴, K.545"). 화면이 열리면 검색창에 커서가 가 있다.
   - **인기곡** 10개 — 영역 제목은 **"지금 바로 받을 수 있는 인기곡"** (2026-09-08 개정, §11-3). 각 항목은 한국어 제목 · 작곡가 한글 · 난이도. 누르면 **곡 상세**.
     - **이 자리는 순위표가 아니라 견본 진열대다.** 홈에 처음 온 사람이 묻는 것은 "여기 1등이 뭐냐"가 아니라 "여기 내가 받을 만한 게 있냐"다. 그래서 **자격을 갖춘 곡만** 이 자리에 올라온다.
     - **자격 조건 (둘 다 만족해야 한다)**
       1. 준비 상태가 **"바로 받기 가능"** — 홈 첫 화면에서 "바로 받기"라는 약속이 깨지면 안 된다. 추천 판본이 없거나 판정이 확인 중인 곡은 올라오지 않는다.
       2. **한국어 대표 제목이 있다** — 제목이 원어로만 보이는 항목은 우리가 없애겠다고 한 IMSLP 그 자체다(`00 §3` 문제 1). 한국어 제목 없는 곡이 1위에 오르면 서비스의 존재 이유가 첫 화면에서 부정된다.
     - **정렬**: 누적 다운로드 수 많은 순 → 같으면 **큐레이션 노출 순서**(`03_1차_큐레이션_곡목록.md` 의 곡 번호 1→50. 이 번호는 입문 → 초급 → 중급 → 고급 순으로 매겨져 있다) → 그래도 같으면 한국어 제목 가나다순. **"최근 등록순"(등록 시각 역순)은 쓰지 않는다** — 방금 만든 미완성 곡이 1위가 된다.
     - **모자랄 때 (폴백)**: 자격을 갖춘 곡이 10개 미만이면 **모자란 칸만** 준비 중 곡으로 채우되, 그 곡도 한국어 대표 제목이 있는 곡만 쓰고 "준비 중" 뱃지를 붙인다. 자격 곡이 0개면 인기곡 영역 자체를 표시하지 않는다(작곡가 바로가기와 검색창만 남는다). 빈 채로 자리를 남기지 않는다.
     - 왜 필터를 거는데도 정렬 근거는 다운로드 수 그대로인가: 실제 인기가 쌓이면 그대로 반영돼야 한다. 우리가 손보는 것은 "누가 이 자리에 설 자격이 있는가"이지 "누가 더 인기 있는가"가 아니다.
   - **작곡가 바로가기**: 공개된 곡이 1개 이상 있는 작곡가 중 곡 수가 많은 순 8명 (한글 표기). 누르면 **작곡가 상세**. 옆에 "모든 작곡가 보기" → **작곡가 목록**.
3. 검색창에 글자를 넣고 Enter 또는 검색 버튼 → **검색 결과** 화면으로 이동.
4. 빈 검색어(공백만)로 Enter → 이동하지 않고 검색창 흔들림 등 가벼운 표시만. 오류 문구 없음.

### F2. 검색

1. **검색 결과** 화면 상단에 검색창이 그대로 있고, 입력했던 검색어가 채워져 있다. 검색어를 고쳐 다시 검색할 수 있다.
2. 결과 화면 주소에 검색어가 담겨 있어, 주소를 복사해 다른 사람에게 보내면 같은 결과가 보인다. 브라우저 뒤로 가기를 누르면 직전 화면(홈 또는 이전 검색)으로 돌아간다.
3. **무엇으로 찾아지나** — 검색어가 다음 중 어디에라도 **부분 일치**하면 결과에 나온다.
   - 곡의 한국어 대표 제목 ("월광 소나타")
   - 곡의 별칭 전부 ("월광", "Moonlight Sonata", "엘리제", "Für Elise")
   - 곡의 원어 제목 ("Piano Sonata No.14")
   - 작곡가 한글 표기("쇼팽", "베토벤"), 작곡가 원어 표기("Chopin", "Beethoven, Ludwig van" — 성·이름 어느 순서로 쳐도), 작곡가 별칭("차이코프스키" / "차이콥스키")
   - 작품번호 ("Op.27 No.2", "BWV 846", "K.545")
4. **일치 규칙**
   - 대소문자 무시. 공백 무시 ("op27no2" = "Op. 27 No. 2", "BWV846" = "BWV 846").
   - 작품번호 표기의 마침표·쉼표 유무 무시 ("Op 27, No 2" = "Op.27 No.2").
   - 검색어를 공백으로 나눠 **모든 단어가 각각** (곡명·별칭·작곡가·작품번호) 어딘가에 걸려야 한다. "쇼팽 녹턴" → 작곡가가 쇼팽이면서 곡명/별칭에 "녹턴"이 있는 곡 전부. "베토벤 월광" → 월광 소나타 1건.
   - 초성 검색("ㅇㄹㅈ")은 1차 포함 여부 미결 (§8-4).
5. **결과 화면 구성**
   - **작곡가 일치 영역** (검색어가 작곡가 이름에 걸릴 때만 맨 위에): "작곡가: 쇼팽 (Frédéric Chopin) — **등록된 곡 24개 모두 보기** →" 카드. 누르면 **작곡가 상세**.
     - **이 숫자는 필터·페이지와 무관한 "작곡가 페이지에 가면 있는 곡 수"다** (2026-09-08 문구 확정, §11-4). 아래 곡 목록의 건수와 다른 질문의 답이므로 숫자를 맞추지 않는다. 대신 **문구로 그 뜻을 드러낸다** — "곡 24개"가 아니라 "등록된 곡 24개 모두 보기".
     - 필터 때문에 아래 곡 목록이 0건이 되어도 이 카드는 남는다. 그때는 카드가 결과가 아니라 **출구**다 (§5 "필터를 걸었더니 0건" 참고).
   - **곡 목록**: 한 항목에 보이는 정보
     - 한국어 대표 제목 (굵게)
     - 원어 제목
     - 작곡가 한글 표기 (원어 표기)
     - 작품번호
     - 난이도 (입문/초급/중급/고급, 미정이면 "난이도 미정"). **묶음 악보는 "고급 (전곡 기준)"처럼 기준을 함께 적는다** — "달빛"을 찾은 사람에게 베르가마스크 모음곡의 "고급"만 보이면 자기가 칠 곡이 고급이라고 오해한다(달빛 단독은 중급). 2026-09-07 추가, §10-3
       - **어떤 곡이 묶음 악보인가**: **수록곡 안내가 있는 곡**이다(§0-3, `03` §10). 이 값이 없는 곡에는 "(전곡 기준)"이 붙지 않는다 — 수집·관리자 등록 곡의 처리는 §12-2 참고
     - 추천 판본 쪽수 ("12쪽") — 추천 판본이 없으면 표시 안 함. **묶음 악보는 쪽수에도 "(전곡 기준)"이 걸린다** — 60쪽은 곡 하나의 길이가 아니다. 난이도와 쪽수가 한 줄에 나란히 있으면 "(전곡 기준)"은 **한 번만** 쓴다: "고급 · 62쪽 (전곡 기준)"
       - **곡 수를 적는 표시("25곡 묶음")는 1차에서 뺀다** (2026-09-08 결정, §12-2). 정확한 곡 수·악장 수는 곡 상세의 **수록곡 안내**가 완성 문장으로 말한다("이 악보에는 25곡이 들어 있어요 — …")
     - 추천 판본 첫 페이지 축소 이미지 (있을 때만)
     - 준비 상태 뱃지 ("준비 중" / "한국에서 이용 제한" / "저작권 확인 중"). 바로 받기 가능한 곡은 뱃지 없음
     - 검색어가 별칭에 걸렸다면 "'월광'으로 찾음"처럼 어떤 이름으로 걸렸는지 한 줄 (같은 곡이 왜 나왔는지 사용자가 이해하도록)
       - **묶음 악보는 문구가 다르다: "'강아지 왈츠'가 들어 있는 악보"** (2026-09-07 추가, §10-3). "'강아지 왈츠'으로 찾음"은 이 항목이 강아지 왈츠 한 곡이라는 뜻으로 읽히는데, 실제로 받게 되는 건 왈츠 3곡이 든 PDF 다.
     - **받게 되는 악보의 범위 한 줄** (2026-09-08 추가, §11-2). 추천 판본이 **전곡이 아니거나 편곡**이면 항목에 그 사실이 보인다. 위의 "묶음 악보" 문구와 **같은 자리·같은 한 줄**을 쓴다 (묶음은 "받는 게 찾은 것보다 크다", 이건 "작거나 다르다" — 사용자에게는 같은 종류의 정보다).
       - 추천 판본의 포함 범위가 특정 악장이면: **"이 악보는 2악장만 들어 있어요"**
       - 추천 판본 종류가 편곡이면: **"피아노 편곡 악보예요"**
       - 둘 다면 두 문구를 한 줄에 이어 쓴다: "피아노 편곡 악보예요 · 2악장만 들어 있어요"
       - 추천 판본이 "전체 악보 · 전곡"이면 이 줄은 없다 (대부분의 곡이 여기 해당한다 — 줄이 늘어나지 않는다)
       - 같은 줄을 **작곡가 상세의 곡 목록**에도 쓴다 (항목 구성이 검색 결과와 같다, §F4)
   - 항목을 누르면 **곡 상세**.
   - 결과 건수 표시 ("'녹턴' 검색 결과 21곡").
   - **정렬**: 기본은 일치도 순 (한국어 대표 제목·별칭에 정확히 일치 → 앞부분 일치 → 그 외 부분 일치), 같으면 누적 다운로드 수 많은 순.
   - **필터** (결과 위쪽, 누르면 즉시 반영, 여러 개 동시 가능)
     - 난이도: 입문 / 초급 / 중급 / 고급 (복수 선택). 미정 곡은 필터를 걸면 빠진다.
     - 쪽수: 10쪽 이하 / 11~20쪽 / 21쪽 이상 (추천 판본 기준. 추천 판본 없는 곡은 쪽수 필터 걸면 빠진다)
     - 바로 받기 가능한 곡만 보기 (체크)
   - 20개씩 나누어 보여주고, 아래에 페이지 이동. 필터·페이지 상태도 주소에 담겨 공유·뒤로가기가 된다.
6. **숨김 처리된 곡**(관리자가 숨김)은 검색·인기곡·작곡가 목록 어디에도 나오지 않는다. 주소로 직접 들어가도 "찾을 수 없는 페이지".

### F3. 곡 상세

1. 검색 결과·인기곡·작곡가 페이지에서 곡을 누르면 **곡 상세**. 주소를 공유하면 같은 화면이 보인다.
2. **곡 정보 영역** (맨 위)
   - 한국어 대표 제목 (제목 크기)
   - 원어 제목
   - 작곡가 한글 표기 (원어 표기) — 누르면 **작곡가 상세**
   - 작품번호
   - 난이도 뱃지
   - "이렇게도 불러요: 월광, Moonlight Sonata, 월광 소나타 14번" — 별칭 나열 (없으면 줄 자체 생략)
   - 작곡 연도, 조성, 악장 구성 — 있는 것만 표시
   - **수록곡 안내** — 묶음 악보라면 **항상 보인다**(2026-09-07 개정, §10-3). 곡 번호 기준 한 줄:
     "이 악보에는 25곡이 들어 있어요 — 2번 아라베스크 · 4번 작은 모임 · 15번 발라드 · 21번 천사의 합창 · 25번 귀부인의 승마"
     - 이 문구는 **큐레이션 목록(`03_1차_큐레이션_곡목록.md` §10)에 곡마다 미리 적어 두고 시드로 함께 넣는다.** 관리자 입력에만 기대면 50곡 전부 빈칸으로 열리게 된다(현재 시드에 이 값이 없어 실제로 그렇다).
     - **시드로 넣되 관리자가 고칠 수도 있다** (2026-09-08 추가, §12-2). 수집·직접 등록으로 만든 곡은 이 값이 비어 있고, 그 곡이 묶음 악보인지 아는 사람은 관리자뿐이다 → 곡 편집의 입력 항목(§3 F5-2).
     - 판본이 바뀌어도 번호는 안 바뀌므로 판본과 무관하게 쓸 수 있다. **쪽수는 적지 않는다** — 판본마다 다르고 우리가 확인할 수 없다.
   - 악장 페이지 안내 (관리자가 쪽수까지 확인해 적었을 때만, 선택): "1악장 1쪽 · 2악장 6쪽 · 3악장 9쪽 (추천 판본 기준)". 추천 판본이 바뀌면 관리자가 다시 확인해야 한다
3. **추천 판본 카드** (화면의 주인공, 크게)
   - "추천 판본" 라벨
   - **첫 페이지 미리보기 이미지** — 누르면 크게 보기(화면 위에 띄움, 닫기 버튼/바깥 클릭으로 닫힘). 이미지가 아직 없으면 회색 자리에 "미리보기 준비 중"
   - 판본 종류 (전체 악보 / 파트보 / 편곡) + 포함 범위 (전곡 / N악장만)
   - **쪽수**, **파일 크기** (예: "12쪽 · 2.4MB")
   - 판본 정보: 출판사, 출판 연도, 편집자, 스캔 제공자 — 있는 것만
   - 한국 기준 저작권 뱃지 + IMSLP 원문 표기 한 줄 (예: "IMSLP 표기: Public Domain")
   - CC 라이선스 판본이면 라이선스 이름과 저작자 표기 한 줄 (예: "CC BY-SA 4.0 · 편집: ○○○")
   - 출처: "출처: IMSLP — 원본 페이지 보기" (새 탭). IMSLP 파일 페이지 링크도 함께
   - **다운로드 버튼** ("PDF 받기 · 2.4MB"): 누르면 즉시 파일이 내려온다. 면책·대기·확인 창 없음. 버튼 1번 = PDF 1개
     - 파일 이름: `작곡가 한글 - 한국어 대표 제목 (작품번호).pdf` 예: `베토벤 - 월광 소나타 (Op.27 No.2).pdf` (**2026-09-08 확정 — §12-1. §8-9 미결 해소**)
       - **이름에 쓰는 값이 비어 있으면 원어로 대신한다**: 작곡가 한글 표기가 없으면 원어 표기, 한국어 대표 제목이 없으면 원어 제목. (수집으로 들어온 곡도 추천 판본·판정만 갖추면 다운로드가 열린다 — 그때 이름이 비면 안 된다)
       - **괄호는 "제목이 말하지 않은 것"만 말한다.** 아래 세 경우에는 괄호를 통째로 생략한다 (2026-09-07 §10-6 → 2026-09-08 §12-1 확정).
         1. **작품번호가 없는 곡** — `사티 - 짐노페디.pdf`, `조플린 - 엔터테이너.pdf`
         2. **이름에 실제로 쓰인 제목 안에 그 작품번호가 이미 들어 있다** — `쇼팽 - 녹턴 Op.9.pdf`, `브람스 - 6개의 피아노 소품 Op.118.pdf`, `슈베르트 - 즉흥곡 Op.90 (D.899).pdf`. 비교는 **대소문자·공백·마침표를 무시**하고 한다("Op. 9" = "op9"). 한국어 제목이 없어 원어 제목을 쓴 곡이면 **원어 제목과 비교**한다(`Nocturnes, Op.9` → 괄호 생략).
            - 단 **다른 번호에 걸치면 안 된다**: 제목의 `Op.10` 은 작품번호 `Op.1` 을 담은 것으로 보지 않는다. 번호가 끝나는 자리에서 제목의 숫자도 끝나야 같은 번호다.
         3. **작품번호가 여러 개이거나, 작품번호 안에 다시 괄호가 들어 있다** — 전부 적으면 이름을 알아볼 수 없고(`… (Opp.19b·30·38·53·62·67·85·102).pdf`), 하나만 적으면 나머지가 빠진 악보처럼 읽힌다. 괄호 안에 또 괄호가 생기는 것도 마찬가지다(`… (BWV Anh.113–132 (1725년 수첩)).pdf`). 괄호를 생략한다: `멘델스존 - 무언가 (전곡).pdf`, `바흐 - 안나 막달레나 바흐를 위한 음악 수첩.pdf`
       - **제목이 담지 못한 것이 작품번호에 남아 있으면 괄호는 그대로 둔다.** 제목 "녹턴 Op.9" + 작품번호 "Op.9 No.2" → `쇼팽 - 녹턴 Op.9 (Op.9 No.2).pdf`. 같은 "Op.9"가 두 번 보이지만 이건 **중복이 아니라 좁혀 준 것**이다 — 지우면 파일 이름만 보고 어느 곡인지 알 수 없다. 파일 이름은 **곡을 가리키는 이름**이지 내용 목록이 아니다(내용 범위는 아래 악장·편곡 꼬리표가 말한다).
         - 다만 이 조합(제목은 넓은 번호, 작품번호는 좁은 번호)이 **실데이터에 실제로 나오면 기획으로 되돌린다** — 곡 정보 자체가 어긋났다는 신호일 수 있다. 시드 50곡에는 없다.
       - **추천 판본이 전곡이 아니거나 편곡이면 그 사실을 파일 이름 끝에 붙인다** (2026-09-08 추가, §11-2). 파일은 사용자의 컴퓨터에 남아 몇 주 뒤에 다시 열린다. 그때 화면은 없고 파일 이름만 있다 — 이름이 곧 마지막 안내다.
         - 특정 악장: `베토벤 - 비창 소나타 (Op.13) 2악장.pdf`
         - 편곡: `리스트 - 사랑의 꿈 (S.541) 편곡.pdf`
         - 둘 다: `… 편곡 2악장.pdf`
         - 전곡·전체 악보면 아무것도 붙지 않는다 (기존 이름 그대로)
         - **괄호가 생략된 곡에도 꼬리표는 그대로 붙는다**: `쇼팽 - 녹턴 Op.9 편곡.pdf`, `사티 - 짐노페디 편곡.pdf`
     - 다운로드가 시작되면 누적 다운로드 수가 1 올라간다 (인기곡 순위에 반영)
     - 파일 크기가 **20MB 이상**이면 버튼 옆에 "파일이 큽니다 (25MB). 모바일 데이터에 주의하세요" 한 줄. 그래도 클릭 1번으로 받는다 (확인 창 띄우지 않음)
4. **"다른 판본 보기 (N개)"** — 기본 접힘. **2026-09-07 전면 개정 (§10-1). 여기에 IMSLP 의 판본을 전부 늘어놓지 않는다.**

   실측: 곡 하나에 IMSLP 판본이 평균 70~90개이고(20곡에 1,792개, `02_저작권_판정_지침.md` 부록 A 도입부), 그중 우리 서버에 파일이 있는 건 **곡당 2개**다. 전부 펼치면 "파일 없음 · 저작권 확인 중 · IMSLP에서 보기" 가 68줄 이어진다. 이건 우리가 고치겠다고 한 IMSLP 의 문제(`00_제품비전…` §3 문제 2 "한 곡에 판본이 너무 많다")를 그대로 재현하는 것이다.

   - **목록에 줄로 펼치는 것은 "우리가 파일을 가진 판본"뿐이다** (추천 판본 제외). 헤더 문구도 개수를 그것으로 센다: "다른 판본 보기 (1개)".
   - 파일이 없는 판본은 **줄로 만들지 않는다.** 대신 접힌 영역 맨 아래에 회색 한 줄:
     **"IMSLP 에는 이 곡의 다른 악보가 88개 더 있어요 — IMSLP 에서 보기 ↗"** (곡의 IMSLP 작품 페이지, 새 탭). 개수만 알려주고 목록은 만들지 않는다.
   - 파일 있는 다른 판본이 0개면 위 한 줄만 남는다. IMSLP 판본도 0개면 영역 자체를 표시하지 않는다.
   - 줄에 보이는 것 (기존과 같음): 판본 종류 · 포함 범위 / 쪽수 · 파일 크기 / 출판사 · 편집자 · 연도 / 한국 기준 저작권 뱃지 / 첫 페이지 미리보기(작게, 노출 규칙은 §F3-6) / 오른쪽 버튼 "PDF 받기"(바로 받기 가능) 또는 "IMSLP에서 보기"(그 외).

   > 관리자 화면(F6 판본 목록)은 그대로 **전부** 보여준다. 판본 70개를 다루는 건 관리자의 일이지 사용자의 일이 아니다.
5. 화면 아래 "같은 작곡가의 다른 곡" 5개 (다운로드 수 순) → 누르면 그 곡 상세. 없으면 영역 생략.
6. **미리보기 이미지 노출 규칙** (2026-09-07 추가, §10-4)
   - 첫 페이지 미리보기는 **"한국에서 자유 이용 가능"으로 판정된 판본만** 보여준다.
   - "저작권 확인 중" / "한국에서 이용 제한" 판본은 미리보기 자리에 회색 상자 + **"저작권을 확인하는 중이라 미리보기도 아직 보여드릴 수 없어요"**. 판본 정보(종류·출판사·편집자·쪽수)와 IMSLP 링크는 그대로 보인다.
   - 이유: 판정이 안 된 판본의 PDF 를 우리가 못 내주는 이유(`02_저작권_판정_지침.md` A-4 "확인되지 않은 파일을 우리 서버에서 내려주는 것은 우리가 재배포의 주체가 되는 것")는 **그 PDF 의 첫 페이지 이미지에도 똑같이 적용된다.** 지금 기획대로면 다운로드는 막아 놓고 같은 파일의 1쪽을 우리 도메인의 공개 주소로 무제한 배포하게 된다 — 스스로 모순이다.
   - 반대 방향의 결과도 확인했다: 자유 이용 가능 판본은 미리보기가 보이므로 "받기 전에 스캔 화질을 본다"(`00_제품비전…` §3 문제 4)는 약속은 유지된다.
7. **준비 중 / 이용 제한 / 확인 중일 때 내보내는 IMSLP 링크** (2026-09-07 개정, §10-5)
   - 지금 기획은 곡의 **작품 페이지**로 보낸다. 그러면 사용자는 우리가 없애 주기로 한 "판본 70개 중 고르기"를 그 자리에서 그대로 겪는다.
   - 우리가 이미 판본 정보를 갖고 있으므로, **우리가 추천으로 고른(또는 고를 후보인) 판본의 IMSLP 파일 페이지**로 바로 보낸다: "IMSLP 에서 이 판본 보기 ↗ — 전체 악보 · 전곡 · 12쪽 · Breitkopf 1862".
   - 그 판본조차 없으면(판본 0개) 그때만 작품 페이지 링크. 링크가 아무것도 없으면 버튼 생략.

### F4. 작곡가

**작곡가 목록**
1. 홈 "모든 작곡가 보기" 또는 헤더 "작곡가" 메뉴 → **작곡가 목록**.
2. 공개된 곡이 1개 이상 있는 작곡가만, 한글 표기 가나다순. 한 항목: 한글 표기 · 원어 표기 · 생몰년 · 곡 수.
3. 누르면 **작곡가 상세**.

**작곡가 상세**
1. 상단: 한글 표기 (제목), 원어 표기, 생몰년, 국적(있으면), 검색용 별칭(있으면 "차이콥스키라고도 씁니다"), IMSLP 작곡가 페이지 링크(새 탭).
2. **곡 목록**: 이 작곡가의 공개 곡 전부. 항목 정보는 검색 결과와 동일 (한국어 제목, 원어 제목, 작품번호, 난이도, 쪽수, 상태 뱃지). 작곡가 이름은 생략.
3. 정렬: 기본 누적 다운로드 수 순. "작품번호 순"으로 바꿀 수 있다.
4. 필터: 검색 결과와 같은 난이도 · 쪽수 · 바로 받기 가능만.
5. 20개씩 페이지 이동.

### F8. 공통 틀

- **헤더**: 서비스 이름(로고, 누르면 홈) · 작은 검색창(홈 이외 모든 일반 화면에서, 입력 후 Enter → 검색 결과) · "작곡가" 메뉴 · 오른쪽에 로그인 상태 표시
  - 비로그인: "로그인" 버튼 (관리자 진입용. 노출 여부는 §8-3)
  - 로그인(ADMIN): "관리" 메뉴 + 닉네임 + 로그아웃
  - 로그인(USER): 닉네임 + 로그아웃 (1차에는 USER 전용 기능이 없다)
  - 기존 "커뮤니티" "채팅" 메뉴: 1차 범위 밖. 처리 방식은 §8-2
- **푸터**: "악보 출처: IMSLP (imslp.org)" · "저작권 안내: 각 악보의 한국 기준 이용 가능 여부는 판본별로 표시합니다. 판정에 이견이 있으면 알려주세요 (연락처)" · 서비스 이름
- **찾을 수 없는 페이지** (기존 화면 유지): 문구 "찾을 수 없는 페이지예요" + "홈으로" 버튼 + 검색창

## 3. 사용자 흐름 — 관리자

### 공통: 관리자 진입

1. 헤더 "로그인" → 기존 **로그인** 화면 → 로그인 성공 시 **원래 보던 화면**으로 돌아온다 (홈에서 눌렀으면 홈).
2. ADMIN 역할이면 헤더에 "관리" 메뉴가 생긴다 → **관리 홈**.
3. USER 역할이 관리 화면 주소로 직접 들어오면 → "관리자만 들어갈 수 있어요" 안내 + "홈으로" 버튼. 관리 메뉴는 보이지 않는다.
4. 비로그인이 관리 화면 주소로 직접 들어오면 → 로그인 화면으로. 로그인 후 원래 가려던 관리 화면으로.
5. 관리 화면 안에서 세션이 끊기면(오래 방치 등) → 저장 시도 시 "로그인이 풀렸어요. 다시 로그인해 주세요" + 로그인 화면으로. 작성 중이던 내용은 잃을 수 있음을 안내.

### 관리 홈 (대시보드)

- 숫자 카드: 전체 곡 수 · 바로 받기 가능 곡 수 · 준비 중 곡 수 · **보완 필요 곡 수**(규칙은 §F5-3 — 곡 목록 필터·곡 편집 표시와 **같은 규칙**을 쓴다) · 저작권 확인 중 판본 수 · 이번 달 다운로드 수
- 바로가기: 작곡가 관리 / 곡 관리 / 저작권 판정 대기함 / 수집 관리
- "최근 수집 작업" 1건 요약: 상태(진행 중/완료/중지됨/실패) · 진행 N/M · 시작 시각 → 누르면 **수집 진행/결과** 화면
- 수집이 진행 중이면 관리 화면 어디에서나 상단에 얇은 띠 "수집 진행 중 12/50 — 보기"가 보인다.

### F5. 작곡가·곡·별칭·난이도 관리

**작곡가 관리**
1. 관리 홈 → **작곡가 목록(관리)**: 이름 검색, 곡 수, 한글 표기 유무. "새 작곡가" 버튼.
2. **작곡가 등록/수정** 입력 항목
   - 한글 표기 (필수) — 예: 베토벤
   - 원어 표기 (필수) — 예: Beethoven, Ludwig van
   - 검색용 별칭 (여러 개, 선택) — 예: 루트비히 판 베토벤
   - 생년·몰년 (선택. 저작권 판정 근거로 쓰이니 입력 권장 문구 표시)
   - 국적 (선택)
   - IMSLP 작곡가 페이지 링크 (선택)
3. 저장 → 목록으로, "저장했어요" 알림. 같은 원어 표기가 이미 있으면 "이미 등록된 작곡가예요 — 보기" 안내로 중복 막음.
4. 삭제: 곡이 1개라도 있으면 삭제 불가 안내("곡 12개가 있어 삭제할 수 없어요. 곡을 먼저 옮기거나 지우세요").

**곡 관리**
1. 관리 홈 → **곡 목록(관리)**: 검색창(사용자 검색과 같은 규칙) + 필터
   - 상태: 바로 받기 가능 / 준비 중 / 이용 제한 / 저작권 확인 중 / **보완 필요** / 숨김
   - 작곡가
   - 난이도(미정 포함)
   - 한 항목: 한국어 제목(없으면 원어 제목을 회색으로) · 작곡가 · 작품번호 · 난이도 · 판본 수 · 추천 판본 유무 · 상태 · 마지막 수정일
   - "새 곡" 버튼 (수집을 안 거치고 직접 등록할 때)
2. **곡 등록/수정** 화면 — 위쪽은 곡 정보, 아래쪽은 판본 목록(F6)
   - 작곡가 (필수, 목록에서 고르기. 없으면 "새 작곡가 등록" 바로가기)
   - 한국어 대표 제목 (필수 — 비어 있으면 저장은 되지만 상태가 "보완 필요")
   - 원어 제목 (필수)
   - 작품번호 (여러 개 가능. 예: "Op.27 No.2", "WoO 59")
   - 별칭 목록: 한 줄에 하나씩 추가/삭제. 같은 곡 안 중복은 막고, **다른 곡과 같은 별칭은 허용하되** "'녹턴'은 다른 곡 20개에도 있어요" 경고만 보여준다 (사용자는 검색 결과에서 여러 곡을 본다)
   - 난이도: 입문 / 초급 / 중급 / 고급 / 미정 (기본 미정)
   - 작곡 연도, 조성, 악장 구성 (선택)
   - **수록곡 안내** (선택, 자유 문장. 예: "이 악보에는 25곡이 들어 있어요 — 2번 아라베스크 · …") — **2026-09-08 추가, §12-2.** 큐레이션 50곡은 시드로 채워져 있지만 수집·직접 등록으로 만든 곡은 비어 있다. 입력칸 옆 도움말: **"여러 곡·여러 악장이 한 PDF 에 들어 있는 곡이면 적어 주세요. 이 줄이 있어야 사용자 화면에 '(전곡 기준)'이 붙습니다."**
     - 이 값이 있으면 그 곡은 **묶음 악보**로 취급된다(§0-3) — 곡 상세의 수록곡 안내 한 줄, 검색 결과의 "'…'가 들어 있는 악보" 문구, 난이도·쪽수의 "(전곡 기준)"이 모두 이 값으로 갈린다
     - 쪽수는 적지 않는다(판본마다 다르다). 쪽수 기준 안내는 아래 "악장 페이지 안내"가 따로 있다
   - 악장 페이지 안내 (선택, 자유 문장. 예: "1악장 1쪽 · 2악장 6쪽")
   - IMSLP 작품 페이지 링크 (수집으로 만든 곡은 자동 채움, 직접 등록이면 선택)
   - 숨김 여부 (기본: 보임). 숨기면 사용자 화면 어디에도 안 나온다
   - 저장 → 같은 화면에 머물며 "저장했어요". "사용자 화면에서 보기" 링크(새 탭)
3. **보완 필요** 판정 규칙 (관리자에게만 보이는 표시)

   **'보완 필요'가 답하는 질문은 "이 곡을 사용자에게 열어 주려면 뭐가 남았나"다** (2026-09-08 확정, §11-1). 곡 단위 작업 목록이며, 판본 단위 목록인 **저작권 판정 대기함(§F6)과 역할이 다르다** — 대기함은 "확인 중 판본 수천 건을 처리하는 자리"이고, 여기는 "곡 50개를 하나씩 완성하는 자리"다. 관리자의 목표(§8-17 공개 기준 "50곡 중 35곡 이상 바로 받기 가능")가 **곡 단위 숫자**이므로 주 작업 목록도 곡 단위여야 진척이 같은 단위로 보인다.

   빠진 것으로 세는 항목:
   - 한국어 대표 제목이 비었다
   - 별칭이 0개다
   - 난이도가 미정이다
   - 추천 판본이 없다
   - **추천 판본은 있는데 그 판본의 한국 기준 저작권 판정이 "확인 중"이다** (2026-09-08 추가, §11-1). 판정이 안 끝난 곡은 사용자에게 **닫혀 있다** — 추천 판본이 있다는 이유로 할 일 목록에서 빠지면 관리자는 그 곡을 다시 볼 계기가 없다. 판정이 "이용 제한"인 것은 **사람이 내린 결론**이므로 빠진 것으로 세지 않는다 (할 일이 아니라 끝난 일이다).

   곡 편집 화면 상단에 "빠진 것: 한국어 제목, 난이도, **저작권 판정**" 식으로 항목을 나열한다. 곡 목록(관리)의 상태 필터 "보완 필요", 관리 홈의 "보완 필요 곡 수" 카드, 곡 편집 상단 표시 **세 곳이 이 한 규칙을 공유한다** — 한 곳에서 사라진 곡이 다른 곳에는 남아 있으면 안 된다.
4. 곡 삭제: 판본이 있으면 "판본 3개와 파일이 함께 지워져요" 확인 창 → 확인 시 삭제. 다운로드 기록이 있는 곡은 삭제 대신 숨김을 권장하는 문구.

### F6. 판본 관리 (곡 편집 화면 아래쪽)

1. **판본 목록**: 한 행에 종류·포함 범위 · 쪽수 · 크기 · 출판사/편집자/연도 · 파일 유무 · 한국 기준 뱃지 · "추천" 표시 · 다운로드 수. 행 오른쪽에 "수정" "추천으로 지정" "파일 받아오기"(파일 없고 IMSLP 링크 있을 때) "삭제".
2. **판본 추가/수정** 입력 항목
   - PDF 파일: 파일 선택 → 올리면 **쪽수·파일 크기·첫 페이지 미리보기가 자동으로 채워진다** (쪽수는 수정 가능). PDF가 아니거나 상한(§8-6)을 넘으면 즉시 거부 안내. 이미 파일이 있으면 "교체" (교체 시 미리보기·쪽수·크기 다시 채움)
   - 판본 종류 (필수): 전체 악보 / 파트보 / 편곡
   - 포함 범위 (필수): 전곡 / 특정 악장(악장 번호 입력)
   - 출판사, 출판 연도, 플레이트 번호, 편집자, 스캔 제공자 (선택)
   - IMSLP 파일 페이지 링크 (수집이면 자동)
   - IMSLP 저작권 표기 원문 (수집이면 자동. 예: "Public Domain", "Creative Commons Attribution-ShareAlike 4.0")
   - **한국 기준 저작권 판정** (필수): 자유 이용 가능 / 이용 제한 / 확인 중 (기본 "확인 중")
   - 판정 메모 (판정을 "자유 이용 가능" 또는 "이용 제한"으로 바꿀 때 **필수**): 근거를 적는다. 예: "작곡가 1827 사망, 편집자 1913 사망 → 사후 70년 경과". 화면에 작곡가 몰년을 자동으로 보여준다 (등록돼 있을 때)
   - CC 라이선스라면 라이선스 이름 + 표기할 저작자 (선택, 사용자 화면에 노출)
3. **추천으로 지정**: 곡당 1개. 다른 판본이 추천이면 자동 해제되고 "추천 판본을 ○○에서 △△로 바꿨어요" 알림. PDF 파일이 없는 판본은 지정 불가 ("파일이 없어 추천으로 지정할 수 없어요").

   **지정은 되지만 경고가 뜨는 경우** (2026-09-08 개정, §11-2). **경고는 하나가 아니라 해당되는 것이 전부 보인다** — 겹칠 때 하나만 보이면 관리자는 나머지를 모른 채 지정한다.
   | 조건 | 경고 문구 |
   |---|---|
   | 저작권이 "확인 중" / "이용 제한" | "이 판본은 사용자에게 다운로드가 열리지 않아요" |
   | 판본 종류가 **편곡** | "이 판본은 편곡이에요. 사용자가 원곡 악보를 기대하고 받을 수 있어요" |
   | 포함 범위가 **특정 악장** | "이 판본은 2악장만 들어 있어요. 곡 전체가 아니에요" |

   - 세 경고는 동시에 뜰 수 있다 (예: "편곡 · 2악장만 · 확인 중"이면 세 줄 다).
   - **경고를 보고도 지정하면 그건 사람의 결정이므로 막지 않는다.** 실데이터에서 곡당 우리가 가진 파일은 2개뿐이라, "편곡뿐이지만 없는 것보다 낫다"가 정당한 선택일 때가 있다. 대신 그 선택의 결과가 **사용자에게 보이게** 한다 — 검색 결과 한 줄(§F2-5)·곡 상세 카드(§F3-3)·파일 이름(§F3-3) 세 곳.
   - **자동 지정은 지금처럼 "전체 악보 · 전곡"만 고른다** (실데이터 42곡 중 편곡·부분 범위 자동 지정 0건). 이 경고는 관리자 수동 지정 경로만을 위한 것이다.
4. **추천 후보 제안**: 수집으로 만든 곡은 시스템이 "전체 악보 · 전곡 · IMSLP 다운로드 수 최다" 판본을 "추천 후보"로 표시해 준다. 관리자는 "이 후보를 추천으로 지정" 한 번에 확정. 후보는 사용자에게 보이지 않는다.
   - **자동 지정된 추천은 "사람이 눈으로 확인" 전까지 미검수 상태다** (2026-09-07 추가, §10-8). 자동 규칙은 "전체 악보 · 전곡"만 고르지만, 그것이 **피아노 악보라는 보장은 없다.** IMSLP 는 같은 작품 페이지에 관현악 편곡의 총보도 "Complete Score"로 둔다 — `03_1차_큐레이션_곡목록.md` §6 이 이미 파반느(#33)·사계(#29)·짐노페디(#14)·어린이 차지(#32)·꽃노래(#9)·엔터테이너(#35)를 위험 곡으로 적어 두었다. 사용자가 "죽은 왕녀를 위한 파반느" 피아노 악보를 눌렀는데 오케스트라 총보를 받는 일이 실제로 가능하다.
   - 곡 편집·곡 목록(관리)에 **"추천 판본 미검수"** 표시를 두고, 관리 홈에 "추천 판본 확인 필요 N곡" 카드를 둔다. 관리자가 미리보기를 열어 확인하고 "확인함"을 누르면 표시가 사라진다.
   - 미검수여도 사용자 화면에서 다운로드는 열린다(안 열면 초기에 받을 수 있는 곡이 0개가 된다). 대신 **공개 전 체크리스트(§10-8)에 "미검수 0곡"을 넣는다.**
5. 판본 삭제: 추천 판본이면 "추천이 해제됩니다" 확인. 다운로드 기록이 있으면 경고 후 삭제 가능.

**저작권 판정 대기함**
1. 관리 홈 → **저작권 판정 대기함**: 판정이 "확인 중"인 판본 전부. 한 행에 곡 · 작곡가(몰년) · 판본 종류 · 편집자 · IMSLP 표기 원문 · IMSLP 링크.
2. 행마다 바로 "자유 이용 가능" / "이용 제한" 버튼 + 메모 입력. 저장하면 행이 대기함에서 사라진다.
3. 여러 행 선택 → 같은 판정·메모 일괄 적용 (예: 같은 작곡가의 PD 스캔 20개).

### F7. 수집 운영 (관리자 관점)

**수집이 하는 일 / 관리자가 하는 일** (사용자에게 보이는 결과 기준)

| 수집이 자동으로 채우는 것 | 관리자가 채우는 것 |
|---|---|
| 원어 제목, 작곡가 원어 표기(없으면 작곡가 새로 생성), 작품번호, IMSLP에 적힌 영문 별칭, 작곡 연도·조성·악장 구성, IMSLP 작품 페이지 링크 | 한국어 대표 제목, 한국어 별칭, 작곡가 **한글 표기**(작곡가마다 최초 1회), 난이도, **수록곡 안내**(묶음 악보일 때 — 2026-09-08 추가, §12-2), 악장 페이지 안내 |
| 작품 페이지의 **모든 판본 정보** (종류, 포함 범위, 쪽수, 크기, 출판사, 연도, 편집자, 스캔 제공자, IMSLP 저작권 표기, IMSLP 다운로드 수, 파일 페이지 링크) | 한국 기준 저작권 판정 + 메모 |
| **PDF 파일은 "전체 악보" 중 IMSLP 다운로드 수 상위 2개만** 실제로 받아온다 (추천 1 + 대체 1). 나머지 판본은 정보만 | 추천 판본 확정 (후보를 확인만 하면 됨). 그 외 판본의 파일이 필요하면 "파일 받아오기" 개별 실행 |
| 받아온 PDF의 첫 페이지 미리보기 | — |

**흐름**

1. 관리 홈 → **수집 관리**. 화면은 위에 "수집 대상 등록", 아래에 "수집 작업 목록"(최근 순).
2. **수집 대상 등록**
   - 큰 입력칸에 IMSLP 작품 페이지 주소를 **한 줄에 하나씩** 붙여넣는다 (예: `https://imslp.org/wiki/Piano_Sonata_No.14,_Op.27_No.2_(Beethoven,_Ludwig_van)`). 파일 하나로 올리는 방식은 1차에 없다.
   - "확인" 버튼 → 줄마다 판정 표가 뜬다
     - 정상: "수집 예정"
     - 주소 형식이 IMSLP 작품 페이지가 아님: "주소 형식 오류" (수집 대상에서 제외)
     - 이미 우리 서비스에 같은 IMSLP 링크로 등록된 곡: "이미 있음 — 건너뜀" (옆에 "정보만 다시 가져오기" 체크를 켜면 판본 정보를 갱신하되 **이미 받은 파일은 다시 받지 않는다**)
     - 같은 주소가 목록 안에 중복: 하나만 남기고 "중복 제거"
   - 표 아래 요약: "수집 예정 48건 · 건너뜀 2건 · 오류 1건 · 예상 소요 약 1시간 10분"
   - **예상 시간 안내 문구 (고정 표시)**: "IMSLP 서버에 부담을 주지 않도록 요청 사이에 2초 이상 쉬며 천천히 가져옵니다. 곡당 보통 1~2분, 파일이 크면 더 걸립니다. 화면을 닫아도 수집은 계속됩니다."
3. **"수집 시작"** 버튼 → 수집 작업이 만들어지고 **수집 진행** 화면으로 이동.
   - 이미 진행 중인 작업이 있으면 "수집 시작" 버튼은 비활성 + "진행 중인 수집이 끝나면 시작할 수 있어요 — 보기". 동시에 하나만 돈다.
4. **수집 진행** 화면
   - 상단 진행 막대: "12 / 50 완료 · 성공 11 · 실패 1 · 남은 예상 시간 약 45분"
   - "지금 처리 중: Nocturne in E-flat major, Op.9 No.2 — 판본 정보 읽는 중 / 파일 받는 중 (2/2)"
   - 항목 목록: 순서 · IMSLP 주소 · 상태(대기 / 처리 중 / 성공 / 실패 / 건너뜀) · 결과 요약(성공: "판본 14개, 파일 2개 받음 → 곡 보기" / 실패: 사유)
   - 화면은 **10초마다 자동 갱신**. "새로고침" 버튼도 있다.
   - **"중지"** 버튼: 지금 처리 중인 곡은 끝까지 마치고 멈춘다. 남은 항목은 "대기"로 남는다. 상태가 "중지됨"으로 바뀌고 **"이어서 시작"** 버튼이 생긴다.
   - 화면을 떠났다가 (브라우저를 닫았다가) 다시 들어와도 같은 현황이 보인다.
5. **수집 결과** (작업이 끝나면 같은 화면이 결과 모드로)
   - 요약: "총 50건 — 성공 46 · 실패 3 · 건너뜀 1 · 걸린 시간 1시간 3분"
   - 실패 항목은 사유와 함께 위로 모아 보여주고, **"실패한 것만 다시 시도"** 버튼 (새 작업으로 만들어져 다시 §4 진행 흐름). 실패 사유 종류:
     - "IMSLP에 그 페이지가 없어요" (주소 오타·이동)
     - "작품 페이지에 PDF 판본이 없어요" (정보만 등록되고 곡은 "준비 중")
     - "파일을 받다가 끊겼어요" (판본 정보는 등록됨, 파일만 없음 → 곡 편집에서 "파일 받아오기"로 개별 재시도 가능)
     - "IMSLP가 응답하지 않아요" (아래 예외 §4 참고)
     - "피아노 독주곡이 아닌 것 같아요" — 편성 정보가 피아노 독주가 아니면 **등록은 하되 숨김 상태**로 만들고 사유에 표시. 관리자가 확인 후 숨김 해제
   - 성공 항목: "→ 곡 보기" 를 누르면 **곡 편집** 화면. 수집으로 만든 곡은 한국어 제목·별칭·난이도가 비어 있으므로 모두 **"보완 필요"** 상태다. 사용자 검색에는 원어 제목·작곡가·작품번호로는 이미 찾히지만 (숨김이 아니므로) "준비 중"/"저작권 확인 중" 뱃지로 보인다.
6. **수집 후 관리자 마무리 흐름** (2026-09-07 개정, §10-8)

   **(A) 전체를 한 번에** — 수집이 끝나면 판본이 수천 건이고 전부 "저작권 확인 중"이라 이 단계를 건너뛰면 **바로 받기 가능한 곡이 0개**다. 곡 하나씩 도는 (B)보다 먼저 한다.
   1. 저작권 판정 대기함 → **"자동 판정 실행"** (미리보기로 숫자 확인 후 실행). 규칙은 `02_저작권_판정_지침.md` 부록 A
   2. 같은 실행이 추천 판본이 없는 곡에 추천을 자동 지정한다 → 곡들이 "바로 받기 가능"으로 바뀐다
   3. 관리 홈에서 "바로 받기 가능 곡 수"를 확인한다. 이 숫자가 §10-8 의 공개 기준에 못 미치면 (B)로 손 판정을 더 한다
   4. **되돌리기** (2026-09-08 확정, §11-1) — 자동 판정 결과가 마음에 안 들면 되돌릴 수 있다. 버튼 이름은 **"자동 판정만 되돌리기"** 다.
      - 되돌리는 것: 이번 실행이 매긴 **저작권 판정**만. 판본들이 다시 "확인 중"이 된다.
      - **되돌리지 않는 것: 같은 실행이 지정한 추천 판본.** 추천은 판정과 별개의 선택이고, 되돌리면 관리자가 그 사이에 손으로 손댄 추천까지 날아갈 수 있다.
      - 그래서 실행 결과 안내에 **반드시 이 한 줄이 함께 보인다**: "저작권 판정만 되돌렸어요. 자동으로 지정된 추천 판본은 그대로 있어요 — 바꾸려면 곡 편집에서 해제하세요." 이름과 행동이 다르면 관리자가 "되돌렸는데 왜 그대로지?"에서 멈춘다.
      - 되돌린 곡들은 **"보완 필요"로 다시 올라온다** (§F5-3 의 "추천 판본은 있는데 판정이 확인 중" 항목). 관리 홈의 보완 필요 수도 실행 전 값으로 돌아간다. **되돌리기를 눌렀는데 관리자의 할 일 목록이 그대로면 되돌린 게 아니다.**

   **(B) 곡 1개당**
   1. 곡 관리 → 필터 "보완 필요" 또는 "추천 판본 미검수" → 곡 편집
   2. 한국어 대표 제목·별칭·난이도·**수록곡 안내** 입력. 큐레이션 50곡은 시드에 이미 들어 있으므로 이 단계가 필요 없다 — **시드에 없는 주소를 관리자가 직접 넣었을 때만** 해당한다 (`03` §9 가정 3). 작곡가 한글 표기가 비어 있으면 상단 경고 "작곡가 한글 표기가 없어요 → 작곡가 편집"
   3. 판본 목록에서 추천 판본의 **미리보기를 열어 피아노 악보가 맞는지 확인** → "확인함" (§F6-4)
   4. 판정이 미심쩍은 판본은 대기함 또는 곡 편집에서 사람 판정으로 덮어쓴다
   5. 저장 → 사용자 화면에 반영

| 필터를 걸었더니 0건 | "이 조건에 맞는 곡이 없어요 — 필터 해제" 버튼. **작곡가 카드가 정확히 1명 떠 있으면 그 아래에 한 줄을 더 붙인다: "쇼팽의 곡은 10개 등록돼 있어요 — 조건 없이 모두 보기 →"** (작곡가 상세로). 카드의 "10개"와 결과의 "0곡"이 나란히 보여도 모순이 아니라는 것을 문구로 잇는다 (2026-09-08, §11-4). **카드가 2명 이상이면 이 줄은 없다** — 누구의 곡인지 모호해지고 줄이 늘어 더미가 되며, 그때는 카드마다 자기 출구(작곡가 상세)가 이미 있다 (2026-09-11 designer 확정, `04` 개정 7) | 결과 화면에 머묾 (또는 작곡가 상세) |

| 한국에서 비PD (이용 제한) | 검색 결과에 "한국에서 이용 제한" 뱃지. 곡 상세 추천 판본 카드에 뱃지 + 설명 "한국 저작권 기준으로 아직 자유 이용이 어려운 판본이에요. IMSLP 원본 페이지에서 각자 판단해 이용해 주세요" + "IMSLP에서 보기" 버튼. 다운로드 버튼 없음. 미리보기·판본 정보는 보임 | 곡 상세 |
| 저작권 확인 중 | 위와 같되 뱃지 "저작권 확인 중", 설명 "이용 가능 여부를 확인하는 중이에요" | 곡 상세 |

## 6. 인수 조건 (qa 체크리스트)

### 홈 / 공통
- [ ] 로그인하지 않은 상태로 서비스 주소에 들어가면 홈이 열리고, 로그인 요구가 없다.
- [ ] 홈에 검색창 1개, 인기곡 10개(다운로드 수 순, 같으면 큐레이션 노출 순서 — §11-3), 작곡가 8명(곡 수 순)이 보인다.
- [ ] 홈이 열리면 검색창에 바로 입력할 수 있다 (커서가 검색창에 있다).
- [ ] 홈 인기곡 항목을 누르면 그 곡의 상세로 이동한다.
- [ ] 홈 작곡가 항목을 누르면 그 작곡가 상세로, "모든 작곡가 보기"를 누르면 작곡가 목록으로 이동한다.
- [ ] 홈 이외의 일반 화면(검색 결과·곡 상세·작곡가)에서도 헤더 검색창으로 검색할 수 있다.
- [ ] 헤더 로고를 누르면 홈으로 간다. 헤더에 "작곡가" 메뉴가 있다.
- [ ] 푸터에 "악보 출처: IMSLP"와 저작권 안내 문구가 있다.
- [ ] 존재하지 않는 주소로 들어가면 "찾을 수 없는 페이지"가 나오고 홈 버튼과 검색창이 있다.
- [ ] 화면 폭이 모바일(360px)이어도 검색창·다운로드 버튼이 잘리지 않고 눌린다.

### 검색
- [ ] "월광"으로 검색하면 베토벤 피아노 소나타 14번이 결과에 나온다 (별칭 일치).
- [ ] "엘리제를 위하여", "엘리제", "Für Elise", "fur elise"로 검색하면 모두 같은 곡이 나온다.
- [ ] "쇼팽 녹턴"으로 검색하면 쇼팽의 녹턴만 나오고, 다른 작곡가의 녹턴은 나오지 않는다.
- [ ] "Chopin"과 "쇼팽"으로 검색한 결과에 같은 곡들이 나온다.
- [ ] "Op.27 No.2", "op 27 no 2", "op27no2"로 검색하면 모두 같은 곡이 나온다.
- [ ] "BWV 846"과 "BWV846"으로 검색한 결과가 같다. "K.545"와 "K545"도 같다.
- [ ] 대소문자를 바꿔 검색해도 결과가 같다.
- [ ] 검색어의 일부만 쳐도(예: "녹") 부분 일치로 결과가 나온다.
- [ ] 검색어가 작곡가 이름에 걸리면 결과 맨 위에 작곡가 카드가 보이고, 누르면 작곡가 상세로 간다.
- [ ] 결과 항목마다 한국어 제목, 원어 제목, 작곡가 한글(원어), 작품번호, 난이도, 추천 판본 쪽수(있을 때), 상태 뱃지(해당 시)가 보인다.
- [ ] 별칭으로 걸린 항목에는 어떤 별칭으로 걸렸는지 한 줄이 보인다.
- [ ] 결과 건수("N곡")가 표시된다.
- [ ] 난이도 필터를 "초급"만 켜면 초급 곡만 남고, "난이도 미정" 곡은 빠진다.
- [ ] 쪽수 필터 "10쪽 이하"를 켜면 추천 판본이 10쪽 이하인 곡만 남는다.
- [ ] "바로 받기 가능한 곡만" 필터를 켜면 준비 중·이용 제한·확인 중 곡이 빠진다.
- [ ] 결과가 20개를 넘으면 페이지 이동이 보이고 2페이지로 갈 수 있다.
- [ ] 결과 화면 주소를 복사해 새 탭에 붙여넣으면 같은 검색어·필터·페이지 결과가 보인다.
- [ ] 브라우저 뒤로 가기를 누르면 직전 화면으로 돌아간다.
- [ ] 없는 검색어로 검색하면 "찾지 못했어요" 안내와 예시 별칭, 인기곡 5개, 작곡가 목록 링크가 보인다.
- [ ] 필터로 0건이 되면 "필터 해제" 버튼이 보이고, 누르면 필터가 풀린다.
- [ ] 관리자가 숨긴 곡은 검색·인기곡·작곡가 상세 어디에도 나오지 않고, 주소로 들어가면 "찾을 수 없는 페이지"다.
- [ ] 빈 검색어로 Enter를 눌러도 화면이 이동하지 않고 오류 문구도 없다.

### 곡 상세
- [ ] 곡 상세에 한국어 제목, 원어 제목, 작곡가(누르면 작곡가 상세), 작품번호, 난이도, 별칭 목록이 보인다.
- [ ] 추천 판본 카드에 첫 페이지 미리보기, 판본 종류(전체 악보/파트보/편곡)·포함 범위, 쪽수, 파일 크기, 출판사·연도·편집자·스캔 제공자(있는 것), 한국 기준 저작권 뱃지, IMSLP 원문 표기, "출처: IMSLP" 링크가 보인다.
- [ ] "출처: IMSLP" 링크를 누르면 새 탭에서 그 곡의 IMSLP 작품 페이지가 열린다.
- [ ] 미리보기 이미지를 누르면 크게 보이고, 닫기 버튼이나 바깥을 누르면 닫힌다.
- [ ] 바로 받기 가능한 곡에서 "PDF 받기" 버튼을 **한 번** 누르면 확인 창·대기 화면 없이 PDF 파일이 내려온다.

- [ ] 관리 홈의 보완 필요 수 · 곡 목록 필터 결과 건수 · 곡 편집 상단 표시가 **서로 어긋나지 않는다** (같은 규칙을 쓴다).

**§11-2 편곡·부분 범위 추천 판본**
- [ ] 포함 범위가 "2악장만"인 판본을 추천으로 지정하면 "곡 전체가 아니에요"라는 취지의 경고가 보인다.
- [ ] 종류가 "편곡"인 판본을 추천으로 지정하면 편곡 경고가 보인다.
- [ ] 편곡이면서 2악장만이면서 판정이 "확인 중"인 판본을 지정하면 **경고 3개가 모두** 보인다 (하나만 보이면 결함).
- [ ] 경고를 무시하고 지정하면 지정은 된다 (막히지 않는다).
- [ ] 그 곡을 검색하면 결과 항목에 "이 악보는 2악장만 들어 있어요" / "피아노 편곡 악보예요" 한 줄이 보인다. 작곡가 상세의 곡 목록에서도 같다.
- [ ] 추천 판본이 "전체 악보 · 전곡"인 곡에는 그 줄이 **없다**.
- [ ] 그 곡의 PDF를 받으면 파일 이름이 `베토벤 - 비창 소나타 (Op.13) 2악장.pdf` 처럼 범위를 담고 있다. 전곡 곡의 파일 이름에는 아무것도 붙지 않는다.
- [ ] 곡 상세 추천 판본 카드에 "전체 악보 · 2악장만" / "편곡 · 전곡"이 그대로 보인다.

**§11-3 홈 인기곡 자격**
- [ ] 홈 인기곡에 **한국어 대표 제목이 없는 곡이 하나도 없다** (원어 제목만 보이는 항목이 없다).
- [ ] 홈 인기곡에 "준비 중" / "이용 제한" / "저작권 확인 중" 뱃지 곡이 있다면, 그것은 **자격 곡이 10개에 못 미쳐 채운 뒷자리뿐**이다. 자격 곡이 10개 이상이면 뱃지 곡이 하나도 없다.
- [ ] 추천 판본을 지운 곡(PREPARING)이 홈 인기곡 **1위에 오지 않는다**.
- [ ] 다운로드가 모두 0인 상태에서 홈 인기곡 순서가 큐레이션 노출 순서(입문 → 초급 → 중급 → 고급)를 따르고, **10곡이 전부 고급이 아니다** (입문·초급·중급이 섞여 있다).
- [ ] 자격 곡이 0개면 인기곡 영역이 아예 보이지 않고, 빈 자리가 남지 않는다.
- [ ] 한 곡을 여러 번 다운로드해 다운로드 수를 올리면 그 곡이 위로 올라간다 (실제 인기는 그대로 반영된다).

**§11-4 필터 0건과 작곡가 카드** *(2026-09-11: "카드 1명일 때" 조건 명시 — `04` 개정 7)*

- [ ] 그때 — **작곡가 카드가 정확히 1명이므로** — 빈 결과 안내에 "쇼팽의 곡은 10개 등록돼 있어요 — 조건 없이 모두 보기" 한 줄이 함께 보이고, 누르면 작곡가 상세로 간다.
- [ ] "필터 해제"를 누르면 결과가 다시 나온다.
- [ ] 작곡가 카드의 곡 수는 필터·페이지를 바꿔도 변하지 않는다 (의도된 동작이다 — 변하면 결함).

## 7. 기존 화면·흐름과의 정합성

- **홈**: 기존 보일러플레이트 홈(HomePage)은 내용을 전면 교체한다. 주소(`/`)는 그대로.
- **로그인**: 기존 로그인 화면·회원가입 화면은 그대로 두되, 1차에서 일반 사용자에게 로그인을 권하는 문구는 어디에도 두지 않는다. 로그인 후 "원래 보던 화면으로 복귀"가 안 되면 홈으로 보낸다 (현재 동작 확인 필요 — qa).
- **헤더**: 로고 문구("Boilerplate")를 서비스 이름으로, 메뉴를 "작곡가"(+ 관리자에게만 "관리")로 바꾼다. 커뮤니티·채팅 메뉴는 §8-2 결정에 따른다.
- **마이페이지**: 1차에는 관리자만 로그인하므로 그대로 둔다. 헤더의 "마이페이지" 링크는 로그인 사용자에게만 보이는 현재 동작 유지.
- **페이지 이동 부품**: 기존 목록 페이지 이동 방식(20개씩)을 검색 결과·작곡가 상세에서도 같은 모양으로 쓴다.
- **파일**: 기존 파일 업로드 흐름이 있으니 관리자 PDF 업로드는 그 사용감(파일 선택 → 올리는 중 표시 → 완료)을 따른다.

### 9-1. 수집 방식 결정 (2026-09-06, `docs/설계/00_IMSLP_수집_조사.md` 반영)

조사 결과 IMSLP 는 파일 다운로드에 **봇 게이트(`friendlyredirect`) → 면책 동의 → 15초 대기** 3중 장치를 두고 있고, 메타데이터 경로(작품 페이지·`api.php`·공개 API)는 허용한다. 선임개발자 권고는 "메타데이터 자동 + PDF 는 관리자가 곡별 버튼으로 1회 대리 수신(B안)"이다. 사용자는 "파일도 크롤링으로 모으자"고 했다. 절충으로 다음을 **가정**하고 진행한다(사용자가 B안으로 바꾸면 수집 잡의 "파일 받기" 단계만 끄면 되도록 설계한다):

| 항목 | 결정 |
|---|---|
| 메타데이터 | 수집 잡이 자동 수집 (작품 페이지 HTML 1회 + 위키텍스트 1회, 2초 간격) |
| PDF | 수집 잡이 **곡당 "전체 악보" 상위 2개만** 자동 수신하되, **IMSLP 의 15초 대기를 우회하지 않고 그대로 기다린다**(파일당 최소 15초 + 요청 간 2초). 동시 1커넥션, 파일당 평생 1회, 식별 가능한 User-Agent(연락처 포함). 저작권 표기가 PD·CC0·CC-BY·CC-BY-SA 가 아닌 파일은 받지 않는다(정보만) |
| 예상 시간 | 곡당 약 1~2분 → 50곡 약 1시간. 기획서 F7 의 "천천히 가져옵니다" 안내 유지 |
| 개별 재수신 | 곡 편집의 "파일 받아오기" 버튼은 같은 규칙으로 1건씩 |
| 전환 스위치 | 관리자 수집 설정에 "파일도 함께 받기" 켜기/끄기(기본 켬). 끄면 B안과 동일 |
| IMSLP 연락 | 첫 배치 50곡 이후·확대 전에 사용자가 연락 여부 결정(8-10) |

> 보충(2026-09-06, 설계 반영): "전체 악보 상위 2개"는 **재배포 허용 표기(PD·CC0·CC-BY·CC-BY-SA)인 판본 중** 상위 2개다. NC/ND 판본이 상위여도 건너뛴다. 인기곡 정렬은 누적 다운로드 수 → 최근 등록 순으로 구현된다(기록 없는 곡끼리는 최근 등록순 — **§10-2 로 개정되고 §11-3 으로 최종 확정됐다. 최근 등록순은 더 이상 쓰지 않는다**).

## 10. 1차 수집 실데이터로 드러난 기획 오류와 개정 (2026-09-07, product-planner)

- **묶음 악보를 곡집 페이지로 계속 잡을 것인가** — 근본 해법은 "녹턴 2번"을 곡으로 따로 두는 것이다(IMSLP 에 개별 페이지가 있는 곡도 많다: 쿨라우 소나티네 Op.20 No.1, 쇼팽 왈츠 Op.64 No.1 등). 1차는 §10-3 의 수록곡 안내로 덮되, **2차의 첫 과제로 "곡집 → 개별 곡 분리"를 올려 둔다.** 지금 구조로는 "녹턴 2번만 3쪽짜리로 받고 싶다"는 가장 흔한 요구를 끝내 못 들어준다.

## 11. 3차 QA(비즈니스 시나리오) 결과에 대한 기획 판단 (2026-09-08, product-planner)

> 왜 이 절이 있는가: qa 3차 검증에서 **"계약(API 명세) 위반은 아니지만 제품으로 이상하다"** 로 분류된 4건이 나왔다.
> 계약대로 만들었는데 사용자(또는 관리자)가 이상하다고 느낀다면 **틀린 것은 계약이 아니라 기획**이다.
> 아래는 그 4건에 대한 기획 결론이다. 판단 기준은 하나다 — **취미·입시·레슨생(`00 §2`)이 이 화면에서 무엇을 하는가.**
> 각 항목은 위 본문에도 반영돼 있고, 인수 조건은 §6 "3차 QA 반영분"에 있다.

### 11-1. 관리자의 작업 목록은 곡 단위다 (결함 2)

**결정**
- '보완 필요'의 빠진 항목에 **"추천 판본의 한국 기준 저작권 판정이 확인 중"**을 추가한다. 판정이 "이용 제한"인 것은 세지 않는다.
- 목록(곡 목록 관리 필터) · 카운트(관리 홈 카드) · 곡 편집 상단 표시 **세 곳이 한 규칙을 공유**한다.
- "자동 판정만 되돌리기"는 판정만 되돌리고 추천 지정은 유지하되, **그 사실을 결과 안내 문구로 반드시 말한다.**

**왜 그렇게 정했나 (관리자 관점)**
1. '보완 필요'가 답해야 하는 질문은 **"이 곡을 사용자에게 열어 주려면 뭐가 남았나"** 다. 지금 규칙은 "필드가 비었나"만 물어서, **추천은 있는데 사용자는 못 받는 곡**이 답에서 빠진다. 관리자에게 그 곡은 다시 볼 계기가 사라진 곡이다.
2. 관리자의 목표는 §8-17 공개 기준 — **"50곡 중 35곡 이상 바로 받기 가능"**. 목표가 곡 단위 숫자인데 주 작업 목록이 판본 단위면 진척을 같은 단위로 볼 수 없다. 일감과 목표는 같은 단위로 세야 한다.
3. **판본 단위 대기함(§F6 저작권 판정 대기함)과 중복이 아니다.** 두 화면은 다른 질문에 답한다.
   - 대기함: "확인 중 판본 수천 건 중 다음에 뭘 처리하지?" — 판본을 빠르게 소화하는 자리(일괄 판정이 여기 있다)
   - 보완 필요: "곡 50개 중 아직 못 여는 게 뭐지?" — 곡을 하나씩 완성하는 자리
   같은 판본이 양쪽에 등장하는 것은 정상이다. 하나의 일을 두 방향에서 보는 것이지 두 번 하는 게 아니다.
4. **되돌리기가 되돌린 티가 나야 한다.** 관리자가 되돌리기를 누르는 이유는 "자동 판정이 못 미더워서 다시 보겠다"는 것이다. 그런데 눌러도 할 일 목록이 그대로면 "다시 볼 곡"을 찾을 방법이 없다. 되돌리기의 목적 자체가 달성되지 않는다.
5. 추천 지정을 함께 되돌리지 **않는** 이유: 추천은 판정과 별개의 선택이고, 관리자가 그 사이 손으로 바꾼 추천까지 날리면 되돌리기가 파괴적인 버튼이 된다. 다만 **버튼 이름과 안내 문구가 그 범위를 정확히 말해야** 한다 — "되돌리기"가 아니라 **"자동 판정만 되돌리기"**.

**사용자(일반) 영향**: 없다. 사용자 화면은 지금도 뱃지와 403 으로 올바르게 막고 있다. 이건 순수하게 **관리자 작업 흐름의 결함**이다.

### 11-2. 편곡·부분 범위는 막지 않고 드러낸다 (결함 3)

**결정** (세 가지를 모두 한다. 우선순위는 ① → ③ → ②)
1. **관리자 경고를 목록으로** — "저작권 확인 중" / "편곡이에요" / "N악장만 들어 있어요"가 **해당되는 대로 전부** 보인다. 지금처럼 하나만 보이면 관리자는 나머지를 모른 채 지정한다.
2. **검색 결과·작곡가 목록 항목에 한 줄** — "이 악보는 2악장만 들어 있어요" / "피아노 편곡 악보예요". §10-3 의 묶음 악보 문구와 **같은 자리·같은 줄**을 쓴다.
3. **파일 이름에 표기** — `베토벤 - 비창 소나타 (Op.13) 2악장.pdf`, `… 편곡.pdf`.
4. 곡 상태는 **READY 그대로**, 다운로드도 **연다**. 자동 지정 규칙은 지금처럼 "전체 악보 · 전곡"만.

**왜 세 곳 다인가 (사용자 관점)**
- senior-dev 는 "①만으로도 '모르고 지정'은 막힌다"고 봤다. 맞다. 그런데 우리가 막아야 하는 건 두 가지다.
  - **관리자가 모르고 지정하는 것** → ①로 막힌다.
  - **관리자가 알고 지정하는 것** → ①로 막히지 않는다. 그리고 실데이터에서 곡당 우리가 가진 파일은 2개뿐이라, **"편곡뿐이지만 없는 것보다 낫다"는 정당한 선택이 실제로 생긴다.** 그때 아무 표시가 없으면 **사용자만 모른다.**
- 사용자가 겪는 자리는 세 곳이고, 각각 다른 순간이다.
  - **받기 전(검색 결과)**: "비창 소나타"를 찾은 레슨생이 목록에서 고른다. 여기서 모르면 헛클릭한다. → ②
  - **받는 순간(곡 상세)**: 이미 §F3-3 에 "판본 종류 + 포함 범위"가 표시하기로 돼 있다. **기존 기획대로면 여기는 이미 보인다** — qa 가 확인해야 할 기존 항목이지 새 요구가 아니다.
  - **받은 뒤(파일 이름)**: 파일은 컴퓨터에 남아 몇 주 뒤 레슨 직전에 열린다. **그때 화면은 없고 파일 이름만 있다.** `베토벤 - 비창 소나타 (Op.13).pdf` 를 열었더니 5쪽짜리 2악장이면, 사용자는 우리를 "엉터리 파일을 주는 곳"으로 기억한다. → ③
- ②를 넣는 또 다른 이유: §10-3 이 이미 같은 자리에 **"'강아지 왈츠'가 들어 있는 악보"**(받는 게 찾은 것보다 **크다**)를 넣기로 했다. 이번 건은 반대 방향(**작거나 다르다**)이다. 같은 종류의 정보를 한쪽만 말하면 사용자는 "표시가 없으면 정확히 그 곡"이라고 학습한 뒤 배신당한다. **두 문구는 한 줄로 통합해 구현한다** — 새 필드 두 개가 아니라 하나다.
- **막지 않는 이유**: 못 받게 하면 사용자가 얻는 것은 0이다. 우리는 IMSLP 위에 얹는 레이어이지 검열자가 아니다. "정확히 알려주고 사용자가 고르게 한다"가 `00 §3` 문제 3·4 에 대한 우리 답이다.

### 11-3. 홈 인기곡은 순위표가 아니라 견본 진열대다 (결함 4, §8-15 흡수 확정)

**결정** — §2 F1 참조. 요약:
- **자격**: 준비 상태 "바로 받기 가능" **AND** 한국어 대표 제목 있음. 둘 다.
- **정렬**: 다운로드 수 → 큐레이션 노출 순서(`03` 곡 번호 1→50) → 가나다. **등록 시각 역순은 쓰지 않는다.**
- **폴백**: 모자란 칸만 준비 중 곡(한국어 제목 있는 것)으로. 0개면 영역 자체를 숨긴다.
- 영역 제목은 **"지금 바로 받을 수 있는 인기곡"**.

**왜 그렇게 정했나 (사용자 관점)**
1. **홈에 처음 온 사람이 묻는 것은 "여기 1등이 뭐냐"가 아니다.** 우리 서비스에 차트를 보러 오는 사람은 없다. 취미·레슨생이 홈에서 하는 일은 딱 하나 — **"여기 내가 받을 만한 게 있나"를 3초 안에 판단하는 것**이다. 그래서 이 자리는 순위표가 아니라 **견본 진열대**다. 진열대에 못 파는 물건을 놓지 않는다.
2. **"한국어 제목 없는 곡"이 1위인 상태는 서비스의 존재 이유를 첫 화면에서 부정한다.** 우리 한 줄 정의는 "한국어로 검색 → 바로 PDF"다(`00 §1`). 원어 제목만 뜬 항목은 사용자가 IMSLP 에서 겪던 바로 그 화면(`00 §3` 문제 1)이다.
3. **"열정 소나타(PREPARING)"가 1위인 상태는 "바로 받기"라는 약속을 첫 화면에서 깨뜨린다.** 뱃지로 "준비 중"이라 적어도, 홈 상단은 약속을 지키는 자리여야 한다.
4. **정렬 근거(다운로드 수)는 건드리지 않는다.** 우리가 손보는 것은 "누가 이 자리에 설 자격이 있는가"이지 "누가 더 인기 있는가"가 아니다. 실제 인기가 쌓이면 그대로 반영돼야 한다.
5. **고급 쏠림(10곡 중 9곡 ADVANCED)은 tie-breaker 로 풀린다.** `03` 의 곡 번호는 이미 **입문(1–2) → 초급(3–15) → 중급(16–35) → 고급(36–50)** 순이다. 다운로드가 전부 0인 초기에 그 순서를 쓰면 홈 첫 10칸이 자연히 입문·초급으로 채워진다. **난이도를 인위적으로 섞는 별도 규칙은 두지 않는다** — 큐레이션 순서 자체가 이미 그 판단을 담고 있고, 규칙이 둘이면 어느 쪽이 이겼는지 아무도 설명 못 한다.
   - 만약 데이터에 "큐레이션 노출 순서" 값이 없다면 → **senior-dev 에게 되돌린다.** 대안 tie-breaker: 난이도 오름차순(입문→초급→중급→고급) → 한국어 제목 가나다.
6. **홈이 비는 위험**: 자격 곡이 0개면 인기곡 영역을 통째로 숨긴다. "인기곡"이라 써 놓고 빈 자리를 남기는 것보다, 검색창과 작곡가 바로가기만 있는 홈이 낫다. 자격 곡이 10곡에 못 미치면 부족분만 준비 중 곡으로 채운다 — 이건 §10-2 에서 이미 정한 방향이고 여기서 유지한다.

### 11-4. 두 숫자는 다른 질문의 답이다 — 문구로 잇는다 (결함 10)

**결정**
- **작곡가 카드의 곡 수는 그대로 둔다** (필터·페이지와 무관). API 변경 없음.
- 카드 문구를 **"쇼팽 (Frédéric Chopin) — 등록된 곡 24개 모두 보기 →"** 로 바꾼다.
- 필터로 결과가 0건이고 **작곡가 카드가 정확히 1명일 때**, 빈 결과 안내에 한 줄을 붙인다: **"쇼팽의 곡은 10개 등록돼 있어요 — 조건 없이 모두 보기 →"**. **카드가 2명 이상이면 붙이지 않는다** (2026-09-11 designer 확정, `04` 개정 7 — 누구의 곡인지 모호해지고 줄이 늘어 더미가 된다. 그때는 카드마다 자기 출구가 이미 있다. 이 절은 처음부터 단일 작곡가 `쇼팽` 만 상정했으므로 결정을 뒤집는 게 아니라 빠져 있던 조건을 채운 것이다).
- 배치(카드를 빈 결과 위에 둘지 안내와 묶을지)는 **designer 판단**으로 넘긴다.

**왜 그렇게 정했나 (사용자 관점)**
1. 사용자가 `쇼팽 + 바로 받기 가능`으로 걸러 0건을 만났을 때 필요한 것은 두 가지다 — **"내가 잘못 친 게 아니다"라는 확인**과 **출구**. 작곡가 카드는 그 둘을 동시에 준다. **카드를 지우면 사용자는 0건 화면에 갇힌다.**
2. 숫자를 필터에 맞춰 0으로 바꾸면 카드는 정보가 아니라 **또 하나의 0**이 된다. 우리가 줄 수 있는 유일한 다음 행동(작곡가 페이지)을 스스로 지우는 셈이다.
3. 이상하게 느껴진 진짜 원인은 숫자가 아니라 **문구**다. "곡 10개"는 "이 결과에 10개"로 읽힌다. "등록된 곡 10개 모두 보기"는 **다른 질문의 답**임을 스스로 말한다. 고칠 것은 데이터가 아니라 말이다.
4. 필터별 곡 수로 바꾸면 카드의 뜻 자체가 바뀌고("작곡가 페이지에 가면 몇 곡"이 아니게 된다) 사용자가 카드를 눌렀을 때 보게 될 곡 수와 어긋난다 — **더 큰 거짓말이 된다.**

### 11-5. 다른 담당에게 넘기는 것 (되돌림)

## 12. senior-dev 기술 검토 후 되돌아온 2건의 결론 (2026-09-08, product-planner)

> 왜 이 절이 있는가: §10-6(파일명 작품번호 중복)과 §10-3(묶음 악보 "N곡 묶음")은 **"이렇게 보이면 안 된다"까지만 적혀 있고
> "그래서 정확히 어떻게 판정하는가"가 비어 있었다.** senior-dev 가 기술 검토를 마치고 그 빈칸을 기획으로 되돌렸다.
> 아래가 그 빈칸의 답이다. 판단 기준은 §11 과 같다 — **취미·레슨생이 이 자리에서 무엇을 하는가.**

| # | 되돌아온 것 | 결론 | 1차 포함 |
|---|---|---|---|
| 12-1 | 파일 이름에서 작품번호를 언제 생략하는가 | **괄호는 "제목이 말하지 않은 것"만 말한다.** 생략 조건 3가지 확정 | **포함** |
| 12-2 | "(전곡 기준)" / "N곡 묶음" 을 1차에 넣는가 | **"(전곡 기준)"만 넣는다.** "N곡 묶음"은 **2차로 미룬다** | 부분 포함 |

### 12-1. 파일 이름 — 괄호는 "제목이 말하지 않은 것"만 말한다

**결정** (본문 §2 F3-3 에 반영. §8-9 미결 해소)

파일 이름 `작곡가 한글 - 한국어 대표 제목 (작품번호).pdf` 는 그대로 두고, 다음을 더한다.

1. **빈 값은 원어로 대체한다** — 작곡가 한글 표기가 없으면 원어 표기, 한국어 대표 제목이 없으면 원어 제목.
2. **괄호를 통째로 생략하는 경우 3가지**
   - ① 작품번호가 없다 (`사티 - 짐노페디.pdf`)
   - ② **이름에 실제로 쓰인 제목** 안에 그 작품번호가 이미 들어 있다 (`쇼팽 - 녹턴 Op.9.pdf`). 대소문자·공백·마침표는 무시하고 비교하되, **다른 번호에 걸치면 안 된다**(제목의 `Op.10` 은 작품번호 `Op.1` 이 아니다)
   - ③ 작품번호가 여러 개이거나 그 안에 또 괄호가 있다 (`멘델스존 - 무언가 (전곡).pdf`, `바흐 - 안나 막달레나 바흐를 위한 음악 수첩.pdf`)
3. 제목이 담지 못한 것이 번호에 남아 있으면 **괄호는 그대로 둔다** (`쇼팽 - 녹턴 Op.9 (Op.9 No.2).pdf`).
4. 편곡·특정 악장 꼬리표(§11-2)는 괄호 생략 여부와 무관하게 그대로 붙는다.

**왜 그렇게 정했나 (사용자 관점)**

1. **파일 이름은 몇 주 뒤 레슨 직전에 열리는 마지막 안내다**(§11-2). 그 자리에서 사용자가 하는 일은 딱 하나 — **폴더에 쌓인 PDF 여러 개 중 오늘 필요한 것을 고르는 것**이다. 그 판단에 필요한 정보는 "누구 곡인가 · 무슨 곡인가 · 전곡인가"이고, `(Op.9)`가 두 번 적혀 있는 것은 그 판단에 **아무것도 보태지 않으면서 우리 서비스를 엉성하게 보이게 한다.** 42곡 중 11곡(26%)이면 "가끔 그런 파일"이 아니라 **네 개 중 하나**다.
2. **senior-dev 의 ⓑ(정규화 후 부분 문자열 포함)를 채택한다.** 이 규칙이 실제로 하는 일은 *"제목이 작품번호보다 자세하면 생략"* 인데, 사용자 말로 옮기면 **"괄호는 제목이 말하지 않은 것만 말한다"** 다. 파일 이름에서 괄호가 하는 일이 원래 그것이므로(월광 소나타가 여러 개일 때 `Op.27 No.2` 로 갈라 주는 것), 규칙과 목적이 일치한다.
3. **경계 ⓒ("제목 녹턴 Op.9" + "번호 Op.9 No.2" → 괄호가 남는다)를 그대로 받아들인다.** 같은 `Op.9` 가 두 번 보이지만 이건 §10-6 이 지적한 중복(`(Op.9)` 가 통째로 반복)과 **다른 것**이다 — 뒤의 괄호가 **범위를 좁혀 준다**(3곡 중 2번). 지우면 파일 이름만 보고 어느 곡인지 알 수 없게 되고, 그건 우리가 고치려던 것보다 나쁜 결과다.
   - 다만 **이 조합은 시드 50곡에 없다.** 곡 데이터가 어긋나야(전곡집 제목 + 단일곡 번호) 생기는 조합이므로, **실데이터에 나타나면 파일명 문제가 아니라 곡 정보 문제로 보고 기획에 되돌린다.**
   - "겹치는 부분만 잘라 `(No.2)` 로 만들자"는 대안은 **쓰지 않는다.** 규칙이 둘이 되면 어느 쪽이 이겼는지 아무도 설명할 수 없고(§11-3-5 와 같은 이유), 나오지도 않는 경우를 위해 규칙을 늘리는 것이다.
4. **③(번호 여러 개)을 함께 정한 이유**: 같은 조립 규칙에서 나오는 같은 종류의 사고다. 멘델스존 무언가 전곡은 지금 규칙대로면 `멘델스존 - 무언가 (전곡) (Opp.19b·30·38·53·62·67·85·102).pdf` 가 된다 — 중복은 아니지만 **사용자가 파일 이름을 읽지 못한다.** 하나만 골라 적으면 "Op.19b 만 든 악보"로 읽혀 더 나쁘다. 이 곡들은 제목("무언가 (전곡)", "안나 막달레나 바흐를 위한 음악 수첩")이 이미 무엇인지 다 말한다.
5. **①(번호 없음)을 명시한 이유**: 짐노페디·그노시엔느·엔터테이너·하농은 작품번호가 없다(`03` §1). 규칙에 안 적혀 있으면 `사티 - 짐노페디 ().pdf` 같은 빈 괄호가 나올 자리다.

### 12-2. "(전곡 기준)"은 넣고, "N곡 묶음"은 2차로 미룬다

**결정**

| 항목 | 1차 | 이유 한 줄 |
|---|---|---|
| **"(전곡 기준)"** — 난이도·쪽수 | **넣는다.** 묶음 악보(수록곡 안내가 있는 곡)의 난이도와 쪽수 **양쪽**에 걸린다. 한 줄에 나란히 있으면 **한 번만** 쓴다("고급 · 62쪽 (전곡 기준)") | 사용자를 실제로 다치게 하는 오해를 막는다 |
| **"N곡 묶음"** — 곡 수 표시 | **1차에서 뺀다. 2차.** `03` §10 의 38곡 숫자·단위 표는 **작성하지 않는다** | 숫자가 사용자의 다음 행동을 바꾸지 않는데, 틀릴 자리는 세 군데다 |
| **값이 없는 곡** (수집·관리자 등록) | "(전곡 기준)"을 **붙이지 않는다**. 대신 **관리자가 곡 편집에서 수록곡 안내를 직접 입력**할 수 있게 한다(§3 F5-2 에 입력 항목 추가) | 시스템은 그 곡이 묶음인지 모른다. 아는 사람이 적게 한다 |

**왜 "(전곡 기준)"은 넣나 (사용자 관점)**

1. **이 표시가 막는 것은 오해가 아니라 포기다.** "달빛"을 찾아 들어온 레슨생이 **고급**만 보면 "나는 아직 못 치는 곡"이라고 판단하고 창을 닫는다. 실제로 달빛 단독은 중급이다(`03` #50). 우리가 한 사람의 잘못된 포기를 만든 것이다. 쪽수도 같다 — 62쪽은 달빛의 길이가 아니라 모음곡 4곡의 길이다.
2. **공짜라는 사실이 판단을 바꾸지는 않지만, 미룰 이유도 없앤다.** 필요한 값은 "이 곡이 묶음인가" 하나이고 그건 이미 있다(수록곡 안내). 새로 셀 것도, 새로 정할 것도 없다.
3. **난이도만 붙이고 쪽수를 빼면 사용자는 "쪽수는 이 곡 것"이라고 학습한다.** 두 숫자가 같은 함정을 갖고 있으므로 같은 꼬리표를 단다. 대신 같은 줄에서 두 번 반복하지는 않는다 — 한 번 읽고 둘 다에 적용하는 게 사람이 읽는 방식이다.

**왜 "N곡 묶음"은 미루나 (사용자 관점)**

1. **숫자가 사용자의 다음 행동을 바꾸지 않는다.** 검색 결과에서 이 한 줄을 본 사람이 하는 일은 "이건 곡 하나가 아니구나 → 눌러서 안을 본다"뿐이다. 그 행동은 "25곡 묶음"이든 "(전곡 기준)"이든 똑같이 일어난다. **그리고 눌러서 들어간 곡 상세에는 이미 정확한 문장이 있다** — "이 악보에는 25곡이 들어 있어요 — 2번 아라베스크 · …"(§F3-2, `03` §10, 38곡 전부 작성 완료). 숫자가 필요한 사람은 **한 번의 클릭으로 숫자보다 나은 것**을 받는다.
2. **내가 쓴 38건이 한 단위로 안 세어진다** — 이건 데이터 문제가 아니라 **내 기획의 문제**다.
   - **6건은 곡이 아니라 악장**이다 — #17·#18·#21·#36·#37 "3개 악장"(senior-dev 가 센 5건) + #20 "2개 악장". "월광 소나타 3곡 묶음"은 **틀린 말**이다. 악장은 이어서 한 곡을 이루는 것이지 3곡이 아니다.
   - #28 멘델스존은 "8권 48곡"으로 숫자가 둘이고, #15 평균율은 "프렐류드와 푸가가 이어서"로 숫자가 없다.
   - 즉 정확히 하려면 값이 **두 개**(개수 + 단위) 필요하고, 그러면 검색 결과 한 줄을 위해 시드 38줄을 새로 채우고 계약을 넓히게 된다. **1번의 결론(행동이 안 바뀐다)과 곱하면 값이 안 나온다.**
3. **값이 없는 곡이 만드는 오학습이 더 위험하다.** 수집·관리자 등록으로 들어온 묶음 곡에는 이 숫자가 없다. 그러면 화면에는 "3곡 묶음"이 붙은 곡과 아무것도 없는 곡이 섞이고, 사용자는 **"표시가 없으면 곡 하나"** 라고 학습한 뒤 배신당한다 — §11-2 에서 이미 한 번 확인한 실패 방식이다. "(전곡 기준)"도 같은 위험을 갖지만, 이쪽은 **관리자가 수록곡 안내 한 줄만 채우면 그 순간 복구된다**(그리고 그 한 줄은 어차피 곡 상세에 필요하다). 숫자·단위는 채워도 그 자리에서만 쓰이는 값이라 채울 이유가 관리자에게 없다.
4. **2차에 다시 볼 때는 다른 형태가 될 가능성이 높다.** `03` §10-10 에 이미 **"곡집 → 개별 곡 분리"**가 2차 첫 과제로 올라가 있다. 그게 되면 "녹턴 2번"이 곡으로 서고 "N곡 묶음"이라는 표시 자체가 필요 없어진다. **지금 38줄을 채우는 것은 2차에 지울 값을 만드는 일일 수 있다.**

**미루면서 남기는 것** — 2차에 이 판단을 다시 열 때 필요한 것은 값 두 개(곡 수 · 단위 `곡`/`악장`)라는 사실과, 그 표는 `03` §10 의 38줄 문장에서 사람이 읽어 만들어야 한다는 것이다(문장 파싱 불가 — senior-dev 확인). 이 문단이 그 기록이다.

## 13. 악기 구분 도입에 따른 이 문서의 위치 변경 (2026-09-10, product-planner)

> 사용자 요청: **상단에 피아노·바이올린·오케스트라 같은 구분을 두고, 구분별로 나중에 따로 사이트를 만든다. 일단은 피아노만.**
> 그리고 **검색은 통합검색보다 select 로 곡명/작곡가를 고르게.**
> 전체 정의는 **`docs/기획/04_악기구분과_검색기준_기획서.md`** 에 있다. 여기에는 **이 문서에 미치는 영향만** 적는다.

**이 문서의 위치가 바뀌었다.** `01` 은 이제 "서비스 전체"가 아니라 **"피아노 구분 안쪽"** 의 기획서다. 구분 탭·주소 구조·검색 기준 선택 같은 **바깥 껍데기**는 `04` 가 담당한다. 곡 상세·판본·추천·다운로드·파일 이름·저작권·관리자 흐름은 **하나도 바뀌지 않는다.**

| 13-1 | §0-2 1차 범위 | "피아노 독주곡만" → **"피아노 구분만 열려 있고, 바이올린·오케스트라 구분은 탭에 '준비 중'으로 보인다"**. 다른 편성의 곡·수집·판본은 그대로 범위 밖 |
