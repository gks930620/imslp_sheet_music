## 0. 이 문서가 왜 따로 있는가

`01` 은 "곡 하나를 찾아 받는" 비로그인 흐름의 문서이고, `04` 는 그 바깥 껍데기(구분·주소·검색 기준)다. 이번 요청은 **"돌아온 사람"** 의 문서다 — 피아노를 배우는 사람은 같은 곡을 몇 주씩 연습하므로 **한 번 찾은 곡을 다시 찾으러 온다.** 지금 제품은 그 사람에게 검색창밖에 주지 않는다. 세 기능은 전부 "내가 보던·받던·모아 둔 곡이 어디 있지"라는 한 질문에 대한 답이고, 그 답이 `01` 의 흐름(검색 → 상세 → 다운로드)을 **하나도 바꾸지 않은 채** 그 위에 얹힌다.

### 0-1. 확인한 사실 (2026-09-15, 기획이 조사한 것)

| # | 사실 | 이 문서에 미치는 것 |
|---|---|---|
| 1 | **즐겨찾기는 미구현**이다. 곡 상세의 "악장 안내" 줄 옆에 책갈피 모양 아이콘이 있지만 **장식**이지 기능이 아니다 | 사용자가 그걸 눌러 보려 할 수 있다 → 그 아이콘은 다른 모양으로 바꾼다(§8 충돌 6) |
| 2 | **다운로드 기록은 이미 있다**(관리 홈 "이번 달 다운로드"가 쓴다). 그런데 **누가 받았는지는 기록에 없고, 비로그인 다운로드도 전부 기록된다** | 이력 기능은 이 기록을 그대로 "내 것"으로 보여줄 수 없다. **로그인한 상태에서 받은 것부터** 내 것이 된다(§3-1). 기능 도입 전의 기록은 누구의 것도 아니다 |
| 3 | 다운로드는 클릭 1번이고(확인 창 없음, `01` §F3-3), 로그인 상태면 그 클릭에 이미 "누구인지"가 함께 간다 | **다운로드 사용감을 바꾸지 않고** 기록에 사람을 붙일 수 있다 — 확인 창·로그인 요구가 생기면 `01` 의 핵심 약속이 깨진다 |
| 4 | 로그인 화면은 "돌아갈 주소"를 받아 로그인 후 복귀시킨다(관리 화면 딥링크가 이미 쓴다). **회원가입을 거치면 그 주소가 끊긴다** | 즐겨찾기 → 로그인 → 복귀 흐름의 뼈대는 있다. 회원가입 경유는 §10 8-4 미결 |
| 5 | 회원은 `users`(로컬 / 카카오 / 구글), 역할 ADMIN·USER. 로그인·회원가입·마이페이지 화면은 **보일러플레이트 잔재**로 남아 있고 이 서비스에 맞게 정비된 적 없다(`01` §8-2 (a): 헤더 메뉴만 빼고 주소는 열림) | 마이페이지 잔재 처리는 §2-5 |
| 6 | 곡은 정확히 하나의 구분에 속한다(`04` §5). 1차에 열린 구분은 피아노뿐 | 즐겨찾기·받은 악보·최근 본 곡은 **곡에 붙는 것**이므로 자연히 구분에 속한다 → §5 |

### 0-2. 용어 (화면 전체에서 통일)

| 용어 | 뜻 | 화면에 이렇게 보인다 |
|---|---|---|
| **즐겨찾기** | 로그인한 사용자가 곡을 계정에 모아 두는 것. 기기가 바뀌어도 남는다 | 곡 상세의 "즐겨찾기" 버튼(별 모양). 켜지면 "즐겨찾기됨" |
| **받은 악보** | 로그인한 상태에서 PDF 를 받은 곡의 목록. 사용자 말로 "다운로드 이력" | 내 악보의 "받은 악보" 탭. **"이력"·"로그"라는 말은 화면에 안 나온다** |
| **최근 본 곡** | 이 브라우저에서 최근에 연 곡 상세 10곡. 로그인과 무관 | 홈의 "최근 본 곡" 영역 |
| **내 악보** | 즐겨찾기 + 받은 악보를 모은 화면. 로그인 필요 | 헤더 메뉴 "내 악보"(로그인 시, 기존 "마이페이지" 자리) |
| **다시 받기** | 받은 악보에서 그 곡의 PDF 를 다시 내려받는 것 | 받은 악보 항목의 버튼 |

### 0-3. 1차 범위

| 포함 | 제외 |
|---|---|
| 곡 상세의 즐겨찾기 켜기/끄기 (로그인) | 곡 카드(검색 결과·작곡가 상세·인기곡)의 즐겨찾기 버튼·표시(§1-3) |
| 비로그인이 즐겨찾기를 누르면 로그인 → **돌아와서 완성** | 즐겨찾기 폴더·메모·정렬 바꾸기 |
| 내 악보 화면(신규): 즐겨찾기 탭 · 받은 악보 탭 | "N명이 즐겨찾기" 같은 집계 표시 |
| 받은 악보: 로그인 상태에서 받은 곡 목록 + 다시 받기 | 받은 악보 삭제(§3-4), 기능 도입 전 기록의 소급 |
| 최근 본 곡: 홈에 10곡, 브라우저 저장, 지우기 | 최근 본 곡의 계정 동기화, 항목별 지우기 |
| 헤더 "마이페이지" → "내 악보" 교체 | 회원가입·마이페이지(계정 화면)·소셜 로그인 정비 — 사용자 별도 작업(④)·§10 |

### 0-4. 세 기능을 어떻게 묶는가 — 결정과 근거

**결정: "내 악보" 한 화면 = 즐겨찾기 + 받은 악보. 최근 본 곡은 내 악보가 아니라 홈에 둔다.**

| 기능 | 로그인 | 저장되는 곳 | 어디에 보이나 |
|---|---|---|---|
| 즐겨찾기 | **필요** | 계정 | 내 악보 › 즐겨찾기 탭 |
| 받은 악보 | **필요** | 계정 | 내 악보 › 받은 악보 탭 |
| 최근 본 곡 | **불필요** | 이 브라우저 | **홈** (내 악보에는 없다) |

왜 이렇게 나누나:
1. **즐겨찾기와 받은 악보는 같은 질문의 두 답이다** — "내가 챙겨 둔 곡"(의도적으로 모은 것)과 "내가 실제로 받은 곡"(행동의 기록). 둘 다 계정에 붙고, 둘 다 기기가 바뀌어도 남아야 뜻이 있다. 한 화면의 두 탭이면 헤더에 메뉴가 하나만 늘고, 사용자는 "내 것은 저기"라는 자리를 하나만 기억하면 된다.
2. **최근 본 곡은 계정의 것이 아니다.** 사용자가 "로그인 없이, 브라우저 저장"을 정했다. 로그인이 필요한 화면(내 악보) 안에 로그인 없이 되는 것을 넣으면, 비로그인 사용자에게 "내 악보" 메뉴를 보여 줘야 하고 그 화면은 3분의 1만 차 있다. 반대로 최근 본 곡이 하는 일은 **"다시 왔을 때 3초 안에 그 곡으로 돌아가기"** 이고, 다시 온 사람이 서는 자리는 홈이다. 기능을 그 일이 일어나는 자리에 둔다.
3. **최근 본 곡은 "모은 것"이 아니라 "지나온 자리"다.** 10곡, 오래된 것부터 밀려나고, 브라우저를 바꾸면 없다. 이런 것을 즐겨찾기와 나란히 두면 사용자는 둘의 차이("왜 이건 다른 폰에서 안 보이지?")를 설명 들어야 한다. 자리를 다르게 두면 설명이 필요 없다.
4. **홈의 "검색창 하나가 주인공" 원칙(`01` §F1)은 지킨다.** 최근 본 곡은 **있을 때만** 보이고(첫 방문 홈은 지금과 한 글자도 안 다르다), 검색창 아래에 놓이며, 인기곡보다 크지 않다(§4).

## 1. 기능: 즐겨찾기

### 1-1. 사용자 흐름 (로그인 상태)

1. 곡 상세를 연다 → 곡 정보 영역(제목 근처)에 **"즐겨찾기"** 버튼이 보인다. 지금 이 곡이 즐겨찾기돼 있으면 **"즐겨찾기됨"** 으로 채워진 별이 보인다.
2. 누른다 → **즉시** "즐겨찾기됨"으로 바뀐다. 확인 창·화면 이동·안내 팝업 없음. (누르는 순간 바뀌고, 저장이 실패하면 그때 되돌린다 — §7)
3. 다시 누른다 → 즐겨찾기가 풀린다. 역시 즉시.
4. 헤더 **"내 악보"** → 즐겨찾기 탭에 방금 넣은 곡이 **맨 위**에 있다(최근에 넣은 순).
5. 즐겨찾기는 계정에 저장된다 — **새로고침해도, 다른 기기에서 같은 계정으로 열어도** 같은 상태다.

**"즐겨찾기" 버튼은 "PDF 받기"를 밀어내지 않는다.** 곡 상세의 주인공은 여전히 추천 판본 카드와 다운로드 버튼 하나다(`03_곡상세` 머리말). 즐겨찾기 버튼은 그 위 곡 정보 영역에 **보조 버튼**으로 놓이고, 다운로드 버튼과 같은 크기·같은 색으로 나란히 서지 않는다. 정확한 자리·모양은 designer 몫이되, **모바일 첫 화면(스크롤 전)에 보여야 한다** — 스크롤해야 보이는 즐겨찾기는 없는 것과 같다.

### 1-2. 비로그인이 눌렀을 때 — 로그인에 갔다가 **돌아와서 완성된다**

**원칙: 즐겨찾기 버튼은 비로그인에게도 보인다.** 숨기면 "이 서비스엔 즐겨찾기가 없구나"로 끝나고, 로그인할 이유가 사용자에게 전달되지 않는다. 눌렀을 때 무슨 일이 일어나는지가 전부다.

1. 비로그인으로 곡 상세에서 "즐겨찾기"를 누른다 → **로그인 화면**으로 이동. 그 화면에 **왜 여기 왔는지 한 줄**이 보인다: "즐겨찾기는 로그인하면 쓸 수 있어요" 취지(문구는 designer).
2. 아이디·비밀번호 또는 카카오·구글로 로그인한다 → **원래 곡 상세로 돌아온다.** 그리고 **그 곡이 이미 "즐겨찾기됨" 상태**이고, "즐겨찾기에 넣었어요" 취지의 짧은 안내(토스트)가 한 번 보인다. **다시 누를 필요가 없다.** 사용자가 한 행동은 하나("이 곡 즐겨찾기")이고 로그인은 그 중간에 끼어든 절차일 뿐이다 — 돌아와서 또 눌러야 하면 절차가 행동을 잡아먹은 것이다.
3. 로그인 화면에서 **"이전 페이지로 돌아가기"** 또는 브라우저 뒤로 가기 → 곡 상세로 돌아온다. 즐겨찾기는 **되어 있지 않다.** 아무 안내도 없다.
4. 돌아온 뒤 **새로고침해도** 즐겨찾기는 한 번만 된다 — "완성"이 두 번 일어나 다시 풀리는 일이 있으면 안 된다. 어떻게 기억하고 한 번만 쓰는지는 senior-dev 몫(§11).
5. 로그인해 보니 그 곡이 이미 즐겨찾기돼 있었다(다른 기기에서 넣어 둠) → 그냥 "즐겨찾기됨"으로 보인다. **(2026-09-20 확정)** 안내 문구는 가르지 않는다 — "새로 넣었는지"와 무관하게 `즐겨찾기에 넣었어요` 하나다(`09` §6 P2). 계약에 "새로 넣었는지" 필드를 요구하지 않기 위한 선택이기도 하다.

**막다른 화면 금지 체크** — 이 흐름에서 사용자가 서는 화면은 곡 상세 → 로그인 → 곡 상세 뿐이다. 홈으로 튕기거나(`01` §7 의 "복귀 안 되면 홈" 폴백은 여기서는 **결함**이다), 로그인 후 내 악보로 가거나, 빈 화면에 서는 경우가 없어야 한다.

**로그인 상태가 아직 확인되지 않은 순간에 눌렀을 때** (화면이 막 열려 헤더 닉네임 자리에 "…"가 있는 동안) — 로그인 화면으로 보내지 않는다. 확인이 끝난 뒤 그 상태로 처리한다. 로그인돼 있는 사람을 잠깐의 로딩 때문에 로그인 화면으로 보내면 "나 로그인했는데?"가 된다.

**세션이 조용히 풀린 상태**(로그인한 줄 알았는데 서버가 모른다) → 저장이 거부되면 §1-2 1번과 같이 로그인 화면으로 가고, 돌아와서 완성된다. 이때 헤더도 비로그인 상태로 바뀌어야 한다 — 헤더는 로그인이라 하고 즐겨찾기는 안 되는 화면은 결함이다.

### 1-3. 어디서 켜고 끄나 — **곡 상세와 내 악보, 두 곳뿐**

| 자리 | 켜기 | 끄기 |
|---|---|---|
| 곡 상세 | O | O (같은 버튼) |
| 내 악보 › 즐겨찾기 탭 | — | O ("즐겨찾기 해제") — 누르면 **즉시 목록에서 빠지고**, 잠깐 **"되돌리기"** 가 보인다(토스트). 되돌리기를 누르면 제자리로 돌아온다. 확인 창은 없다 |
| 곡 카드 (검색 결과·작곡가 상세·홈 인기곡·같은 작곡가의 다른 곡) | **없다** | **없다** |

왜 카드에 두지 않나: 곡 카드는 **카드 전체가 곡 상세로 가는 링크**다(`00_공통` §3-2). 그 위에 누르는 것을 하나 더 얹으면 모바일에서 "상세로 가려다 즐겨찾기가 켜지는" 오터치가 생기고, 카드마다 별이 붙으면 목록이 시끄러워진다. 그리고 사용자가 "이 곡이다"라고 정하는 자리는 미리보기·쪽수·판본을 본 **곡 상세**다. 카드에서 즐겨찾기하는 건 아직 안 본 곡을 찜하는 것이다. 카드에 "즐겨찾기됨" 표시만 두는 것도 1차에서 뺀다(§10 8-6) — 목록이 사용자마다 달라 보이기 시작하는 첫 지점이라 신중하게 연다.

왜 내 악보에서 해제에 "되돌리기"를 두나: 목록에서 누르는 해제는 오터치가 잦고(항목이 링크·버튼이 섞인 줄이다), 눌린 곡은 목록에서 **사라지므로** 사용자가 다시 찾아 넣으려면 검색부터 해야 한다. 확인 창은 되돌릴 수 있는 행동에 너무 무겁다 — 즉시 실행하고 잠깐 되돌릴 길을 둔다.

### 1-4. 무엇을 즐겨찾기할 수 있나

- **곡** 단위다(판본이 아니다). 사용자가 모으는 건 "월광 소나타"이지 "판본 #301"이 아니다(`01` ERD 다운로드 원장의 논리와 같다).
- **준비 상태와 무관하게 된다.** "준비 중"·"이용 제한"·"확인 중" 곡도 즐겨찾기할 수 있다 — 다운로드 버튼이 없어도 즐겨찾기 버튼은 있다. 이건 예외가 아니라 **주된 쓰임 중 하나**다: "받고 싶은데 아직 안 열린 곡을 찜해 두고, 나중에 열리면 받는다." 즐겨찾기 탭의 항목은 다른 곡 목록처럼 **지금의 상태 뱃지**를 보이므로, 준비 중이던 곡이 열리면 그 자리에서 뱃지가 사라진 것을 본다.
- 즐겨찾기한 곡을 관리자가 **숨기면** 즐겨찾기 탭에서 **보이지 않고 숫자에도 안 센다.** 숨김을 풀면 다시 나온다 — 즐겨찾기가 지워진 게 아니라 곡이 잠시 안 보이는 것이다(`01` §F2-6 "숨김 곡은 사용자 화면 어디에도 안 나온다"와 같은 규칙). 곡이 **삭제**되면 즐겨찾기도 함께 없어진다.
- 즐겨찾기 개수 상한은 1차에 두지 않는다(§10 8-5).

## 2. 기능: 내 악보 (신규 화면)

### 2-1. 진입과 구성

1. 로그인 사용자의 헤더에 **"내 악보"** 메뉴가 있다(지금 "마이페이지"가 있는 자리, `00_공통` §2-1). 비로그인에게는 이 메뉴가 없다(지금처럼 "로그인" 버튼만).
2. 누르면 → **내 악보** 화면. 위에 탭 두 개: **즐겨찾기 (N)** · **받은 악보 (N)**. 처음 열면 **즐겨찾기 탭**이다(사용자가 ①로 꼽은 것이고, "모은 것"이 "지나온 것"보다 앞이다).
3. 탭마다 **자기 주소**가 있다 — 새로고침·공유·뒤로 가기에서 탭이 유지된다(이 서비스의 주소 원칙, `04` §4-5 와 같다). 주소 모양은 senior-dev(§11) — 요구는 **구분 아래**일 것(§5).
4. 화면에는 **구분 바**가 보이고 현재 구분(피아노)이 선택돼 있다. 헤더 "내 악보"는 활성 표시.
5. 비로그인이 내 악보 주소로 직접 들어오면 → 로그인 화면("내 악보는 로그인하면 볼 수 있어요" 취지 한 줄) → 로그인 후 **내 악보로** 돌아온다(관리 화면 딥링크 복귀와 같은 방식, `01` §3 공통 4).
6. 내 악보에서 로그아웃하면 → 홈(기존 로그아웃 동작 그대로).
7. 관리자(ADMIN)도 같은 계정 기능을 쓴다. 관리 화면 쪽에는 아무것도 생기지 않는다(`04` §3-6).

### 2-2. 즐겨찾기 탭

- 항목: 다른 곡 목록과 **같은 곡 카드**(한국어 제목·원어 제목·작곡가·작품번호·난이도·쪽수·상태 뱃지·"(전곡 기준)"·범위 한 줄 — `01` §F2-5 의 구성 그대로. 별칭 일치 줄만 없다). 누르면 곡 상세.
- 항목 오른쪽에 **"즐겨찾기 해제"** (§1-3). 문구·모양은 designer — 단 카드 링크와 겹쳐 오터치되지 않게.
- 정렬: **최근에 넣은 순**(맨 위가 방금 넣은 것). 정렬 바꾸기·필터는 없다.
- 20곡씩 페이지 이동(기존 부품).
- 탭의 숫자 (N) = 지금 보이는 곡 수(숨김 곡 제외).

### 2-3. 받은 악보 탭 — §3

### 2-4. 빈 상태 (빈 표를 두지 않는다)

| 탭 | 보이는 것 | 출구 |
|---|---|---|
| 즐겨찾기 0곡 | "아직 즐겨찾기한 곡이 없어요 — 곡 상세에서 ☆ 즐겨찾기를 누르면 여기 모여요" | "인기곡 보러 가기" → 홈 |
| 받은 악보 0곡 | "아직 받은 악보가 없어요 — **로그인한 상태에서** 받은 악보가 여기 남아요" | "인기곡 보러 가기" → 홈 |

받은 악보의 빈 안내에 "로그인한 상태에서"를 꼭 넣는 이유: 기능 도입 전이나 비로그인으로 받은 사람이 "분명 받았는데 왜 없지?"에서 멈추지 않게 — §3-1.

### 2-5. 기존 마이페이지 잔재는 어떻게 하나

**결정: 헤더의 "마이페이지" 링크를 "내 악보"로 바꾼다. 기존 마이페이지 화면(`/mypage`)은 주소로는 열리되 헤더에서 링크하지 않는다** (`01` §8-2 (a) 와 같은 처리 — 지우지 않고 메뉴만 뺀다).

왜 합치지 않나:
- 지금 마이페이지가 보여주는 것(아이디·닉네임·이메일·로그인 제공자)은 **이 서비스에서 사용자가 할 일이 하나도 없는 정보**다. 닉네임은 헤더에 이미 있다. 비밀번호 변경·탈퇴·소셜 연결 같은 **계정 관리**는 사용자가 따로 손보는 영역(④)이고 이번 범위 밖이다.
- **계정은 구분을 넘고, 내 악보는 구분 안에 있다**(§5). 관리 화면을 구분 밖에 둔 것(`04` §3-6)과 같은 논리로, 나중에 계정 화면이 필요해지면 **구분 밖 화면으로 따로** 둔다. 지금 내 악보에 계정 정보를 섞으면 사이트를 나눌 때 그 줄이 갈 곳을 잃는다.
- 그래서 내 악보 화면에는 **계정 정보를 넣지 않는다.** 제목은 "내 악보" 고정이다. **(2026-09-20 확정)** 닉네임을 곁들이는 것을 designer 재량으로 열어 뒀으나 닫는다 — 닉네임은 이미 헤더에 있고(같은 화면 안에서 두 번 보일 이유가 없다), h1 은 "지금 어느 화면인가"만 말하면 된다. 이 결정으로 h1 도 §5-5(계정 정보 미포함) 원칙을 예외 없이 따른다.

회원가입 화면(`/signup`)도 마찬가지로 주소만 남긴다. 다만 §1-2 의 복귀 흐름이 회원가입을 거치면 끊기는 문제는 §10 8-4 로 사람에게 올린다.

## 3. 기능: 받은 악보 (다운로드 이력)

### 3-1. 무엇이 기록되나 — **로그인한 상태에서 받은 것만**

| 상황 | 받은 악보에 남나 | 인기곡 순위·관리 홈 다운로드 수에 드나 |
|---|---|---|
| 로그인 상태에서 곡 상세 "PDF 받기" | **남는다** | 든다 |
| 로그인 상태에서 "다른 판본"의 PDF 받기 | **남는다** | 든다 |
| 로그인 상태에서 받은 악보의 "다시 받기" | **남는다**(받은 날짜가 갱신된다) | 든다 |
| 비로그인으로 받기 | **안 남는다** — 누구의 것도 아니다 | 든다(지금과 같다) |
| **이 기능이 들어오기 전**에 받은 것 | **안 남는다** — 누가 받았는지 기록이 없다(§0-1 2) | 이미 들어 있다 |
| 받기 실패(파일 없음·서버 오류) | 안 남는다 | 안 든다(기존 규칙) |

- **다운로드 사용감은 바뀌지 않는다.** 클릭 1번, 확인 창 없음, "이력에 남길까요?" 같은 물음 없음. 로그인해 있으면 조용히 남고, 아니면 조용히 안 남는다.
- **비로그인 다운로드를 나중에 로그인한 계정에 붙이지 않는다.** 같은 브라우저라도 안 한다 — 도서관 컴퓨터에서 받은 남의 기록이 내 계정에 붙는 사고보다 "안 남는 것"이 낫다.
- 다른 사용자의 받은 악보는 어떤 주소로도 볼 수 없다. 관리자도 "누가 뭘 받았나"를 보는 화면은 없다(관리 홈은 지금처럼 **합계**만).

### 3-2. 목록이 보여주는 것 — **곡 단위 한 줄**

받은 악보는 영수증 더미가 아니라 **선반**이다. 사용자의 질문은 "내가 받았던 그 곡"이지 "몇 시에 몇 번 받았나"가 아니다.

- **같은 곡을 여러 번 받아도 한 줄.** 줄에는 **가장 최근에 받은 날짜**가 보인다("9월 12일 받음" 취지, 오늘이면 "오늘" — 표기는 designer, 사용자 지역 시각).
- 항목 구성: 곡 카드(§2-2 와 같다) + 받은 날짜 + 버튼 **"다시 받기"**.
- 정렬: **최근에 받은 순.** 20곡씩 페이지 이동.
- 같은 곡의 다른 판본을 각각 받았어도 한 줄이며, "다시 받기"는 **가장 최근에 받은 판본** 기준이다(§3-3).
- 관리자가 숨긴 곡은 안 보이고 숫자에 안 센다(숨김 해제 시 복귀). 삭제된 곡은 사라진다.

### 3-3. "다시 받기"는 무엇을 주나

**원칙: 그때 받았던 그 판본을 준다. 그 판본을 못 주게 됐으면 그 사실을 말하고 지금 추천 판본으로 안내한다.**

| 그때 받은 판본의 지금 상태 | 항목에 보이는 것 | 누르면 |
|---|---|---|
| 그대로 있고, 파일 있고, "한국에서 자유 이용 가능" | **"다시 받기"** 버튼 | 그 판본 PDF 가 클릭 1번으로 내려온다(파일 이름 규칙 `01` §F3-3 그대로). 다운로드 수 +1, 받은 날짜 갱신 |
| 위와 같은데, **지금 추천 판본이 그 판본과 다르다** | "다시 받기" 버튼 + 한 줄: **"지금 추천 판본은 이것과 달라요 — 곡 보기"** | 다시 받기는 그 판본. "곡 보기"는 곡 상세(거기서 지금 추천을 본다) |
| 판본이 **삭제**됐거나, 파일이 없어졌거나, 판정이 **"이용 제한"·"확인 중"** 으로 바뀜 | "다시 받기" 대신 **"그때 받은 악보는 지금 받을 수 없어요"** + ① 지금 추천 판본이 바로 받기 가능하면 **"지금 추천 판본 받기"** 버튼 ② 아니면 **"곡 보기"** 링크 | ① 추천 판본 PDF 내려옴(기록·수 갱신) ② 곡 상세(거기서 뱃지·IMSLP 링크를 본다) |

왜 "그때 그 판본"인가:
- 사용자가 다시 받는 이유는 대부분 **파일을 잃어서**(폰을 바꿨다, 지웠다)다. 그 사람이 원하는 건 **연습하던 그 악보**다 — 쪽수·손가락 번호·악장 위치가 같은 것. 조용히 다른 판본을 주면 "왜 페이지가 다르지?"가 된다.
- 그런데 추천이 바뀐 데는 이유가 있을 수 있다(더 좋은 스캔, 혹은 잘못된 판본을 고침 — `01` §F6-4 의 위험). 그래서 **막지 않고 드러낸다**(`01` §11-2 와 같은 태도): 같은 파일을 주되, 추천이 달라졌다는 사실을 한 줄로 말하고 곡 상세로 가는 길을 둔다. 고르는 건 사용자다.
- "이용 제한"으로 바뀐 판본은 **어디서도 주지 않는다** — 곡 상세가 못 주는 것을 받은 악보가 주면 저작권 게이트에 구멍이 하나 더 생긴다(`02_API` §3-4 "유일한 공개 경로"의 논리). 이때 문구는 이유를 나열하지 않는다("삭제됐어요 / 제한이에요"로 갈라 말하지 않는다) — 사용자에게 필요한 건 이유가 아니라 **다음 행동**이고, 이유는 곡 상세의 뱃지가 이미 말한다.

### 3-4. 지우기는 없다 (1차)

받은 악보에는 항목 삭제·전체 삭제를 **두지 않는다.** 이유: ① 이 목록은 "있었던 일"의 기록이고, 내용은 퍼블릭 도메인 악보라 감출 이유가 약하다 ② 곡 단위 한 줄이라 20곡/페이지면 어지럽지 않다 ③ 삭제를 두면 "지웠는데 다시 받으면 또 생기나"·"인기곡 집계에서도 빠지나" 같은 설명거리가 생긴다. 사용자가 원하면 §10 8-3 으로 연다 — 그때는 "내 목록에서만 숨김"이지 집계에서 빼는 것은 아니다.

## 4. 기능: 최근 본 곡

### 4-1. 사용자 흐름

1. 곡 상세를 연다(로그인 여부 무관) → 그 곡이 이 브라우저의 "최근 본 곡"에 **맨 앞**으로 들어간다. 화면에는 아무 변화도 없다(안내 없음).
2. 홈으로 온다 → 검색창 아래, 인기곡 위에 **"최근 본 곡"** 영역. 방금 본 곡이 맨 위. 항목은 인기곡과 같은 모양(순위 숫자 없이 제목·작곡가·난이도·상태 뱃지). 누르면 곡 상세.
3. 영역 제목 옆에 **"지우기"** → 누르면 확인 창 없이 **즉시 영역이 사라진다.** 다음에 곡 상세를 열면 다시 생긴다.
4. 한 번도 곡 상세를 연 적 없는 브라우저(첫 방문·시크릿 창·지운 직후) → **영역 자체가 없다.** 빈 제목·빈 자리도 없다. 즉 **첫 방문 홈은 지금과 똑같다.**

### 4-2. 규칙

| 항목 | 규칙 |
|---|---|
| 몇 개 | **10곡.** 11곡째를 열면 가장 오래된 곡이 빠진다. 홈에는 있는 만큼 전부(최대 10) 보인다 — 따로 "더 보기"가 없다 |
| 무엇이 "본" 것인가 | **곡 상세가 정상으로 열린 것.** 없는 곡·숨김 곡(404)은 들어가지 않는다. 검색 결과·작곡가 상세를 훑어본 것은 아니다 |
| 같은 곡 다시 열면 | 맨 앞으로 올라온다. **두 번 나오지 않는다** |
| 어디에 저장 | **이 브라우저.** 브라우저를 닫아도 남고, **로그아웃해도 남고**, 로그인해도 계정으로 옮겨지지 않는다. 다른 기기에는 없다 |
| 보이는 정보 | 저장한 순간의 것이 아니라 **지금의 것** — 제목이 바뀌었으면 바뀐 제목, 준비 중이던 곡이 열렸으면 뱃지 없음. 곡 목록 어디서나 같은 규칙(`01` §F2-5)이다 |
| 내려간 곡 | 관리자가 숨기거나 지운 곡은 **보이지 않는다**(눌러서 404 를 만나지 않는다). 숨김이 풀리면 다시 보인다. 어떻게 확인하는지는 senior-dev(§11) — 요구는 "홈에 보이는 최근 본 곡은 전부 눌러서 열린다"이다 |
| 저장 자체가 안 되는 브라우저 | (저장을 막아 둔 환경) 기능이 **조용히 없다.** 오류 문구 없음 |
| 지우기 | 전체만. 항목별 지우기는 없다 — 10곡짜리 흘러가는 목록에 항목 관리 기능을 붙이면 목록보다 기능이 커진다 |
| 관리자 | 관리자도 곡 상세를 열면 같은 브라우저 규칙으로 들어간다. 특별 취급 없음 |

**"지우기"가 필요한 진짜 이유** — 최근 본 곡은 로그아웃해도 남는다. 학원·도서관의 공용 컴퓨터에서 "내가 뭘 봤는지"가 다음 사람 홈에 남는다. 지우기는 편의가 아니라 그 한 줄을 없앨 수단이다. 그래서 확인 창 없이 한 번에 지운다.

### 4-3. 왜 홈에 두고 내 악보에 두지 않나 — §0-4 참고. 요약: 로그인 없이 되는 것을 로그인 필요한 화면에 넣지 않는다. 그리고 다시 온 사람이 서는 자리가 홈이다.

### 4-4. `04` §1-4 "보이지 않는 곳에 기억하지 않는다"와의 정합

`04` §1-4 는 **"지금 어느 구분인가"를 쿠키·브라우저 저장소로 기억하지 말라**는 요구다 — 같은 주소가 사람마다 다른 **구분**을 보이면 링크 공유가 깨지기 때문이다. 최근 본 곡은 이것과 다르다:
- **주소가 가리키는 것은 변하지 않는다.** `/piano` 는 누구에게나 피아노 홈이고, 검색창·인기곡·작곡가는 누구에게나 같다. 최근 본 곡은 그 위에 얹힌 **그 사람만 보는 선반**이며, 링크를 받은 사람은 그 선반이 없을 뿐(또는 자기 선반이 있을 뿐) 같은 화면을 본다.
- 구분 자체를 기억하지 않는다. 기억하는 것은 **"어떤 곡을 봤나"** 이고, 곡마다 구분이 붙어 있으므로 피아노 홈에는 피아노 곡만 보인다(§5). 바이올린 곡을 봤다고 피아노 홈이 바이올린으로 바뀌는 일은 없다.
- 그래서 §9 8-E 10 을 둔다: **시크릿 창에서 같은 주소를 열면 최근 본 곡 줄만 없고 나머지는 같다.**

## 5. 악기 구분과의 관계 (`04` §3 적용)

**결론: 내 악보(즐겨찾기·받은 악보)도 최근 본 곡도 "구분 안의 것"이다. 계정은 하나(구분 밖)이지만, 목록은 구분마다 따로 있다.**

| # | 요구 | 왜 |
|---|---|---|
| 5-1 | **내 악보 주소는 구분 아래에 있다** (`/piano/…`). 주소만 보고 "피아노 구분의 내 악보"임을 안다 | `04` §3-1·3-2 와 같다. 즐겨찾기·받은 악보는 **곡에 붙는 것**이고 곡은 정확히 하나의 구분에 속한다. 나중에 피아노를 다른 사이트로 옮기면 **피아노 즐겨찾기가 주소째 따라간다** |
| 5-2 | **피아노 내 악보에는 피아노 곡만** 보인다. 바이올린 구분이 열리면 `/violin/…` 의 내 악보에 바이올린 즐겨찾기가 보이고, 피아노 쪽에는 안 보인다 | `04` §5 의 검색·작곡가 목록과 같은 규칙 |
| 5-3 | **여러 구분의 즐겨찾기·받은 악보를 한꺼번에 보는 화면은 만들지 않는다** | `04` §3-3 — 나누는 순간 갈 곳이 없어진다. 1차에는 피아노뿐이라 잃는 것이 없다 |
| 5-4 | 헤더 **"내 악보"는 현재 구분의 내 악보로** 간다(작곡가 메뉴와 같은 규칙, `00_공통` §8). 구분이 없는 화면(로그인·관리·준비 중)에서는 기본 구분(피아노) | 탭이 곧 사이트가 될 때 메뉴가 그대로 그 사이트의 메뉴가 된다 |
| 5-5 | **계정 정보는 내 악보에 넣지 않는다** — 계정 화면이 필요해지면 구분 밖에 따로(§2-5) | 계정은 구분을 넘는다. 관리 화면을 구분 밖에 둔 것과 같은 이유(`04` §3-6) |
| 5-6 | **최근 본 곡도 구분별.** 피아노 홈에는 피아노 곡만. 브라우저에 저장하되 곡의 구분을 함께 기억한다 | §4-4. 홈은 구분의 홈이다 |
| 5-7 | 준비 중 구분(`/violin`)에는 내 악보 하위 주소가 없다(다른 하위 주소와 같이 찾을 수 없는 페이지). 그 화면에서 헤더 "내 악보"는 피아노 내 악보로 | `04` §1-3 의 준비 중 화면 규칙 유지 |
| 5-8 | 관리 화면에는 즐겨찾기·내 악보 관련 요소가 없다 | `04` §3-6 |

**나중에 사이트가 나뉠 때 내 즐겨찾기는 어디로 가나** — 피아노 곡의 즐겨찾기·받은 악보는 **피아노 사이트로** 간다(5-1). 계정을 두 사이트가 공유할지(한 번 로그인으로 양쪽), 따로 둘지는 **그때 사람이 정한다**(§10 8-7) — 지금 지켜야 할 것은 "어느 구분의 것인지가 항상 분명하다"뿐이고, 그건 곡의 구분이 보장한다. 이걸 지키면 분리는 **재분류가 아니라 필터**다.

## 9. 인수 조건 (qa 체크리스트)

> **번호 규칙** — `04` §8 과 같다. 각 항목 앞의 숫자가 이름이다(예: `8-D 7`). 이후 개정에서 **번호를 끼워 넣지 않고** 각 절 맨 뒤에 붙인다.
> **전제**: 8-B 5 는 사용자의 별도 작업(④ 카카오·구글 로컬 동작)이 끝난 뒤 검증한다. 그 전에는 "보류"로 두고 결함으로 적지 않는다.

### 8-A. 즐겨찾기 — 곡 상세 (8)
- [ ] **1.** 로그인 상태로 곡 상세를 열면 곡 정보 영역에 "즐겨찾기" 버튼이 보이고, 누르면 **즉시** "즐겨찾기됨" 상태(채워진 별 + 글자)로 바뀌며 확인 창·화면 이동이 없다.
- [ ] **2.** 그 상태에서 다시 누르면 즐겨찾기가 풀린다. 역시 확인 창 없음.
- [ ] **3.** 즐겨찾기한 뒤 **새로고침해도, 다른 브라우저에서 같은 계정으로 로그인해 열어도** "즐겨찾기됨"이다 (계정에 저장된다 — 브라우저 저장이 아니다).
- [ ] **4.** "준비 중"·"한국에서 이용 제한"·"저작권 확인 중" 곡도 즐겨찾기 버튼이 있고 켜진다 (다운로드 버튼이 없어도).
- [ ] **5.** "PDF 받기"는 여전히 화면에서 가장 큰 버튼 하나이고, 즐겨찾기 버튼이 그것과 같은 크기·색으로 나란히 서지 않는다. 모바일(360px)에서 스크롤 없이 즐겨찾기 버튼이 보인다.
- [ ] **6.** 즐겨찾기를 켜고 꺼도 다운로드가 일어나지 않고 관리 홈의 다운로드 수가 오르지 않는다.
- [ ] **7.** 네트워크를 끊고 즐겨찾기를 누르면 버튼이 **누르기 전 상태로 돌아가고** "즐겨찾기를 저장하지 못했어요" 취지의 안내가 보인다. 화면 이동 없음.
- [ ] **8.** 곡 상세 "악장 안내" 줄의 아이콘이 즐겨찾기 버튼의 아이콘(별)과도, 책갈피 모양과도 다르다.

### 8-B. 즐겨찾기 — 비로그인 흐름 (7)
- [ ] **1.** 비로그인으로 곡 상세를 열어도 "즐겨찾기" 버튼이 **보인다** (숨겨져 있지 않다).
- [ ] **2.** 비로그인이 누르면 로그인 화면으로 가고, 그 화면에 "즐겨찾기는 로그인하면 쓸 수 있어요" 취지의 한 줄이 보인다.
- [ ] **3.** 아이디·비밀번호로 로그인하면 **원래 곡 상세로 돌아오고**, 그 곡이 이미 "즐겨찾기됨"이며, "즐겨찾기에 넣었어요" 취지의 안내가 한 번 보인다. **다시 누르지 않아도 된다.** 홈이나 내 악보로 가지 않는다.
- [ ] **4.** 돌아온 뒤 **새로고침해도** "즐겨찾기됨" 그대로다 (완성이 두 번 일어나 풀리지 않는다).
- [ ] **5.** *(④ 완료 후)* 카카오 또는 구글로 로그인해도 3·4 와 같다.
- [ ] **6.** 로그인 화면에서 "이전 페이지로 돌아가기"를 누르면 곡 상세로 돌아오고 즐겨찾기는 **되어 있지 않다.** 브라우저 뒤로 가기도 같다.
- [ ] **7.** 로그인 상태 확인이 끝나기 전(헤더 닉네임 자리 "…")에 눌러도 로그인 화면으로 튕기지 않는다 — 로그인돼 있던 사용자는 즐겨찾기가 그대로 켜진다.

### 8-C. 내 악보 — 진입과 즐겨찾기 탭 (9)
- [ ] **1.** 로그인 상태의 헤더에 "내 악보" 메뉴가 보이고 **"마이페이지" 메뉴는 없다.** 비로그인 헤더에는 "내 악보"가 없다.
- [ ] **2.** "내 악보"를 누르면 내 악보 화면이 열리고 **즐겨찾기 탭**이 먼저 보이며, 탭에 "즐겨찾기 (N) · 받은 악보 (N)" 숫자가 있다.
- [ ] **3.** 즐겨찾기 탭에 곡이 **최근에 넣은 순**으로 보이고, 항목은 검색 결과와 같은 정보(제목·원어 제목·작곡가·작품번호·난이도·쪽수·상태 뱃지)를 보이며 누르면 곡 상세로 간다.
- [ ] **4.** 항목의 "즐겨찾기 해제"를 누르면 **즉시** 목록에서 빠지고 잠깐 "되돌리기"가 보인다. 되돌리기를 누르면 제자리로 돌아온다. 확인 창은 없다. 그 곡의 곡 상세를 열면 상태가 목록과 일치한다.
- [ ] **5.** 즐겨찾기가 0곡이면 "곡 상세에서 즐겨찾기를 누르면 여기 모여요" 취지의 안내와 홈으로 가는 출구가 보인다. 빈 표·빈 제목이 아니다.
- [ ] **6.** 21곡 이상 즐겨찾기하면 페이지 이동이 보이고 2페이지로 갈 수 있다.
- [ ] **7.** 관리자가 즐겨찾기한 곡을 숨기면 목록과 탭 숫자에서 빠지고, 숨김을 풀면 다시 나온다 (즐겨찾기가 지워진 게 아니다).
- [ ] **8.** 비로그인으로 내 악보 주소에 들어가면 로그인 화면으로 가고("내 악보는 로그인하면 볼 수 있어요" 취지), 로그인하면 **내 악보로** 돌아온다.
- [ ] **9.** 다른 계정의 즐겨찾기·받은 악보는 어떤 주소·값을 넣어도 볼 수 없다. 관리자 화면에도 "누가 뭘 즐겨찾기/받았나" 목록이 없다.

### 8-D. 받은 악보 (12)
- [ ] **1.** 로그인 상태에서 곡 상세 "PDF 받기"를 누르면 — 사용감은 전과 같이 **클릭 1번, 확인 창 없음** — 내 악보 "받은 악보"에 그 곡이 **바로** 보인다(맨 위).
- [ ] **2.** "다른 판본"의 PDF 받기도, 받은 악보의 "다시 받기"도 똑같이 기록된다.
- [ ] **3.** **비로그인으로 받은 것**은 그 뒤 로그인해도 받은 악보에 나오지 않는다. 그래도 관리 홈 다운로드 수와 인기곡 순위에는 든다.
- [ ] **4.** 이 기능이 들어오기 전에 받은 기록은 누구의 받은 악보에도 나오지 않는다 (**결함이 아니다** — 기록에 "누가"가 없었다).
- [ ] **5.** 같은 곡을 3번 받아도 받은 악보에는 **한 줄**이고, 가장 최근에 받은 날짜가 보인다. 목록은 최근에 받은 순.
- [ ] **6.** "다시 받기"를 누르면 확인 창 없이 **그때 받았던 그 판본**의 PDF 가 내려오고(파일 이름은 곡 상세에서 받을 때와 같은 규칙), 관리 홈 다운로드 수가 1 오르며, 받은 날짜가 갱신된다.
- [ ] **7.** 관리자가 그 곡의 추천 판본을 **다른 판본으로 바꾸면**, 받은 악보 항목에 "지금 추천 판본은 이것과 달라요 — 곡 보기" 취지의 한 줄이 보인다. "다시 받기"는 여전히 **그때 판본**을 준다. 추천이 같으면 그 줄이 없다.
- [ ] **8.** 관리자가 그때 판본을 **삭제**하거나 판정을 **"이용 제한"** 으로 바꾸면 "다시 받기" 대신 "그때 받은 악보는 지금 받을 수 없어요"가 보이고, 지금 추천 판본이 바로 받기 가능하면 **"지금 추천 판본 받기"** 버튼이(누르면 추천 판본 PDF), 아니면 **"곡 보기"** 링크가 보인다. 어느 경우에도 "이용 제한" 판본의 PDF 는 내려오지 않는다.
- [ ] **9.** 받은 악보에 항목 삭제·전체 삭제가 **없다** (1차).
- [ ] **10.** 관리자가 숨긴 곡은 받은 악보에서 빠지고 탭 숫자에도 안 센다. 삭제한 곡도 사라진다.
- [ ] **11.** 받은 악보가 0건이면 "**로그인한 상태에서** 받은 악보가 여기 남아요" 취지의 안내가 보인다.
- [ ] **12.** 파일이 서버에서 사라진 판본의 "다시 받기"를 누르면 그 항목 아래 "지금은 파일을 받을 수 없어요" 안내와 "곡 보기" 링크가 보이고, 다운로드 수·받은 날짜는 그대로다.

### 8-E. 최근 본 곡 (11)
- [ ] **1.** 비로그인으로 곡 상세를 3곡 차례로 열고 홈에 오면 "최근 본 곡" 영역이 **검색창 아래·인기곡 위**에 보이고, 마지막에 본 곡이 맨 위다.
- [ ] **2.** 곡 상세를 한 번도 열지 않은 브라우저(시크릿 창)의 홈에는 "최근 본 곡" 영역이 **아예 없다** (빈 제목도 없다). 그 홈은 `01` §6 홈 인수 조건(검색창 1개·인기곡 10개·작곡가 8명)을 그대로 통과한다.
- [ ] **3.** 이미 본 곡을 다시 열면 맨 위로 올라올 뿐 **두 번 나오지 않는다.**
- [ ] **4.** 11곡째를 열면 가장 오래된 곡이 빠져 **10곡**만 남는다.
- [ ] **5.** 브라우저를 닫았다 다시 열어도 남아 있다. **로그아웃해도 남아 있다.** 로그인해도 다른 기기에 나타나지 않는다.
- [ ] **6.** "최근 본 곡 지우기"를 누르면 확인 창 없이 **즉시** 영역이 사라진다. 그 뒤 곡 상세를 하나 열면 영역이 그 1곡으로 다시 생긴다.
- [ ] **7.** 항목은 인기곡과 같은 모양(제목·작곡가·난이도·상태 뱃지, 순위 숫자 없음)이고 누르면 곡 상세로 간다. 준비 중이던 곡이 열리면 뱃지가 사라져 보인다 (지금의 정보를 보인다).
- [ ] **8.** 최근 본 곡에 든 곡을 관리자가 숨기면 홈의 최근 본 곡에서 **사라진다** (눌러서 404 를 만나지 않는다). 숨김을 풀면 다시 나온다.
- [ ] **9.** 없는 곡 주소(404)를 열어도 최근 본 곡에 들어가지 않는다.
- [ ] **10.** 같은 주소(`/piano`)를 시크릿 창에서 열면 **최근 본 곡 영역만 없고 나머지는 같다** (`04` §1-4 정합 — 주소가 가리키는 것은 누구에게나 같다).
- [ ] **11.** 네트워크를 끊고 홈을 열면 최근 본 곡 영역은 **조용히 숨고** 오류 상자를 띄우지 않는다. 인기곡·작곡가 영역의 오류 표시는 기존대로다.

### 8-F. 구분 · 주소 (6)
- [ ] **1.** 내 악보 주소가 구분 아래에 있고(`/piano/…`), 주소만 보고 피아노 구분의 내 악보임을 알 수 있다.
- [ ] **2.** 내 악보 화면에 구분 바가 보이고 피아노가 선택돼 있으며, 헤더 "내 악보"가 활성 표시된다.
- [ ] **3.** 즐겨찾기 탭·받은 악보 탭 각각의 주소를 복사해 새 탭에 붙여넣으면 같은 탭이 열리고, 탭을 바꾼 뒤 뒤로 가기를 누르면 이전 탭으로 돌아간다.
- [ ] **4.** 화면 어디에도 여러 구분의 즐겨찾기·받은 악보·최근 본 곡을 한꺼번에 보는 목록이 없다.
- [ ] **5.** 준비 중 구분 화면(`/violin`)에서 헤더 "내 악보"를 누르면 피아노 내 악보가 열린다. `/violin/…` 아래 내 악보 주소는 찾을 수 없는 페이지다.
- [ ] **6.** 관리 화면(`/admin/**`) 어디에도 즐겨찾기·내 악보·최근 본 곡 요소가 없다.

### 8-G. 기존 동작 회귀 · 범위 밖 확인 (7)
- [ ] **1.** 비로그인으로 검색·곡 상세·작곡가·다운로드가 전과 같이 **로그인 없이** 된다. 로그인이 필요한 것은 즐겨찾기·내 악보뿐이다. *(`01` §6 "범위 밖 확인"의 옛 문장을 대체한다 — §8 충돌 2)*
- [ ] **2.** 홈·검색 결과·곡 상세·작곡가 화면에 로그인을 권하는 배너·팝업·고정 문구가 **없다.** 권유는 즐겨찾기를 눌렀을 때와 내 악보 진입 시 **로그인 화면 안의 한 줄**뿐이다.
- [ ] **3.** `01` §6 "곡 상세"·"곡 상세 — 예외" 인수 조건 전부가 그대로 통과한다 (즐겨찾기 버튼이 추가됐을 뿐 나머지 구성·동작은 같다).
- [ ] **4.** `01` §6 "홈 / 공통" 인수 조건 전부가 **시크릿 창 기준**으로 그대로 통과한다.
- [ ] **5.** 곡 카드(검색 결과·작곡가 상세·홈 인기곡·같은 작곡가의 다른 곡)에 즐겨찾기 버튼·표시가 **없다** (1차 범위 밖).
- [ ] **6.** 곡 상세에 "N명이 즐겨찾기" 같은 숫자가 없다.
- [ ] **7.** `/mypage`·`/signup` 은 주소로 열리되 헤더 어디에서도 링크되지 않는다.
