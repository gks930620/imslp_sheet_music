# 한국 기준 저작권 판정 지침 (1차)

> 작성일: 2026-09-05 (메인 세션). 관리자가 판본마다 "한국 기준 판정"을 입력할 때 쓰는 규칙이다. 법률 자문이 아니며, 불명확하면 보수적으로(다운로드 막음) 간다.

## 판정 값 (판본 단위)
| 값 | 의미 | 사용자 화면 |
|---|---|---|
| `FREE` | 한국에서 자유 이용 가능 | 초록 뱃지 "한국에서 자유 이용 가능" + 다운로드 버튼 |
| `RESTRICTED` | 한국에서 보호 중(비PD) | 회색 뱃지 "한국에서 이용 제한" + IMSLP 원본 링크만 |
| `UNKNOWN` | 확인 중 | 노란 뱃지 "저작권 확인 중" + IMSLP 원본 링크만 |

## 규칙
1. **작곡가**: 사망 연도 + 70년 < 올해 이면 통과. (한국 저작권법: 저작자 사후 70년. 1962년 이전 사망자는 사후 50년 규정으로 이미 만료 — 결과는 같으므로 70년으로 통일 계산.)
2. **편집자·편곡자**: 판본에 편집자(Editor)나 편곡자(Arranger)가 표기돼 있으면 그 사람도 규칙 1을 통과해야 한다. 편집자 사망 연도를 모르면 `UNKNOWN`.
3. **편집자 없음·익명·출판사 명의**: 초판 출판 연도 + 70년 < 올해 이면 통과.
4. **IMSLP 표기가 CC 라이선스**(Creative Commons): 라이선스 조건대로 재배포 가능하면 `FREE` 로 두되, 판본 정보에 라이선스명과 저작자 표기를 반드시 보여준다. NC(비영리)·ND(변경금지) 조건도 그대로 표기. 우리 서비스는 무료라 NC 는 충돌하지 않는다.
5. **IMSLP 표기가 "Non-PD US/EU" 등 국가 제한**: 한국 규칙(1~3)으로 다시 계산한다. IMSLP 의 국가 표기를 그대로 믿지 않는다.
6. **손글씨 자필보(Manuscript)·필사본**: 작곡가 규칙 1만 적용.
7. 규칙 어디에도 안 들어가면 `UNKNOWN`.

## 표기 의무
- 모든 판본 상세에 "출처: IMSLP" + 원본 작품 페이지 링크 + 스캔 제공자·출판사·편집자 정보를 표시한다.
- CC 판본은 라이선스명을 함께 표시한다.

## 예시
- 베토벤(1827 사망) 월광 소나타, 편집자 Sigmund Lebert(1884 사망) 판본 → 둘 다 통과 → `FREE`
- 쇼팽(1849 사망) 녹턴, 편집자 Ignacy Paderewski(1941 사망) 판본 → 1941+70=2011 < 2026 → `FREE`
- 드뷔시(1918 사망), 편집자 불명·1970년대 출판 판본 → 출판+70=204x → `RESTRICTED` (편집 저작물 보호 가능성). 작곡가 원판(초판 1900년대) 스캔이면 `FREE`
- 라흐마니노프(1943 사망) → 2013 만료 → 원판 스캔은 `FREE`. 단 편집자 확인 필요.

## 부록 A. 자동 판정 규칙 (2026-09-07, senior-dev)

> 왜 필요한가: 1차 수집으로 판본 1,792건이 들어왔고 전부 `UNKNOWN` 이다. 사람이 한 건씩 보는 건 비현실적이고,
> `UNKNOWN` 인 동안에는 추천 판본을 지정해도 곡이 `READY` 가 되지 않아 **다운로드 가능한 곡이 0개**다.
> 위 규칙 1~7 중 **우리가 가진 데이터만으로 기계가 확인할 수 있는 부분**을 뽑아 자동 판정으로 만든다.
>
> **자동 판정은 규칙 1~7 을 대체하지 않는다.** 규칙 1~7 은 사람 판정의 기준이고, 부록 A 는 그 부분집합을
> 보수적으로 자동화한 것이다. 자동 판정이 열지 못한 것은 여전히 `UNKNOWN` 으로 남아 사람이 본다.

### A-0. 우리가 가진 데이터와 그 한계
| 가진 것 | 없는 것 |
|---|---|
| `composer.death_year`(시드 25명 전원 있음) | **편집자·편곡자의 사망 연도** |
| `edition.publish_year`, `editor`, `arranger`, `kind` | 초판 여부(우리 `publish_year` 는 그 스캔본의 출판 연도) |
| `edition.imslp_license_code`, `imslp_copyright_text` | 국가별 판정(IMSLP 표기는 대개 미국·캐나다 기준) |

**편집자 사망 연도가 없다는 것이 자동화의 유일하고 결정적인 한계다.** 규칙 2 는 "모르면 UNKNOWN" 이므로,
그대로 자동화하면 편집자 표기가 있는 판본(대다수)이 전부 UNKNOWN 으로 남는다. A-2 가 이 지점을 다룬다.

### A-1. 판정 절차 (위에서부터, 먼저 걸리는 곳에서 끝난다)

대상: `korea_copyright = UNKNOWN` 인 판본만. **자동 판정은 `UNKNOWN → FREE` 한 방향으로만 움직인다.**

| # | 조건 | 결과 |
|---|---|---|
| 1 | `imslp_license_code` 가 `PD / CC0 / CC_BY / CC_BY_SA` 가 **아니다**(null 포함) | `UNKNOWN` 유지 — `LICENSE_NOT_REDISTRIBUTABLE` |
| 2 | `composer.death_year` 가 없다 | `UNKNOWN` 유지 — `COMPOSER_DEATH_YEAR_UNKNOWN` |
| 3 | `death_year + 70 >= 올해` (규칙 1 미통과) | `UNKNOWN` 유지 — `COMPOSER_COPYRIGHT_ACTIVE` |
| 4 | 라이선스가 `CC0 / CC_BY / CC_BY_SA` | **`FREE`** — 규칙 `CC_REDISTRIBUTABLE` |
| 5 | (PD) `editor`·`arranger` 표기가 모두 없고 `kind != ARRANGEMENT` 이며, `publish_year` 가 없거나 `publish_year + 70 < 올해` | **`FREE`** — 규칙 `PD_NO_EDITOR` |
| 6 | (PD) 5 와 같은데 `publish_year + 70 >= 올해` | `UNKNOWN` 유지 — `PUBLICATION_TOO_RECENT` |
| 7 | (PD) `editor`·`arranger` 표기가 있거나 `kind = ARRANGEMENT` 이고 `publish_year + 120 < 올해` | **`FREE`** — 규칙 `PD_OLD_PUBLICATION` |
| 8 | 그 외 (편집자 표기 있음 + 출판 120년 미경과 또는 출판 연도 없음) | `UNKNOWN` 유지 — `EDITOR_UNVERIFIABLE` |

### A-2. 근거

**① 라이선스 관문을 맨 앞에 두는 이유 (1·4).**
"IMSLP 에 있으면 저작권이 없다"는 사실이 아니다. IMSLP 에는 PD 뿐 아니라 CC-BY-NC / CC-BY-ND 같은 **조건부** 판본도 있고,
국가별로 판정이 다르다. 다만 우리 크롤러는 기획 §9-1 에 따라 **재배포가 허용되는 표기(PD·CC0·CC BY·CC BY-SA)** 인 판본의
파일만 내려받는다. 그래서 "파일이 있는 판본"은 이미 한 번 걸러진 것이다. 자동 판정도 같은 관문을 첫 조건으로 쓴다.
CC0·CC BY·CC BY-SA 는 **저작권자가 재배포를 명시적으로 허락한 것**이므로 편집자 사망 연도를 따질 필요가 없다(규칙 4).
단 표기 의무는 그대로다 — `cc_license_name`·`cc_attribution` 을 판본 상세에 반드시 보여준다.

**② 작곡가 조건을 모든 분기의 전제로 두는 이유 (2·3).**
CC 라이선스는 **조판·편집한 사람의 권리**만 푼다. 작품 자체가 보호 중이면 라이선스와 무관하게 우리가 배포할 수 없다.
그래서 규칙 1(사후 70년)은 CC 분기에도 그대로 적용한다. `death_year` 가 비어 있으면(수집이 만든 작곡가는 비어 있을 수 있다)
판정하지 않는다 — 관리자가 작곡가 정보를 채우면 다음 실행에서 자동으로 걸린다.

**③ "편집자 표기 없음"을 출판 연도 없이도 통과시키는 이유 (5) — 규칙 3 의 완화.**
규칙 3 은 "편집자 없음·익명·출판사 명의 → 초판 출판 + 70년"이다. 그런데 IMSLP 스캔의 상당수는 출판 정보가
`n.d.`(연도 미상)라 `publish_year` 가 비어 있다. 이때 **한국 저작권법상 새로 보호될 대상이 무엇인지**를 보면:
편집자·편곡자가 없는 옛 악보의 영인·스캔은 **창작성 있는 선택·배열이 없어 편집저작물이 되지 않고**, 단순 복제물에는
새 저작권이 생기지 않는다. 즉 작곡가가 PD 면 보호될 것이 남지 않는다. 그래서 편집자 표기가 없는 판본은
출판 연도가 없어도 통과시킨다. **다만 출판 연도가 있고 그것이 최근이면(70년 미경과) 막는다(6)** — 최근 출판물은
"편집자 표기가 누락된 새 조판"일 가능성이 있고, 그건 우리가 확인할 수 없다.

**④ "출판 후 120년"을 편집자 사망의 대용으로 쓰는 이유와 그 숫자 (7).**
편집자 사망 연도가 없으므로, 출판 연도로부터 **보호 만료 시점의 상한**을 추정한다.
- 편집자가 그 판본을 낸 시점의 나이 하한을 **25세**로 본다(악보 편집은 전문 훈련이 필요해 그보다 어린 편집자는 사실상 없다).
- 19~20세기 초 유럽 음악가의 사망 나이를 넉넉히 잡아 **75세**로 본다.
- 그러면 사망 시점 ≤ 출판 + 50년, 보호 만료 = 사망 + 70년 ≤ **출판 + 120년**.
- 2026년 기준 **1906년 이전 출판**이면 편집자 표기가 있어도 만료로 본다. (기준 연도는 고정 상수가 아니라 `올해 − 120` 으로 매년 움직인다.)

검증(지침 §예시와 대조):
- 베토벤 월광, 편집자 Lebert(1884 사망), 1880년대 출판 → 120년 경과 → 자동 `FREE`. 사람 판정 결과와 같다. ✅
- 쇼팽 녹턴, 편집자 Paderewski(1941 사망), 1949년 출판 → 120년 미경과 → **자동 판정은 열지 않는다**.
  사람 판정으로는 `FREE`(1941+70=2011)지만, 자동 판정은 편집자 사망 연도를 모르므로 보수적으로 남긴다. 의도된 결과다. ✅
- 드뷔시, 편집자 불명·1970년대 출판 → 6 에 걸려 `UNKNOWN` 유지. ✅

**이 120년은 통계적 안전선이지 법적 보증이 아니다.** 90세까지 산 편집자가 25세에 낸 판본이라면 실제 만료는
출판 + 135년이다. 그래서 자동 판정은 (ⓐ) 전부 `자동 판정:` 으로 표시해 사람 판정과 구분하고, (ⓑ) **한 번의 요청으로 전부 되돌릴 수 있게** 한다(API §5-12).
권리자 이의가 오면 즉시 `RESTRICTED` 로 바꾸고 파일을 내린다.

**⑤ 자동 판정은 `RESTRICTED` 를 만들지 않는다.**
자동으로 `RESTRICTED` 를 찍으면 화면에는 "한국에서 이용 제한"이라는 **단정적인 문장**이 뜨는데, 그 단정의 근거가
우리에게 없다. 그리고 `RESTRICTED` 로 찍힌 것은 판정 대기함(§5-8)에서 사라져 사람이 다시 볼 기회를 잃는다.
`UNKNOWN` 은 이미 "다운로드 막힘 + 대기함에 남음"이라 안전 측면에서 `RESTRICTED` 와 동일하면서 정보를 잃지 않는다.

### A-3. 사람 판정과의 구분 · 되돌리기
- 자동 판정한 판본은 `copyright_judged_by = "system:auto"`, `copyright_note` 는 `자동 판정: …` 으로 시작한다.
- 사람이 나중에 같은 판본을 판정하면 `copyright_judged_by` 가 그 관리자 username 으로 바뀐다 → **되돌리기 대상에서 자동으로 빠진다.**
- 자동 판정은 **`UNKNOWN` 인 판본만** 건드린다. 이미 사람이 `FREE`/`RESTRICTED` 로 판정한 것은 절대 덮어쓰지 않는다(재실행해도 안전).

### A-4. "확인 필요"인 판본을 사용자에게 어떻게 보여주는가
- `UNKNOWN` 판본은 **다운로드를 계속 막는다.** 노란 뱃지 "저작권 확인 중" + IMSLP 원본 링크만(위 표 그대로, 변경 없음).
- 확인되지 않은 파일을 우리 서버에서 내려주는 것은 **우리가 재배포의 주체가 되는 것**이라, 문제가 생겼을 때 IMSLP 가 아니라
  우리가 책임진다. "일단 열고 나중에 정리"는 되돌릴 수 없는 종류의 위험이다(이미 받아간 파일은 회수할 수 없다).
- 대신 **관리자 쪽에서 잘 보이게** 한다: 관리 홈의 `unknownCopyrightEditions` 숫자 카드, 판정 대기함(§5-8) 목록,
  그리고 대기함 각 행의 `autoJudgeSkipReason`("왜 자동으로 열리지 않았는지")이 남은 일감을 그대로 보여준다.
