# 검토 수용 사항 (Accepted — 의도된 동작으로 남겨둔 것)

> 작성일: 2026-07-22
> 코드 리뷰에서 "잠재 이슈"로 지적됐지만, **의도된 설계라 지금은 고치지 않기로 결정**한 항목을 기록한다.
> 목적: 다음 리뷰(senior-dev/qa 포함)가 같은 지점을 **다시 결함으로 리포트하지 않도록** 근거와 재검토 조건을 남긴다.

---

## 1. 첨부파일 무인증 다운로드 — 수용 (공개 커뮤니티)

- **동작**: `GET /uploads/{저장파일명}`, `GET /api/files/{id}/content` 가 로그인 없이 열린다. 파일 id가 순번(Long)이라 값을 바꿔가며 열람할 수 있다.
- **결정(사용자, 2026-07-22)**: 이 서비스는 **공개 커뮤니티 게시판**이다. 본문 이미지도 첨부파일도 **누구나 봐도 되는 공개 자원**이므로 다운로드에 인증을 요구하지 않는다. → **의도된 동작.**
- **재검토 조건**: 아래 중 하나라도 생기면 그때 "로그인 + 소유자/열람권한 확인"을 추가한다.
  - 비공개 글/첨부(작성자만 보는 자료, 유료·회원 전용 등) 개념이 도입될 때
  - 개인정보·민감정보가 담긴 파일을 올리는 기능이 생길 때
- 참고: 업로드·삭제(`POST/DELETE /api/files`)는 지금도 인증 + 소유자 검증(IDOR 방어)이 걸려 있다. 열람만 공개다.

## 2. WebSocket(STOMP 채팅) 토큰 만료 시 재연결 없음 — 수용 (기본 샘플)

- **동작**: access 토큰(30분) 만료 후 채팅 CONNECT가 거부되면 자동 토큰 리프레시·재연결이 없다(HTTP는 401 시 `/api/tokens/refresh`로 자동 갱신되지만 WS 경로는 그 로직을 안 탐). 끊기면 새로고침해야 복구.
- **결정(사용자, 2026-07-22)**: 채팅은 **보일러플레이트의 기본 샘플 코드** 수준이다. 현 상태로 **문제없이 수용**한다. → 지금 고치지 않음.
- **재검토 조건**: 채팅을 **실제 제품 기능으로 키울 때** 다음을 추가한다.
  - 토큰 만료 감지 → 리프레시 후 STOMP 재연결
  - `reconnectDelay` 설정으로 비정상 종료 시 자동 재연결
- 참고: WebSocket 자체의 CSWSH(허용 출처 제한)·CONNECT 시 토큰 검증은 이미 되어 있다. 없는 것은 "만료 후 자동 복구"뿐이다.
