# 배포 환경변수 & 환경 무관 실행 원칙

> 작성일: 2026-07-22
> **핵심 원칙의 출처는 `code-convention` 스킬 §5(환경 무관 실행 원칙)이다.** 이 문서는 그 원칙을
> "이 저장소에서 실제로 어떻게 지켜지는지"와 **"Railway에 직접 등록할 환경변수 목록"** 으로 구체화한 것이다.
> 원칙과 이 문서가 어긋나면 컨벤션 문서(§5)가 기준이다.

---

## 0. 한 줄 원칙

> **같은 코드가 코드 변경 없이 로컬에서도, 운영(Railway)에서도 동작한다.**
> "배포한다고 코드를 고치지 않는다." 환경 차이는 **Spring 프로파일 + 환경변수로만** 흡수한다.
> 운영용 비밀값(DB·OAuth·JWT)은 소스/커밋에 두지 않고 **Railway 대시보드의 서비스 Variables에 직접 등록**한다.

이 원칙은 다음을 금지한다:
- 코드 안의 `if (로컬) ... else (운영) ...` 환경 분기
- 운영 도메인·시크릿을 소스에 하드코딩
- "배포용 브랜치"에서만 코드/설정을 바꿔치기

---

## 1. 이 저장소가 원칙을 구현하는 방식 (읽고 이해만, 바꾸지 말 것)

| 축 | 로컬(dev, 기본 프로파일) | 운영(prod 프로파일) | 어떻게 갈리나 |
|---|---|---|---|
| DB | H2 인메모리, `ddl-auto: create`, 매 기동 초기화 + 시드 재적재 | Railway MySQL, `ddl-auto: update`, 데이터 영속 | 프로파일 (`application.yml` vs `application-prod.yml`) |
| 프로파일 활성화 | 없음(기본) | `prod` | **`Dockerfile` ENTRYPOINT에 `-Dspring.profiles.active=prod` 고정** — 운영은 자동 |
| 포트 | 8080 고정 | `${PORT:8080}` (Railway가 주입) | 환경변수 |
| 설정값 | `${ENV:로컬기본값}`의 기본값 사용 | Railway Variables 주입값 사용 | 환경변수 |
| 프론트 API 호출 | `vite.config.js` 프록시가 `localhost:8080`으로 전달 | 빌드 산출물이 **상대경로**로 같은 오리진 호출 | Vite 빌드 (dev 서버 vs 정적 번들) |
| 쿠키 secure | `false` (HTTP) | `true` (HTTPS) | 프로파일 |

**결과: 로컬에서 `잘 되는 것`을 그대로 커밋 → Railway가 프로파일·환경변수만 바꿔 그대로 운영한다.**

---

## 2. Railway에 직접 등록할 환경변수 체크리스트 ⭐

> Railway → 해당 서비스 → **Variables** 탭에 등록한다. `.env` 파일을 배포하지 않는다(이미지/VCS에서 제외됨).
> `SPRING_PROFILES_ACTIVE`는 Dockerfile이 이미 `prod`로 고정하므로 **따로 넣지 않아도 된다.**

### 2-1. 필수 (미설정 시 기동 실패 또는 로그인 전면 불가)

| 변수명 | 용도 | 예시 / 조립법 | 미설정 시 증상 |
|---|---|---|---|
| `SPRING_DATASOURCE_URL` | 운영 MySQL 접속 URL | `jdbc:mysql://${{MySQL.MYSQLHOST}}:${{MySQL.MYSQLPORT}}/${{MySQL.MYSQLDATABASE}}` | **기동 실패** (기본값 없음 = fail-fast) |
| `SPRING_DATASOURCE_USERNAME` | MySQL 사용자 | `${{MySQL.MYSQLUSER}}` | 기동 실패 |
| `SPRING_DATASOURCE_PASSWORD` | MySQL 비밀번호 | `${{MySQL.MYSQLPASSWORD}}` | 기동 실패 |
| `JWT_SECRET_KEY` | JWT 서명키 | 64 hex 이상 랜덤 문자열 | 기동 실패(빈 키로 서명 불가) |
| `KAKAO_CLIENT_ID` | 카카오 OAuth REST 키 | 카카오 콘솔 값 | 카카오 로그인 실패 |
| `KAKAO_CLIENT_SECRET` | 카카오 OAuth Secret | 카카오 콘솔 값 | **prod는 기본값 없음** → 미설정 시 기동/로그인 실패 (로컬 yml은 빈 값 허용이라 로컬과 다름 — 주의) |
| `GOOGLE_CLIENT_ID` | 구글 OAuth 클라이언트 ID | 구글 콘솔 값 | 구글 로그인 실패 |
| `GOOGLE_CLIENT_SECRET` | 구글 OAuth Secret | 구글 콘솔 값 | 구글 로그인 실패 |
| `BUCKET_ENDPOINT` | 파일저장 버킷(S3 호환) 엔드포인트 | `${{<프로젝트>_bucket.BUCKET_ENDPOINT}}` | **prod 기동 실패** (`RailwayDeploymentValidator` fail-fast) |
| `BUCKET_ACCESS_KEY_ID` | 버킷 액세스 키 | `${{<프로젝트>_bucket.BUCKET_ACCESS_KEY_ID}}` | prod 기동 실패 |
| `BUCKET_SECRET_ACCESS_KEY` | 버킷 시크릿 키 | `${{<프로젝트>_bucket.BUCKET_SECRET_ACCESS_KEY}}` | prod 기동 실패 |
| `BUCKET_NAME` | 버킷 이름 | `${{<프로젝트>_bucket.BUCKET_NAME}}` | prod 기동 실패 |

> 파일저장은 **Railway Storage Buckets(S3 호환)** 이다(§5-3). 버킷은 프로젝트별 1개(`<프로젝트명>_bucket`).
> 로컬(dev)은 `BUCKET_ENDPOINT`를 비워두면 자동으로 로컬 디스크(`LocalFileStorage`)로 폴백하므로 위 4개가 필요 없다 — **같은 코드가 환경만으로 갈린다.**

### 2-2. 사실상 필수 (기본값이 placeholder라 반드시 실제 값으로 덮어야 함)

| 변수명 | 용도 | 반드시 설정할 값 | 미설정 시 증상 |
|---|---|---|---|
| `APP_BASE_URL` | OAuth redirect-uri + WebSocket 허용 출처의 기준 | `https://<your-app>.up.railway.app` (본인 도메인) | 미설정 시 OAuth redirect가 `localhost`로 나가 **카카오/구글 redirect mismatch로 로그인 전면 실패**, WS는 `your-domain.com` placeholder라 **핸드셰이크 거부** |

> ⚠️ `APP_BASE_URL`은 `application-prod.yml`에 기본값이 있어 **없어도 기동은 되지만 런타임에 조용히 깨진다.**
> OAuth 콘솔(카카오/구글)의 **redirect URI 등록값**도 `https://<도메인>/login/oauth2/code/kakao`(및 `/google`)로 맞춰야 한다.

### 2-3. 자동 주입 / 불필요

| 변수명 | 상태 |
|---|---|
| `PORT` | Railway가 자동 주입 → 앱이 `${PORT:8080}`로 수신. **직접 설정 불필요.** |
| `BUCKET_REGION` | 기본값 `us-east-1`. Railway/R2/MinIO 등 대부분 그대로 → 보통 설정 불필요. |
| ~~`SUPABASE_URL/ANON_KEY`~~ | **제거됨** — Supabase 코드 폐기, Railway Buckets(S3)로 대체. |

## 3. "배포 때 코드가 바뀌면 안 되는" 지점 (하드코딩 금지 목록)

배포하면서 아래를 소스에서 고치고 있다면 원칙 위반이다 — 전부 환경변수/프로파일로 처리한다:
- DB 접속정보 → `SPRING_DATASOURCE_*`
- 앱 공개 URL / OAuth redirect / WS 출처 → `APP_BASE_URL`
- 시크릿(JWT·OAuth) → 각 환경변수
- 포트 → `${PORT}`
- 쿠키 secure, 로깅 레벨, SQL 초기화 on/off → 프로파일(`application-prod.yml`)이 이미 담당

---

## 4. 파일 영속성 — Railway Object Storage로 해결됨 ✅ (Volume 안 씀)

- 업로드 파일은 **Railway Storage Buckets(S3 호환)** 에 저장된다(`BucketStorage`, §5-3). Volume은 쓰지 않는다.
  → 컨테이너 파일시스템이 ephemeral이어도 **재배포에도 파일이 보존**된다. (예전 "로컬 디스크 저장 → 소실" 문제 해결)
- 서빙: 버킷은 private → 백엔드 프록시 `GET /uploads/{저장파일명}`이 바이트를 스트리밍(같은 오리진, presigned 만료 없음). 프론트 계약 불변.
- **fail-fast 구현됨**: `RailwayDeploymentValidator`(`@Profile("prod")`)가 prod에서 `BUCKET_*` 누락 시 기동을 막는다.
- orphan 정리: `@Scheduled` 배치가 미연결(refId=0) 파일을 유예시간(기본 24h) 경과 후 정리(`app.file.orphan-grace-hours`).

### 남는 주의 (fail-fast가 못 잡는 것)
- **`APP_BASE_URL`은 기본값이 있어 누락돼도 기동은 되고 런타임에 조용히 깨진다**(OAuth redirect·WS origin). Validator가 안 잡으므로 이 체크리스트로 사람이 등록을 보증한다.
- 버킷 실연동은 외부 S3라 통합테스트(H2) 범위 밖 → **스테이징에서 업로드→재배포→여전히 보이는지** 1회 확인 권장.

---

## 5. 배포 후 확인

- 헬스체크: `GET /actuator/health` → 200 `{status:"UP"}` (Dockerfile HEALTHCHECK도 이 경로 사용)
- 로그인: 카카오/구글 각 1회 (redirect mismatch 없는지 = `APP_BASE_URL`·콘솔 등록 확인)
- 채팅: 방 입장 후 메시지 송수신 (WS 출처 허용 = `APP_BASE_URL` 확인)
- 파일: 이미지 업로드 → 재배포 → **여전히 보이는지**(4번 갭 확인. Volume 미마운트면 깨짐)
